## F10 — R.A.B.B.I.T.'s twins

**What changed underneath.** R.A.B.B.I.T.'s Scenes, Shots, Levels, Experiences, Assets and Tasks pages each carried
their own copy of a few small pieces: the words you click to edit in a table or a window, the menus in the bar that
appears when you tick rows, and the "Delete?" question. Each page also had its own copy of the code behind its saved
views, filters and sorts, and the program kept four near-identical sets of instructions for saving a scene, a shot, a
level and an experience. The copies had drifted apart, so a fix made in one place was missing in the others. Now
there is one of each, shared. The editing words, the menus and the question live in WILSON's shared set of screen
parts, the one every tool draws its buttons and windows from. One piece sits behind every table's saved views; one
set of save instructions serves the four kinds; one piece runs the windows of scenes, shots, levels and experiences,
and one sets or removes their pictures. Nothing new is on the screen; the pages look as they did.

**Before and after.** Twenty-two small copies (492 lines) became one of each in the shared set; the saved-views code
written four times became one piece; the four sets of save instructions (459 lines) became one; the six page files
went from 21,634 lines to 20,275. The app's download is BUNDLE_SMALLER bytes smaller (BUNDLE_BEFORE before, BUNDLE_AFTER
after).

**What you may notice (all small):**
1. After you edit a name or a title in a table or a window and press Enter or Escape, the keyboard stays on that
   name (with its focus outline), so the next Tab goes on from there. Before, the keyboard was left on nothing, and
   the next Tab started again from the top of the page or of the window. If you click into another box or press Tab
   instead, you land where you went, as before. A click on empty space also leaves the keyboard on the name, without
   scrolling, and that row's tick box and buttons stay shown until you move on.
2. In the menus of the Tasks and Assets tick bars, picking **None** for Phase (and, on Tasks, for Assignee) now clears
   it on the ticked rows. Before, picking None did nothing. In the same menus (and on Levels), a phase or a person
   whose name has an underscore now shows it as typed; before, it showed as a space.
3. In a Level's or an Experience's window, after Save, Cancel or Escape in Description or Notes, the keyboard stays on
   the words; and if a teammate changes the description while you have it open but haven't typed, you now see their
   words (once you have typed, yours stay).

**How it was measured.** Before and after, by counting the copies and their lines (above) and by the test suite
(SUITE_N tests): each change above has a test that failed on the old code and passes now, and the pages' own tests,
the permission checks and the speed checks (how often the screen redraws) pass without being changed. The keyboard
behaviour in item 1 was also tried in a real browser, on a test page built from the shared editor itself. The two
reviews found that the first version pulled the keyboard back when you clicked into another box, reopened the name
when you pressed Enter, and could scroll a sorted list away from where you clicked. All of it was fixed before the
work was handed in, and tried again in the browser.

**To try, if you like (nothing needs checking):** rename a scene in the Scenes table and press Enter, then Tab; in
Tasks, click a title, type, then click into the search box and type (the letters land in the search box); tick two
tasks and pick Phase → None.

**Questions for you** (asked in F10's chat; the recommended answer first; until you answer, nothing changes):

2. Should the Levels and Experiences windows take the Scene window's layout? a) Keep their own (recommended): nothing

3. Should Levels and Experiences get the # tags and [[ links (mentions) that Scenes and Shots have? a) Not now
   (recommended): nothing changes. b) Yes: their Description and Notes would take and show them.

## F11 — The bundle and the sign-in

**What changed, in plain words.**

1. **The app opens with less to read.** The file every launch reads first went from 5,093,158 bytes to
   4,289,154, about a sixth smaller. Two things left it:
   - The code highlighter carried 297 programming languages. It now carries the ones the app shows: those
     the Files preview and O.T.T.E.R.'s courses name, the common ones the pet and the lessons write, and the
     doc comments inside them. Code in those languages looks exactly as before, script and style inside HTML
     included (checked letter by letter, colour by colour). A language outside the list (Haskell, say) now
     shows as plain text in the same box, as an unknown one always has.
   - Three things most days never open now load the first time they are opened: the migration panels in
     *App settings → Storage*, the Admin terminal's sections (never for someone who is not an admin; for
     an admin they still load as the app starts), and the
     Dashboard's *Notes*. The first time, one line shows for a moment ("Opening Notes…"). If one cannot load
     (offline on the web, or a tab left open across an update), it says "Notes could not open." in its own
     place, with *Try again* and *Reload the page*.
2. **Every call to the cloud's functions goes through one place.** Sixteen hand-written copies became one.
   Nothing changes while things work. When they fail: a request refused as too large says so in a sentence
   (it showed "Request failed (413)."); a reply the server would never send (a hotel wifi page, say) is no
   longer taken for a success; and a call that hangs stops after a set time and says so, instead of spinning.
3. **Forgot password asks for the company,** as you chose: the company you just signed in with is shown
   above the username, with *Change company*; on a computer that has never signed in, it asks for the
   company first. Before, a username used in two companies got no reset email while the screen said one was
   on its way. *Pictures F11 1 and F11 2* (in `101_wave_4 pictures`).

**How it was measured.** The same build before and after, its bytes on disk; every cloud helper's request
recorded before and after (all identical); the whole test suite (549 files: 14,596 passed, 9 skipped, none
failed); and seven reviewers in two rounds, whose findings in F11's own work were fixed before it merged.

**To look at, if you like (nothing here needs an answer).**

1. Sign out, type your company, *Continue*, then *Forgot password?*: your company is shown above the
   username, with *Change company* beside *Back to login* (picture F11 2).
2. *Dashboard → Notes*: "Opening Notes…" for a moment the first time, then your notes as before.
3. If one of your test usernames exists in two companies on wilson-dev: *Forgot password* with each company
   should send the email to that company's address. This is the one thing not run against the database,
   because the database was not this session's to touch.
