## 2. Branch mechanics (this replaces the protocol's single-branch flow)

Audrey's checkout holds `feat/demo-2026-09-11`. Two worktrees on one branch
share the ref, and the older one's next commit silently REVERTS the newer
one's files (measured on Track A, `75c82b3`). So:

1. **Each session works on its own branch**, cut from the integration branch
   in the fresh worktree (the app cuts worktrees from `main`; `docs/sessions/`
   is missing until this):
   ```
   git fetch origin
   git checkout -b demo/s-bins origin/feat/demo-2026-09-11      # S
   git checkout -b demo/v-assemblies origin/feat/demo-2026-09-11 # V
   git checkout -b demo/u-ui origin/feat/demo-2026-09-11         # U
   npm install --ignore-scripts && git checkout -- package-lock.json
   ```
   Copy `.env.local` from the canonical checkout into the worktree's `WILSON/`
   (vitest and the app read it; never commit it). **No `supabase link` is
   needed** for local-mode work; link to wilson-dev (`eqjzmnvkrakroyqxfsvw`)
   only if you build the optional cloud schema.
2. **Push your own branch early and often** (`git push -u origin demo/s-bins`).
   CI runs on `demo/**` pushes (root `rls.yml`).
3. **Integrate by fast-forwarding the integration branch from your branch,
   never by checking it out:**
   ```
   git fetch origin
   git merge --no-ff origin/feat/demo-2026-09-11   # take everyone else's work
   npx vitest run                                  # must be green
   git push origin HEAD:feat/demo-2026-09-11       # fast-forward on the remote
   ```
   If the last push is rejected, someone integrated in between: merge
   `origin/feat/demo-2026-09-11` again and retry. Integrate at every real
   milestone (a view renders, a route works end to end), at least twice a day,
   and always before a hand-off.
4. **Audrey tests from her checkout** with `git pull --ff-only` then
   `npm run dev`. She does not commit there while sessions run; if she does,
   step 3's merge picks it up.
5. Never push to `feat/multi-user-v1`, never to a `track-*` branch, never
   deploy anything, never touch staging or prod. A demo branch push deploys
   nothing.

## 4. Working rules (short, from this repo's hard-won lessons)

- **One item per session; hand off early** (protocol §1): after one
  compaction, after ~300 KB of reads, before a review round. Hand-off file:
  `docs/sessions/handoffs/demo-<S|V|U>-<YYYY-MM-DD>.md`, protocol §4 order,
  committed on your branch AND integrated (§2 step 3) before the chip. Chip
  title `Continue demo <letter>: <item>`; the prompt repeats the first
  commands in §2.
- **Model:** every new session states its model in its first line and stops if
  it is not the one its chip prompt names. From 2026-09-09 Audrey's default
  for new sessions is **Fable 5.1 at max effort** (`claude-fable-5-1`), which
  is also the user-level default in `~/.claude/settings.json`.
- **`fetch`/`otterFetch` resolve for every status** — check `res.ok`, read the
  body defensively. An RLS 403 or a 401 renders as an empty list.
- **Enumerate your exports and grep for callers before committing** — ten
  features have shipped here with no caller.
- **At least one adversarial review round per item, two if time**; the
  reviewer attacks the corrections, not just the code. Review subagents pass
  `model: "opus"`.
- **Never `open(path, "w")` on a file you cannot regenerate; never put a
  backslash into generated code** (build Windows paths with `chr(92)`);
  heredocs over ~100 lines fail — use the Write tool.
- **`%APPDATA%` is virtualized for Claude**: you cannot inspect Audrey's
  running app's `userData`. Ask her to look, or point your own dev instance at
  a scratch folder.
- `npm install` rewrites `package-lock.json` — discard it unless you changed
  `package.json`. Vitest baseline on this base: **1706 / 71 files**
  (2026-09-04); state your own count in every hand-off.
- Shared docs (`OUTSTANDING.md`, `SYSTEMS_HANDBOOK.md`, `CHANGELOG.md`): edit
  only your own lines, append rather than restructure. Add your item to
  `SYSTEMS_HANDBOOK.md` when it is real, not before.
- A `<!--` in a long markdown file has silently deleted 227 lines here. Count
  the markers after editing any long doc.
