## 5. Traps hit

1. **The smoke account's password is not in the repo** (deliberately, TPN-SDLC
   -007) and `.env.local` has no dev auto sign-in credentials. The real
   password step was run against an in-browser stub of every Supabase
   request instead; the instrument says so and aborts every other
   non-localhost request. Never reach for the password in git history.
2. **The fixtures reviewer is an ADMIN.** With `VITE_DEV_FIXTURES=1` an admin
   with no verified TOTP factor gets the MFA enrolment gate ~180ms after the
   hand-over; the gate starts `idle`, two 50vh panels, and paints the whole
   window orange over the welcome. The first strips looked like the welcome
   never appeared. `?fixtures=member` (the fixtures' own S4b variant) is the
   path Audrey's own sign-in takes to the welcome; the instrument uses it.
3. **`elementFromPoint` skips `pointer-events: none`** — every AuthShell layer
   but its background — so it reads the app UNDER the shell until the
   hand-over. The strips are the pixel truth.
4. **App's mount is a ~100ms long task with no frames.** A pause measured in
   FRAMES read a 320ms still as three frames; the check measures in ms.
5. **The reveal's ease tail is still 40.1px when App mounts at exactly 40.**
   A 0.1px snap after landing is not a second tween; the check judges pauses
   only until the band lands within 0.75px. The loosening is proven by
   `--recheck` on all six pre-fix captures, which still fail.
6. **jsdom keeps `min()`/`calc()` heights** but normalises them
   (`calc((100vh - 544px) / 2)` → `0.5 * (100vh - 544px)`), so a test that
   compares the TEXT of a height against a constant fails for the wrong
   reason; resolve both at window heights instead.
7. **App.jsx, AuthShell.jsx, pages.js are CRLF in the working tree.** A
   node string-replace with `\n` anchors silently misses; normalise first.
   And a backslash inside a node heredoc that writes a template literal is
   eaten (`\s` came out `s`) — the brief's rule, Write/Edit for backslashes,
   is right.
8. **The welcome must start in the hand-over's own handler.** From an
   effect, the bars paint once at Home's height first (the old queue).
9. **App's chrome is not always mounted at the hand-over.** A resumed
   session on a `#/recovery` link keeps the overlay up over a mounted app
   (Session 17's rule in App's session check), and the reset wizard signs out
   without unmounting it. A fix proved only on a fresh device passed and
   regressed that path; a mount-time argument ("nothing to tween from") is
   not enough — the bars' transition has to be off. `--resumed` covers it.
10. **The fields by autocomplete, not by label**, when App is mounted under
    the sign-in screen: Settings' inputs share the labels.
