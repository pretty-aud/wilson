## 5. Traps hit

- 🚨 **`%APPDATA%` is NOT virtualised for a dev Electron instance.** The
  brief says point a dev instance at a scratch folder; setting `APPDATA` in
  the environment does nothing (Electron reads the shell folder API), so
  `npx electron .` from the worktree wrote to Audrey's REAL
  `%APPDATA%\WILSON\rabbit-data`. This session created a test project
  there, verified against it, then deleted the project through the app's
  own route, removed the mirror folder `Documents\My_Work\Bins-Demo` the
  folder tree had created for it, and deleted its 36 poster cache files.
  Her other projects were not touched. If you run a dev instance, test
  only inside a project you created and remove it after.
- **The worktree has no Electron binary** (`npm install --ignore-scripts`
  skips its download). Launch with
  `ELECTRON_OVERRIDE_DIST_PATH=C:\Users\Audrey\Documents\My_Work\Dev_Work\wilson\WILSON\node_modules\electron\dist npx electron .`
  after `npx vite build --mode development` (the window loads the built
  `dist/` from the Express server; the port is random — find it with
  `netstat -ano` against the main `electron.exe` PID).
- **The signed-out app shows only the login overlay**; the shell is not
  mounted underneath, so a dev instance cannot reach R.A.B.B.I.T. without a
  session. What worked: an untracked `dev-harness/bins.html` served by
  `npx vite --config dev-harness/vite.config.mjs` (a config that extends
  `vite.config.js` with a `/api` proxy to the Electron server's port) whose
  `bins.jsx` mounts `<AgentProvider><RabbitProvider><Rabbit currentPage="rabbit" /></RabbitProvider></AgentProvider>`
  with `window.electronAPI` / `window.wilsonSession` stubbed in a `<script>`
  before the module loads (stub `getPathForFile: f => f.__path || ''` so a
  synthetic `DragEvent` with `File` objects carrying `__path` exercises the
  drop path). `document.write` of the built index does NOT re-run a module
  already evaluated in that window; an iframe does, but the login overlay
  is still there — hence the harness.
- **Express order**: a route mounted after `expressApp.get('/{*splat}', …)`
  never runs for GET; the route tests cannot see it. Pinned by a test that
  reads `main.cjs`'s source.
- **The provider value must export the collections**, not only the
  callbacks (`bins`, `binFiles`, `binRoots`, `shotTakes`): the tab read
  `ctx.bins` as undefined until it did.
- **esbuild does not check undefined names**; a multi-line lucide import
  missed by a one-line `sed` shipped `Clapperboard is not defined` to the
  first launch. `scratchpad/undef-check.mjs`-style sweep (capitalised JSX
  tags and calls vs imports/declarations) catches that class.
- **`File.path` is gone in Electron 33**; dropped-file paths need
  `webUtils.getPathForFile` in the preload (added: `electronAPI.rabbit.getPathForFile`).
- **`resolveFfmpegPath` does not look on PATH**: only `WILSON_FFMPEG_PATH`,
  the packaged resources folder, or `resources/ffmpeg/ffmpeg.exe` in the
  repo (gitignored). The route tests assert BOTH states by name.
- **The loopback gate must fail closed**: a request with neither
  `Sec-Fetch-Site` nor `Origin` is refused; tests send
  `sec-fetch-site: same-origin`. `userAuthorizedDirs` in `main.cjs` is
  another subsystem's boundary — never add to it from a request body.
- GitHub connectivity from this machine dropped several times for ~20 s at
  a time; every push and fetch is wrapped in a retry loop.
- A heredoc containing `'` inside a `<<'EOF'` body still broke bash here
  once; write patch scripts to the scratchpad with the Write tool and run
  them with `node`.
- The local-storage session's data-root change (`getRabbitDataDir` etc. are
  root-aware while a demo folder is open) needs nothing from bins: every
  helper is injected. Its `localDemoMissingGuard` is registered before the
  mount, so it covers the bin routes (also pinned by the wiring test).
