## 5. Traps hit

1. **The Bash tool's heredocs choke on this content.** `cat <<'EOF'`
   failed repeatedly with "unexpected EOF while looking for matching
   `'`" on blocks containing box-drawing characters, `’`, or long CSS.
   Write the file with the Write tool (or to the scratchpad and splice
   with Python) instead of fighting it. Cost me three retries.
2. **`\n` inside a heredoc'd Python string is a real newline.** Writing
   `'\nAVAILABLE PAGES: '` into a source file that way split a template
   literal across two lines and broke the build. Use a raw string
   (`r"...\n..."`) or double the backslash.
3. **CRLF, again** (F1 trap 3, and it bit immediately): a multi-line
   `str.replace` against a file read with `newline=''` silently matches
   nothing. Read with universal newlines and write back with
   `newline='\r\n'`. Every `.jsx` in this repo is CRLF.
4. **The `git add -A` trap in a worktree**: `.claude/launch.json` sits at
   the repo root, not under `WILSON/`, so `WILSON/.gitignore` cannot
   cover it and `git add -A` picks it up. It was committed twice before
   I noticed. Add paths explicitly, or `git rm --cached` it after.
5. **A component declared inside a render remounts its subtree.** The
   twelve page wrappers were collapsed into a `PageSurface` component —
   it MUST be module-level. Declared inside `App`, it is a new type
   every render, and the entire reason all twelve pages are mounted at
   once is to preserve their state.
6. **The console log buffer survives a reload.** A `useToast() needs a
   ToastProvider` error persisted across three reloads after the
   provider was added; a brand-new tab showed it was gone. Open a clean
   tab before believing an error is live.
7. **`scripts/screenshot.mjs --pages /team-members` alone is mangled**
   by Git Bash into `c:/Program Files/Git/team-members` (F1 trap 2).
   `root,/team-members` works because the leading `/` is no longer the
   first character of the argument; `MSYS_NO_PATHCONV=1` also works.
8. **A prefix collision in a component-name scan.** `<StatusDot` starts
   with `<Stat`, so a plain `includes('<' + name)` marked `Stat` as
   called and hid a genuinely uncalled component. Use a lookahead.
9. **`\s` in a JS template literal is just `s`.** `new RegExp(`<${name}[\s/>]`)`
   silently matched the letter s rather than whitespace, and the guard
   passed for the wrong reason. In a template literal write `\\s`, or
   avoid the escape entirely (I used `(?![A-Za-z0-9])`).
10. **A guard that a comment can satisfy is not a guard.** The caller
    scan counted `<Table` inside `Table.jsx`'s own header comment, so
    the five biggest F2 components were "called" by their own
    documentation. Strip comments and string literals before scanning
    source for usage — and pick a control that cannot satisfy itself
    (round 1's control asserted `Table`, which was the false positive).
11. **A test that re-implements the thing it tests proves nothing.**
    `pages.test.js` first built its own copy of the validator and
    asserted the copy threw; every one of those assertions survived any
    change to the real function, including deleting it. Export the
    function and call it.
12. **Specificity is per-surface.** The light hover rule is scoped
    through the table (`.ui-table[data-surface="light"] …`) and so is
    (0,6,0); a (0,4,0) selected rule loses to it. Fixing the dark pair
    and stopping is half a fix, and the tables in question are light.
13. **Fixing one edge can break the other.** Capping and centring the
    page header aligned the title with the page's content and moved the
    hamburger 76px away from the nav strip it opens — a bigger
    misalignment than the 24px one it repaired. Pad the left; leave
    `margin-left: auto` alone.
14. **`table-layout: fixed` with conditional columns.** The widths are
    only wrong in the WIDEST view, which is the one you look at last.
    Three cuts of this table claimed a sum in a comment and two were
    wrong. Compute it in a test.
15. **A `<select>` has no `text-overflow`.** It hard-clips mid-word
    instead of eliding, so a narrow fixed column truncates a department
    name with no ellipsis and no hint. Give it a `title`.
16. **`opacity: 0` is the right way to hide a hover-revealed control**
    (`display: none` and `visibility: hidden` both take it out of the
    tab order, which is the dead end Q17(b) exists to fix). The slot
    must still reserve its width or the row reflows under the pointer.
17. **The tokens test's hex ledger bites early.** Any new rule in
    `index.css` carrying a literal hex fails `tokens.test.js`
    immediately — which is the point, and it caught `#fff` and three
    colours in the state-extraction commit within a minute.

  `AWAITING_A_CALLER` names them with the lane that adopts each, and
  the test fails if the list grows. They are:
  - `SectionTitle` → **D1** (Settings has nine copies of the pattern)
  - `Panel` → **A1 / A3 / C1** (the five hand-rolled sidebars)
  - `Drawer` → **A2** (D.O.G.'s settings slide-out) and **B3**

  None of the four has an honest home on Team Members, and inventing
  one would break C1, which outranks §4's caller rule. Take your name
  off the list when your lane lands.
- **`Toast` and `StatusDot` are called from inside the kit** —
  `ToastProvider` renders one, `StatusBadge` the other. That counts:
  both are proven on a real screen through their wrapper, and a second
  direct caller would be decoration.
- **The registry is where a page is born.** Adding a page means one
  entry in `src/layout/pages.js` and nothing else. A lane converting a
  data page to `paper` (Q1) flips `surface` **in the commit that moves
  the page's own inks**, never before — `pages.test.js` pins the
  current schedule (`dog, otter, rabbit, team-members` dark; the other
  five light) so that flip is a deliberate edit to a list.
- **`measure`** caps a page and its header to one column. Only
  `team-members` sets it (`'data'`). A lane capping a page must set it
  or the title will not line up with the page's first row; `'reading'`
  exists for the 720px form pages and has no consumer yet.
- **Surface scopes** are unchanged from F1 (light / chrome / dark
  island), plus: every page wrapper is now stamped from the registry,
  so `data-surface` is no longer the scroll class's second job. Lane C
  still stamps the hand-rolled dark islands inside light pages (F1 §8
  counted 45).
- **`IconButton` has a third surface, `chrome`**, for the orange frame:
  `dark` puts `ink-2` — a grey — on orange, which the colour rule
  forbids outright.
- **Row has four states**: `selected` (a fill plus a 2px signal edge — a
  choice the user made), `highlighted` (a 2px ink-3 edge, no fill — a
  standing role), `interactive` (hover fill and a pointer), `inactive`
  (the third ink, never an opacity). Do not use `selected` for a
  standing role; a row that looks selected and is not is worse than no
  marking, and the two were the same colour for one commit.
- **`Tabs` requires `panelId`.** The caller puts `role="tabpanel"` and
  that id on the region the tabs switch; a tablist with nothing to move
  into announces "tab, 1 of 3, selected" and strands the reader. Arrow
  keys move focus, but every tab stays in the tab order — roving
  tabindex would change what Tab does on eleven existing surfaces (C1).
- **`Toolbar` has NO `role="toolbar"`** and must not gain one until
  someone implements the roving-tabindex keyboard model it promises
  (F1 trap 10, the same reason `Menu` has no menu roles).
- **`Menu` still has no ARIA roles.** F1 handed the roving focus +
  roles job to F2; F2 did not do it — the bundle's definition of done
  did not name it and the nine components plus the worked example filled
  the session. It is a small, self-contained piece of work and it
  belongs to whichever lane first needs a keyboard-navigable menu
  (A2 has the D.O.G. context menu). **Recorded as a kit request.**
