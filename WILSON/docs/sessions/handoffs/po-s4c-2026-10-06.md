15. **`fs.readdirSync` answers in the file system's order**, alphabetical on NTFS and hash order on ext4: a merge that must be predictable sorts the entries, and a test that reasons "the clash comes last" names its files so it does.
16. **A fake Supabase client has to model what the adapter leans on**: `.or('a.like.x,b.like.y')`, `.like` with LIKE semantics (`%`, `_`, backslash escapes), `.range` for the pages, `select('id', { count: 'exact', head: true })`, an update or delete followed by `.select()` answering the rows it touched — and the ways a call can go wrong (refused, filtered to no row, committed with its answer lost, a READ that errors, a bucket that cannot be listed). The fake in `shotRefilingCloud.test.js` carries them as hooks (`failUpdate` returning `'filtered'` or `'committed:<msg>'`, `failDelete`, `failRead`, `failList`, `onMove`, a `hidden` set) so a test states which failure it means — and it hides trashed rows from a SELECT as `files_select` does, which is what showed the adapter's `deleted_at` branches were dead code (round 2). A ranged read with no ORDER answers in a different rotation each call, as Postgres may, so a page read without an order is caught.
17. **`materializeFolderDirs` remakes a directory for EVERY row** after each moved shot — the still-pending ones too — so "the shot's directory exists" says nothing about where its files are. A refusal that reasons from the disk must look at the directory's CONTENTS and the files' places, never at `existsSync(dir)` alone (round 2, the fallback-folder finding, and the first version of its fix, which an empty directory defeated).
18. **`resolveProjectFolder` answers a FALLBACK**, `<root base>/<slug>`, when the recorded `folder_root` cannot be reached, and that fallback exists on any machine where an asset was once added offline. A root that resolves is not yet the project's folder; compare it with the recorded one (`sameDir`) before trusting what it does not contain.
19. **React's `disabled` check reads the fiber's prop, not the DOM attribute** (trap 13 again, from the other side): `creating.removeAttribute('disabled')` in a test changes nothing about what React dispatches.
20. **A custom message on `expect(x).toEqual(y)` is not printed by this reporter** when the diff is shown; `expect(JSON.stringify(x)).toBe('DIAG')` is the quick way to see a value from inside a vitest run whose console output is not shown.
21. **A planted fault can HANG the suite rather than fail a test**, and the plant runner then reports CRASHED (no "Tests N passed" line), which proves nothing either way. A walk that queues children while re-scanning a list whose paths it does not update never drains its queue.
