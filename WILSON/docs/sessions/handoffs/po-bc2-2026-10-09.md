### Why the predicate is not `supportsManagedFiles`

`supportsManagedFiles` answers "which store holds this project's FILES" — a storage MODE, and on the cloud inside the desktop it is the cloud's. The bins' question is different: "can THIS computer read the company's footage where it is?" — a property of the process (the desktop's file process answers its ping) and of the network (each location, once agreed to, answered), not of the storage mode. Composing on `supportsManagedFiles` would have composed nothing on the cloud (where clips most need the desktop) and tied a reachability question to a storage choice. It is untouched (pinned in item 1).

## 5. Traps hit

1. **CI was red for six pushes and nobody looked.** Item 4 made a leaf component import the provider; the suite passed here because `.env.local` has a Supabase address and failed in CI, which has none. Read CI after every push (`curl https://api.github.com/repos/pretty-aud/wilson/commits/<sha>/check-runs`, then `/check-runs/<id>/annotations` names the failing files). Reproduce CI here with `VITE_SUPABASE_URL= VITE_SUPABASE_ANON_KEY= npx vitest run …` (a process variable outranks `.env.local`).
2. **A synchronous `fs` call on a dead network path freezes Electron's main process** — 5 s for an unresolvable name, 42 s for an address nothing answers, the first call only (Windows then caches the failure for a while). And **`UV_THREADPOOL_SIZE` cannot be set from main.cjs** — measured, it reads 16 and changes nothing; Electron's main process has four pool threads, shared by every async `fs` call, `sendFile` and `express.static`. Ask a share in a worker thread (a synchronous stat there), or cap what goes on the pool.
3. **Every new option of the cloud routes must be passed through `mountRabbitBins`** (it hands `mountCloudBins` a fixed set). Missed three times this session (the wait and keep times, then the off keep and cap, then the root question); each time a test silently used the default.
4. **Backslashes:** a shell heredoc into a Python string halves them (a non-raw `'''…'''` reads `\\` as `\`), and a backslash in a command-line argument is eaten. Use the Write/Edit tools, or a raw string in a script file; pass only a number on the command line and build the path inside.
5. **A Python text-mode rewrite turns a CRLF file into LF** (RabbitProvider once). Read and write bytes; a match against a CRLF file must use `\r\n`.
6. **A scratch Vite config cannot import the worktree's `vite.config.js` by a `file://` URL** (its `__dirname` is undefined there); import it by a relative path so Vite bundles it.
7. **The browser pane's page reloads on a hot update**, and the dev fixtures live in the page's memory; script the rehearsal in one Playwright session instead.
8. **The dev fixtures refused every clip add** until `88b7965e`.
9. **`net use \\HOST@PORT\share`** starts Windows' WebClient without administrator rights where `Start-Service WebClient` is refused; the path is a UNC path every `fs` call takes.
10. **The harness keeps its agreements in memory**: clear `harness-cloud-bins-local.json` AND restart it between rehearsal runs, or the second run's "not connected" screens never appear.
11. **An intermittent stall in the rehearsal, cause not found.** In 3 of about 9 runs the page sent no further request after a Connect or a pick, with no console error; the harness answered every request it received, and every tile request in those windows finished. Never seen in the desktop-app runs (which call the routes directly, not through the UI); the final runs at both sizes were clean. Walkthrough 57 asks Audrey to reload and say if she sees it.
12. **Flaky under full-suite load:** the type-scale CONTROL test's 5 s limit (6.9 s once; BC1 trap 16) and once the signed-out same-origin gate test (passed in three isolated runs and the next full run).
