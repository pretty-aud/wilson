### The fix (`09b215fa`, `bd53e32e`)

- **`WILSON/gateway/test/e2e/containerChecks.sh`** (new), sourced at the top of each step of the container job after `set -euo pipefail`, as `. … <label> [<container> [<fake cloud's dir>]]`:
  - `has <text>` writes `docker logs` to `/tmp/<container>.log` and greps the file — no pipe from `docker logs` anywhere in the job;
  - `fail '<sentence>'` ends the step with that sentence as its first annotation; a command that fails under `set -e` (in a function or a command substitution too: `set -E`) is recorded with its line by an ERR trap;
  - on any failure, an EXIT trap prints a marker line, waits up to 5 s for it to reach the step's captured output (`tee`), and leaves **one multi-line error annotation each** for: what failed, the step's own last 25 lines, the container's last 40 log lines, and the fake cloud's last 10 for step 2. Each message is cut from the FRONT to its newest 4,000 characters at a line boundary, then `%`, CR and LF escaped (titles also `:` and `,`): the runner keeps a step's **first ten** error annotations and each message's **first 4,096 characters** (`actions/runner` `src/Runner.Worker/ExecutionContext.cs`: `_maxCountPerIssueType = 10`, `_maxIssueMessageLength = 4096`, read at the source), so one line per annotation showed the oldest ten of forty, and forty gateway lines in one message would have lost the newest.
- **The container job**: every check through `has`, `head` and `grep` on the snapshot files; every failure path a `fail` with its sentence (the old sentences kept); the Range read's three conditions each fail on their own (the old `[ … ] && [ … ] && cmp` let the first two fail silently under `set -e`); the fixed `sleep 1` before reading `clip_served` became a wait of up to 10 s; the switch-off wait waits for `outside_closed {"reason":"closed_switch_off"`, not any close, and fails by name when it never comes. The fake cloud's stderr goes to `/tmp/fc/err.log`, out of the step's output pipe.
- **The ACME job**: `curl … | head -c 400` became a file then `head` (the same trap: `head` stops reading while curl may still write); its Pebble log on failure is one annotation.
- **The tests job**: its `npm ci` echo (GW2's trap 3) could never run — `shell: bash` is `-eo pipefail`, so a failed `npm ci | tee …` ended the step before `s=${PIPESTATUS[0]}`; now `s=0; npm ci … | tee … || s=${PIPESTATUS[0]}` (checked: the old form exits 7 before its echo, the new one echoes), and ten lines, the runner's count.

## 5. Traps hit

- **`docker logs X | grep -q Y` under `set -o pipefail` fails about one time in a hundred with Y in the log**: `grep -q` stops at its match, `docker logs` is killed by SIGPIPE writing the rest, and the pipeline's 141 reads as "missing". Write the log to a file, then grep the file. Any reader that stops early does the same (`head`, `grep -m`, `grep -l`); `rls.yml` met it with `echo | grep -q`.
- **`|| { echo '…'; exit 1; }` is invisible to an ERR trap**: bash runs no ERR trap on `exit`. A step's diagnostics belong in an EXIT trap, and a failure needs its sentence as an annotation of its own.
- **The runner keeps a step's first ten error annotations and each message's first 4,096 characters** (`ExecutionContext.cs`). Put many lines in one annotation (`%0A` between them, `%` escaped first), cut from the front.
- **`shell: bash` in a workflow means `-eo pipefail`**: `cmd | tee log; s=${PIPESTATUS[0]}` never reaches the assignment when `cmd` fails; write `s=0; cmd | tee log || s=${PIPESTATUS[0]}`.
- **A failing job's log is admin-only, but its steps are not**: `https://api.github.com/repos/<owner>/<repo>/actions/jobs/<job id>` gives every step's conclusion and start and end times without signing in. A step that failed in 7 s where it takes 17 s, with no annotation, named the check.
- **The container job is gated on the tests job**: a Windows test's timeout on GW5's last head skipped it, so GW5's round 2 first met it at the merge (GW2's trap 3, again).
- **A fresh worktree has no `WILSON/node_modules`, and `npx vitest` then finds the MAIN checkout's**, an older tree without `jsdom`: 122 jsdom files fail to start ("Cannot find package 'jsdom'") and the run counts 235 files, not 357. `npm ci --ignore-scripts --prefer-offline` in the worktree's `WILSON/` (from npm's cache, 30 s) gives the real count; the lockfile stays unchanged.
- **The plain full run is load-sensitive here**: twice at `bd53e32e` it timed out one Timeline test and cascaded through its file (31 failures, two files, both green alone); `--maxWorkers=4` ran all 357 files green.
- **Git for Windows' bash strips a CR before LF in a command substitution; Linux bash keeps it.** A test of CR escaping puts the CR mid-line.
- **The Bash tool's safety check refuses `rm` inside a `bash -c` script**: scratch harnesses write into the scratchpad and delete nothing.
