## The shared piece for VW1e

Everything lives in `src/tools/rabbit_v0.1.0/views/tableViews/`; `ProjectTasksView.jsx` is the one
caller and the pattern.

- **`viewScreenModel.js`**, pure rules: the fields on screen (`effectiveFields`, `fieldsToStore`,
  `moveFieldTo`, `moveField`), the filters (`appliesFilter` is the one answer to "does this row
  filter", used by `filterCount`, the summaries and `applyViewFilters`; `withFilterField` resets a
  row's condition and value), the sorts (`applyViewSorts`, `withFirstSort`,
  `withFirstSortReversed`, `moveItem`, `moveItemTo`), `sameEffect` (values compared as sets), the
  summaries, `barStateOf` (the bar's states and `BAR_WORDS`), `viewOnScreen`, `copyName`.
- **A table's description**, as `tasksTableView.js`'s `tasksDescription(…)`: `tableKey`, `fields`
  (each `{ key, label, filter: 'choice' | 'item' | 'text', sortable, groupable, kind, column }`),
  `field(key)`, `columns`, `fieldKeys`, `fixed` (the name), `filterFields`, `sortFields`,
  `groupFields`, `cardFields`, `filterOps(def)`, `valuesOf(row, key)`, `compare(key, a, b)`,
  `options(key)` (with each option's `apart` text), `hideEmptyDefault(layout, field)`. Every key is
  the table's column key (§5.1). Lookups by a stored key go through own-key checks (round 2, R2-7).
- **`useTableView({ ctx, tableKey, description, canWrite, nameOf, notify })`** answers
  `{ api, available, error, views, allView, viewId, name, deleted, waiting, config, fromDraft,
  changedBy, bar, canEdit, update, choose, reset, save, saveAsNew, create, duplicate, rename,
  remove, reorder }`. It keeps the change for now in the provider (`viewDraftOf` / `setViewDraft`,
  or local state with no provider API), pins the last used view for the visit, holds a save's
  refusal per view and revision, and says a teammate's delete through `notify`.
- **The wiring, in `ProjectTasksView.jsx`:** the description in a memo; `tv = useTableView(…)`;
  the table's layout, filters, sorts, group, fields and key dates read from `tv.config`; a change
  written back only while `tv.fromDraft`; `useAsk()` for the root's questions (`{ ask, dialog }`);
  one polite live region fed by `announce`; `<TableViewsMenu tv description ask announce>` in the
  toolbar; `<ViewFilterRow>` per row in the strip under it; `<ViewBar tv ask announce focusViews>`;
  the kit Loading line while `tv.waiting`; `<CreateGroupingDialog>` while grouped by a linked kind;
  the old key removed in an effect (`OLD_SAVED_VIEWS_KEY`), its test with a control that keeps
  another table's key.
- **What the Tasks table did not need and the others do:** the columns in front of the name
  (`config.leading`, Q-J), the Gallery (Q8) and its cards' fields, the Scenes table's nested shot
  rows, a Views button width per table (`tableViews.css`, `[data-table="…"]`, declared in
  `tableViewsCss.test.js`'s `VARIABLE` list).
- **The kit as VW1d left it:** `Popover` with `inPlace` (no portal, under its anchor, at least
  240px wide and never past the window, closing on a Tab out unless focus went into another layer);
  `MenuButton` in `src/ui` (a labelled form; the arrows, Home, End and Tab out); `Banner`
  `live={false}` for a bar that is not an announcement.
