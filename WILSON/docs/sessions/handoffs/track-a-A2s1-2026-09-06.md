## 5. Traps hit (the brief did not say these)

- **A track branch can be held by the previous session's worktree.** `git
  checkout --ignore-other-worktrees <branch>` is the precedent (Track B, then
  this session). The old worktree goes stale, not broken.
- **Brace-matching extractors break on a `{` in a parameter list.** Both the
  `folderParity.test.js`-style `extractFunction` and a `functionBody` helper
  take the first `{` after the name — a destructured or defaulted-object
  parameter (`{ sweepDependencies = false } = {}`, `({ tasks, groups })`) is
  taken for the body and the extract is garbage. Match the parentheses first,
  then the braces (both new test files do). `rabbitSubentityRoutes` keeps a
  plain `opts` parameter for the same reason, and its comment says so.
- **The Phase 7 brief's surface table was line-numbered and incomplete.** By
  symbol on 2026-09-06: the Tasks tab's two drag-drop targets write statuses
  and were not listed; the Dashboard writes statuses through a model with no
  dependency data; and "done" had two definitions, not one. Enumerate by grep
  every time.
- **"Done" is two questions, not one.** Whether a PREDECESSOR is finished
  (omitted counts) and whether a TARGET status asserts completion (omitted
  does not) are different sets, and one `isDone` cannot answer both. The
  first build used one and warned on every move to Omitted; R1 caught it.
  Any future status-based rule should say which role it is asking about.
- **Nothing was refused by the desktop app's classifier this session** — dev
  query, staging `link` + query through a scratch workdir, `functions list` on
  two projects all ran. The wall is per command, as the protocol now says.
- **The review subagent died on the account's session rate limit (429)
  before it started, silently except for its task notification.** Relaunched,
  it ran. A review that arrives as "I'll start by reading…" and nothing else
  was not a review.
- **A breaker claim goes into a commit message AFTER the run, never before.**
  `4c645f7`'s message said its RelationsPanel breaker was red; the message
  had been written first, and the breaker was green — the pin matched
  `updateTask(` and the code calls `ctx?.updateTask?.(…)`. `564f02c` corrects
  both. Pre-writing a message to save a round is how a false claim reaches
  history; run the breaker, read the line, then write the sentence.
- **Python on this machine prints to a cp1252 console:** a `→` in a `print()`
  raises AFTER the file writes have happened. Harmless, confusing — keep
  prints ASCII or set `PYTHONIOENCODING=utf-8`.
- **Dynamic strings are not labels.** The walkthrough label-check script
  flags "2 selected" and a counts line as missing because the app renders
  them from numbers; quote those, backtick only literal labels.
- **`npx vite build` is a 15-second gate and vitest is a 3-second one.** No
  test in this repo mounts React, so a JSX slip in a view would pass vitest;
  the build (plus a per-file `esbuild` pass) is what catches it. Run both
  before committing a view change.
- **The three `edit` scripts in the scratchpad** (exact-string edits from a
  JSON spec, a breaker runner that restores files after each mutation, and the
  label check) are worth recreating; the Edit tool insists on a prior Read and
  a heredoc mangles backslashes, and both problems disappear with a JSON spec
  written by the Write tool.
