## 5. Traps hit

1. 🚨 **T0's "140 / 2858, green" DOES NOT REPRODUCE ON WINDOWS, AND THE WAY IT
   FAILS IS QUIET.** At `e1b5c31` this machine reports 139 passed + 1 failed
   SUITE / 2823 tests. Vitest renders a suite that cannot be collected as
   `typeScale.test.js (0 test)` — **one failed suite, zero failed tests** — so
   the summary line stays calm and the whole 35-case type guard silently does
   not run. `node --check`, a direct `await import()` and `esbuild.transformSync`
   all accept the file, so the three checks anyone reaches for first say it is
   fine. Only the module runner sees it.

   **Cause (T3's, and it is the better diagnosis):** Git for Windows sets
   `core.autocrlf=true` in its SYSTEM config, so every worktree gets CRLF
   although every blob is LF. Vite's SSR transform strips a
   `#!/usr/bin/env node` hashbang, and the strip only matches an LF-terminated
   one; with CRLF the hashbang survives into the middle of the rewritten body.
   `typeScale.test.js` imports six hashbanged scripts, so any one is enough.

   CI never saw it: Linux checkouts are LF either way. **T1 and T3 hit this
   within minutes of each other and fixed it two different ways.** T1
   externalised `scripts/*.mjs` in `vitest.config.js` (symptom); T3 pinned
   `*.mjs text eol=lf` in `.gitattributes` (cause). T1's was reverted in
   `32e2a83`.

   🚨 **AND `.gitattributes` DOES NOT CONVERT A WORKTREE THAT ALREADY EXISTS.**
   A session whose worktree predates `b4eac8f` must convert the tracked `.mjs`
   files in place (or delete and re-check-them-out) or its guard stays dead
   while the suite reads 2823 and looks calm.

2. 🚨 **"0 OFF-SCALE ON ALL TWELVE PAGES" WAS TRUE AND WAS ABOUT SOMEWHERE
   ELSE.** `ui-page-check.mjs` walks `/otter`, but `.lesson-content` does not
   exist in the DOM until a course AND a subject have been clicked — so the
   check had only ever measured the course library, while the reading surface
   behind it carried h1 at 24px, h3 at 17.6px and code at 14.4px. Every
   class-based assertion was equally silent, because they sweep JS and JSX and
   this is CSS.

   This is T0's trap 16 (Timeline and Files open on an empty state) on a third
   surface, and **T2 hit the fourth the same afternoon** — its own page check
   never opened a project. **If a bundle's headline surface needs a click to
   exist, no check in this repo reaches it until someone teaches one to click.**
   `ui-shots.mjs` now has an `otter-lesson` page that drives in and then ASKS
   THE DOM whether `.lesson-content` is there, because a drive that silently
   misses produces a plausible screenshot of the wrong thing.

3. 🚨 **GIT AUTO-MERGED TWO SESSIONS' GUARDS WITH NO CONFLICT MARKER AND BROKE
   THE FILE.** T1 and T3 both added inline-type machinery to
   `typeScale.test.js` within the same hour, in different places, both
   declaring `const INLINE_SIZE`. Git took both. The result is
   `SyntaxError: Identifier 'INLINE_SIZE' has already been declared` — which
   vitest reports as `(0 test)`, the SAME silent shape as trap 1, arrived at a
   third way. **A clean `git merge` is not evidence that two sessions' work
   composes.** Run the suite after every merge, and read the file.

   It happened twice more in miniature: `ui-shots.mjs` (T1 made the prefix
   `argv[5]`, T2 made it an env var) and the T2 ratchet (T1 wrote one, T2
   finished the lane and replaced it with a hard assertion). **In all three
   cases the right resolution was to delete T1's half**, because the other
   session's design was better. Merging in tandem is not only about text.

4. ⚠️ **AN AUDIT COLUMN AND A RATCHET ARE NOT THE SAME MEASUREMENT.** T1 set
   `INLINE_SIZE_RESIDUE = 57` to match `ui-audit.mjs` and a mutant proved it
   had four spare notches: the audit counts the bare key and four sites are
   already token reads. **Two wrongs looked like a right** — T1's first regex
   had a backtracking defect that inflated its count by exactly those four, so
   the agreement read as confirmation. Set a ratchet from the guard's own
   sweep, never from a census. (T2 hit the identical lesson two hours later:
   `4b00e65 fix(t2): a ratchet set from the wrong measurement is a ratchet
   with slack`.)

5. 🚨 **`\s*` BEFORE A NEGATIVE LOOKAHEAD BACKTRACKS TO ZERO AND INVERTS IT.**
   `font-size:\s*(?!var\(--text-)` reads correctly and is wrong: `\s*` gives
   the space back, the lookahead is evaluated against the SPACE, a space is not
   `var(`, and the exemption fires backwards. Put the lookahead immediately
   after the colon and consume nothing before deciding. This is the fourth
   boundary-ish regex trap in this bundle's history and the fourth found by a
   control rather than by reading.

6. ⚠️ **A PATTERN THAT MATCHES THE VALUE CANNOT SEE A TEMPLATE LITERAL.**
   `fontSize\s*:\s*['"]?[\w.%-]+` counted 41 where the audit counted 68; the
   sixteen it missed had backtick or expression values. Match the KEY.

7. 🚨 **A REGEX CANNOT EXTRACT A CSS RULE.** `\.lesson-content[^{}]*\{[^{}]*\}`
   cannot cross a nested brace, so a rule using CSS nesting or wrapping an
   `@media` does not get truncated — it DISAPPEARS with its declarations. A
   reviewer nested two real rules with a live `font-size: 1.5rem` inside and
   every assertion INCLUDING its control stayed green, because the floor was
   `>= 15` over a 17-rule block. Walk the braces; make the count exact.

8. 🚨 **A CONTROL THAT TESTS A LITERAL IS NOT A CONTROL.** T1's stylesheet
   control checked regexes against strings typed in the test file; nothing
   proved `extract -> join -> match` ever reached a detector. That is rule 1 of
   that file's own header, violated two paragraphs from where it is written,
   and it is why trap 7 was invisible. The file already had the right shape
   twice (`bareLabelsRaw(false)`, `hardCodedInline(re, false)`).

9. ⚠️ **`.lesson-content p` IS A SUBSTRING OF `.lesson-content pre`.** Round
   one added a required-selector list to make a vanished rule loud, wrote the
   paragraph entry as `' p '` — it saw the problem — and then discarded the
   boundary with `.trim()`. A reviewer deleted the `p` rule, split `ul, ol` to
   keep the count at 17, and the control stayed green with `pre` answering for
   `p`.

10. ⚠️ **"THE RULE THAT SELECTS `p`" IS NOT THE SAME AS "THE RULE THAT SELECTS
    PARAGRAPHS".** Asking whether the token `p` appears in a selector is
    satisfied by `.lesson-content :is(h1, h2, h3, blockquote) p`, which caps
    paragraphs inside headings and leaves every top-level paragraph uncapped —
    under an assertion titled "the measure is on the PROSE rule".

11. ⚠️ **A RATCHET NEEDS A DENOMINATOR, AND THIS REPO PUTS VERSIONS IN PATHS.**
    `T2_LANE = /^src\/tools\/rabbit_v0\.1\.0\//`. A reviewer bumped the
    directory to `v0.1.1`: the count went 77 → 0 and the assertion stayed
    green, taking 77 live declarations out from under the only thing watching
    them. Assert the lane is non-empty as well as clean. The same applies to
    `toEqual([])` over a scoped sweep — an empty scan is the same green as a
    clean one.

12. ⚠️ **AN ALLOWLIST ENTRY IS A CLAIM, AND CLAIMS CAN BE FALSE.** T1 excused
    `Otter.jsx`'s Monaco `fontSize: 14` because "a token string would break the
    editor". True of a string, and beside the point: `tokens.js` builds `TYPE`
    with `Number(...)`, so `TYPE.body` IS 14. The entry bought nothing and cost
    an 800-character exempt window in the largest file in the lane. **Look for
    the token before writing the exemption.**

13. ⚠️ **`git checkout <sha> -- <paths>` STAGES WHAT IT RESTORES** (T0 trap 10,
    hit again). Used here to reconstruct the "before" screenshots after the
    work was done; `git reset HEAD -- <paths>` immediately after, and
    `git diff --numstat` empty either side of the window.

14. ⚠️ **A FIX APPLIED TO ONE SITE IS NOT A PRINCIPLE APPLIED.** T1 removed one
    `leading-tight` and wrote "the class is gone". **156 sites app-wide pair a
    scale step with a hand-set leading** — 19 in T1's own lane, 38 in T2's, 99
    elsewhere. Either narrow the claim or add the guard; T1 did both (a ratchet
    at 156, and the claim narrowed here).

15. ⚠️ **SETTING `font-size` ON A CONTAINER RE-BASES EVERY `em` BENEATH IT.**
    `.lesson-content` going 16px → 14px moved `oneDark`'s inline `padding: 1em`
    / `margin: 0.5em 0` on fenced code blocks from 16/8px (on §3.3's grid) to
    14/7px (off it). Recorded for A3 rather than fixed, because it is spacing.

16. ⚠️ **`PreTag="div"` IS ON ONE BRANCH ONLY.** T1 told A3 that
    `.lesson-content pre` was dead and not worth converting. A fence with NO
    language tag takes the other branch and react-markdown still wraps it in a
    `<pre>` — and lesson content is generated markdown where untagged fences
    are routine. **A note that sends the next session the wrong way is worse
    than no note**; round two caught it.

17. 📌 **A HEREDOC IS NOT A SAFE WAY TO WRITE A LONG COMMIT MESSAGE.** Two of
    this session's commit messages failed to parse in `bash <<'EOF'` for
    quoting reasons that were not obvious. Write the message to a file and use
    `git commit -F`.

18. 📌 **`/tmp` IS `C:\tmp` TO NODE AND SOMETHING ELSE TO GIT BASH** (T0 trap 9,
    hit again on the first attempt to write a transform dump).

19. 📌 **BLOCK COMMENTS AND GLOBS DO NOT MIX.** Writing `src/**/*.{js,jsx}`
    inside a `/* … */` comment closes the comment at the `*/` in `**/*`. It
    broke `typeScale.test.js` in a way that took a full vitest run to see.
