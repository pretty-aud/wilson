## 5. Traps hit

1. **A session that must run on a model the picker does not show stops and
   says so** — and Audrey may answer with a different model. S4d ran on
   Fable 5.1 at her word; the hand-off says so on line one.
2. **`supabase db query --linked` through the shim refuses a `''` claims
   setting.** `set_config('request.jwt.claims', '', true)` is what every
   suite does between actors, but `current_app_role()` casts the setting to
   JSONB and `''::jsonb` raises ("invalid input syntax for type json ...
   during startup"). A probe that calls a predicate "with no claims" must
   use a claims object WITHOUT `app_role` (0074's probe 29 shape), never an
   empty string. (`auth.uid()` tolerates `''`; the 0008 helper does not.)
3. **The working copy is CRLF for tracked files** (`core.autocrlf = true`)
   while new files written by the session are LF. A planted-fault runner
   that matches multi-line patterns must convert its patterns to the file's
   own line endings, or every fault "SKIPs" with "pattern found 0 times".
   The Python console must be reconfigured to UTF-8 before printing an
   em-dash, or it dies at the first CAUGHT line.
4. **A fixed uuid in a migration's synthetic check is a files id the client
   can occupy.** Round 2 found that post-condition 10's `'00000000-…'`
   entity id, planted as an ordinary files row by any member, would make
   every 0092 re-run raise. Synthetic calls take NULL.
5. **An OUT column cannot be added under CREATE OR REPLACE, and dropping the
   function to grow it makes the migration that owns it un-replayable.**
   The Legal verdict lives in a function of its own beside 0088's classifier.
6. **A comment stripper that does not understand SQL quoting is a scalpel
   for the attacker**: `'admin/*' OR … OR 'x' = '*/'` is valid SQL that the
   stripper deletes before a whole-body comparison. Whole-body pins compare
   the raw source; must-not-contain checks run on the raw definition.
7. **`pg_get_triggerdef` and the raw `files` arm of `fn_realtime_broadcast`
   are pinnable whole** (whitespace collapsed); a pin by pieces (named once,
   a function named twice) let an arm that exempted LEGAL rows through.
8. **Absence probes need rows to refuse.** `budget_lines` and
   `project_rate_overrides` have no fixture rows on project A, so "reads 0"
   was true of an empty table; seed one row per table with a project-manager
   control.
9. **The browser pane may not draw while hidden**; `find` / `read_page` /
   `get_page_text` verify the tree without a screenshot, and a `computer`
   click that times out on "not drawn yet" works on the retry.
10. **A full vitest run concurrent with a reviewer subagent that plants and
    restores faults shows load-dependent failures in unrelated files.** Take
    the final count from a run made while nothing else edits `src/`.
11. **`stamp()`-based fixture events sort against a test's pushed events** —
    a contract test that expects exactly one event id must sort or include
    the seeded one.
12. **The nil-uuid probe of the gate is safe** (a STABLE SQL function, false
    for everyone, "no such function" where 0092 is missing), and it must be
    made by BOTH clients that file Legal files — the adapter and the
    desktop→cloud migration — or the two disagree on a 0088-only database.

### Decisions

1. **Workspace managers can ADD Legal files, not only see them** (the four
   files policies and both buckets' INSERT policies carry the Legal arm, so
   Add as Legal is offered to them). The brief's reading of "see" and
   "access a folder to review things" was taken to include adding, editing
   the note, trashing and restoring — the same verbs the money audience has.
   If "see" meant read-only, the INSERT / UPDATE / DELETE arms are one word
   each to narrow (and `canSeeProjectLegal`'s callers to split).
2. **S4b-10 now reaches workspace managers too**: a workspace manager can
   rename a Legal OBJECT out of LEGAL through the Storage API, as a
   money-cleared person could (OUTSTANDING S4b-10, dated note). The
   validated fix is still the RESTRICTIVE UPDATE policy on both buckets with
   a resumable-upload smoke test on dev first — your call.
3. **S4d-01 (older)**: the eight money storage policies carry no
   private-project hop of their own, so a non-creator holding a manager seat
   on a private project reaches its invoice OBJECTS (and, through the money
   half of the Legal predicate, its Legal objects) while the rows are
   hidden. Fix: the hop in all eight, or `passes_project_privacy` inside
   `can_access_project_money` — which narrows the money gate for a
   non-creator manager and so needs your nod.
4. **S4d-02 (older)**: `edit_history_select` has no private-project arm; a
   private project's ordinary history (a task's or scene's diff) is readable
   by every workspace admin and manager. Owner: a session on private
   projects.
5. **S4b-11** (whether any company ran the desktop→cloud migration before
   S4b) is untouched and still yours.
