## For GW3 (the web app)

**The routes, as built** (both doors unless said; every response carries `Cache-Control: no-store`, `Pragma: no-cache`, `X-Content-Type-Options: nosniff`, `Cross-Origin-Resource-Policy: cross-origin`, `Referrer-Policy: no-referrer`, `Strict-Transport-Security: max-age=31536000`; no `Server`, `Date`, `ETag` or `Last-Modified`):

| Route | Door | Answers |
|---|---|---|
| `GET /v1/path` | inside | 200 `{ "gateway_id", "path": "inside", "version" }`; outside: 404, no body |
| `GET /v1/health` | inside | 200 `{ name, version, doors: { inside: { state, addresses }, outside: { state } }, reach: { <location id>: state }, certificate: { fingerprint, root_until, leaf_until }, line, warnings }` |
| `GET /v1/health` | outside | 200 `{ "ok": true }`, plus `"nonce_echo": "<nonce>"` only when the request's `Wilson-Reach-Nonce` header equals the cloud's current nonce (constant-time) |
| `GET`/`HEAD /v1/clips/{id}?t=<ticket>` | both | 200 (no Range) or 206 with `Content-Type` (from the file on disk), `Accept-Ranges: bytes`, `Content-Length`, `Content-Range` (206), `Wilson-Gateway-Path: inside\|outside`; HEAD: the same headers, no body |
| `POST /v1/clips/{id}/renew` | both | body exactly `{ "jti": "<the URL ticket's jti>", "t": "<a fresh ticket>" }`, `Content-Type: application/json` → 204 with `Wilson-Gateway-Path`; 401 for every failure; 413 when the body is over 8 KB; 429 with `Retry-After` |
| `OPTIONS` (any path) | both | the web app's origins (`web_app_origins` at sync), methods GET, HEAD, POST, headers Range and Content-Type → 204 with `Access-Control-Allow-Origin` (the origin), `Vary: Origin`, `Access-Control-Allow-Methods: GET, HEAD, POST`, `Access-Control-Allow-Headers: Range, Content-Type`, `Access-Control-Max-Age: 600`, and `Access-Control-Allow-Private-Network: true` on the inside door only, when asked; anything else 403 |
| `GET /` | inside | the status page (HTML, `Content-Security-Policy: default-src 'none'; style-src 'unsafe-inline'; …`): the health line and the fingerprint |

CORS on a simple request from an allowed origin: `Access-Control-Allow-Origin`, `Vary: Origin`, `Access-Control-Expose-Headers: Content-Range, Content-Length, Accept-Ranges, Wilson-Gateway-Path`. A `<video>` without `crossorigin` needs none of it.

**The statuses of a clip request, in the order the checks run:** 401 (no ticket, two `t` parameters, the shape, the 4096-character cap, the signature, an unknown `kid` after ONE extra sync of at most 5 s, the URL's id is not the ticket's `clip`, the dates with 30 s of skew, another gateway or workspace, `rv` false on the outside door; the 10th on one connection is answered with `Connection: close` and the connection ends); 429 (600 requests a minute per person; then 8 concurrent responses per person, the pool, and outside the 30 GB an hour); 404 (an unknown location, a location the gateway knows is down or not connected, the path's shape, the join leaving the root, the catalogue check, realpath leaving the root, a sequence without a sequence, not a file); 415 (a type off the list, `mt` disagreeing, a sequence whose middle frame is no allow-listed still); 416 (more than one range, an unsatisfiable or malformed one, with `Content-Range: bytes */<size>`). No body on any of them except one: on the INSIDE door, a clip the cloud has never confirmed while the cloud is unreachable answers 404 with the text `WILSON’s cloud is unreachable, so this clip cannot be confirmed yet`. The inside door names itself (`Wilson-Gateway-Path: inside`) on its refusals; the outside door does not, except on a 416. On the inside door, any proxy header (the 18 in `gateway/src/rules/peers.mjs` `PROXY_HEADERS`) or a `Host` that is not the gateway's own name or address is 403 with no body, before any route. One connection serves at most 1,000 requests; its last answer says `Connection: close`. A request sent on a connection before the previous answer arrived (HTTP/1.1 pipelining, which no browser does) ends the connection.

**What the player must know:**
- **A stream is the URL's ticket's `jti`.** Renew with THAT `jti` before the stream's current authority ends (at 75 s, as the design says); every later Range request of the same `<video>` then works on the old URL. Without a renewal the first request after the authority's end (+30 s) is 401, and a response still streaming is cut within 5 s of it (D5). A stream lives four hours in all.
- **Never retry a 401 with the same ticket.** Fetch a fresh one. Ten failed tickets on one connection close it; the browser then opens another, which the door's per-peer connection caps count (60 new connections a minute per address outside, 120 inside; an IPv6 /64 is one address outside).
- **The browser on the gateway's own computer cannot use the office door**: the door closes its own host before TLS, by design (§4). On that computer the web app must say so (or use the outside door while the switch is on).
- **A location the gateway has not been connected to is `not_connected` in its reach, and its clips are 404.** On Windows the gateway contacts a share's server only after an administrator ran `wilson-gateway share-login \\server\share` there (or listed the server in `config.json`'s `connect_without_login`): the cloud's location list is written by any project editor, and a contact authenticates as that computer. Settings should say *run share-login on the gateway* for such a location. A location whose address is no share address at all (the device namespace `\\?\`, WebDAV's `host@SSL`, the `pipe`, `mailslot` or `IPC$` share, a DOS device name, a segment ending in a dot or a space, an invisible character) is dropped by the gateway and absent from its reach report: Settings should say *this gateway cannot use this address* when a location is missing from `reach`. The other spellings of the gateway's own computer stay the cloud's CHECK's to refuse, as `localhost` and `C$` are (review round 2, R2-N1): `127.1`, `0`, `0x7f.1`, and the `ipv6-literal.net` transcriptions such as `0--1.ipv6-literal.net` all pass the gateway's shape rule (and still need an administrator's consent to be contacted).
- **`mt` may be `""` or `null`** (0091 lets the row hold none; GW1 sends `""`): the type then comes from the file alone. A non-empty `mt` that names another type than the file on disk is a 415.
- **A sequence (`seq: true`) serves its middle frame**, only when that frame is a JPEG, PNG, WebP, GIF or AVIF; an EXR or DPX sequence is a 415.
- **The catalogue check costs one round trip to the cloud on a clip's first request** (and every ten minutes after); a cloud that does not confirm is a 404.

3. **The sync body, now in GW1's names** (GW2 renamed its fields to what `parseSyncRequest` reads; a test holds every field to GW1's types and sizes): `{ name, version, platform, hostname, inside_addresses: [{ host, port }], inside_names, root_fingerprint, reach: { <location id>: 'reachable'|'not_reachable'|'not_mounted'|'not_connected' } (a location not checked yet is left out), health: { doors: { inside: 'open'|'closed_<reason>', outside: 'open:<port>'|'closed_switch_off'|'closed_no_address'|'closed_no_cloud'|'closed_minimum_version'|'closed_bind_failed'|'closed_revoked'|'closed_not_enrolled'|'closed_no_certificate', refused_public, inside_bound: ['<address>:<port>'], relay_warning: { address, viewers }|null }, update: 'up_to_date'|'available:<v>'|'failed:<v>:<reason>'|'disabled', certificate: { kind, leaf_not_after, root_not_after, outside, expires_warning }, office_ranges_applied, office_ranges_refused, cloud, smb_dialect, minimum_version_ok, line }, root_cert_pem (after a start or a new root), next_root_cert_pem (when one exists), confirm: [{ clip, loc, path }] }`. `name` matters: GW1 answers `renamed` whenever the report's name differs from the row's. The ports are the ones bound.
4. **What GW1 drops today, and the one that matters:** `platform`, `inside_names`, `root_fingerprint`, `certificate.kind`, `office_ranges_refused` and `line` are dropped harmlessly. **`root_cert_pem` and `next_root_cert_pem` are dropped too**: when an inside address leaves the root's /24s the gateway makes a new root, and a year before the root's end it makes the next one, and sends the PEM at the next sync; GW1 keeps the enrolment's root, so Settings would keep showing and offering the old one. GW3 decides where a new root lands (a sync field `gateway_sync_apply` reads is the simplest).
5. **A viewing's fraction:** the gateway sends `fraction` and `read_in_full` from the distinct bytes it served (a scrub back and forth over the first minute stays a small fraction); `gateway_events_apply` drops them and recomputes `bytes / clip_bytes`, so re-reading the same part counts again and a long scrub can read as "in full". The design names the field without saying which (§6 takes only the viewing's facts from the payload, which favours GW1's); coverage is what *read in full* means to an admin. If GW1's rule stays, the gateway's two fields are dropped and nothing else changes.
6. **An empty file's viewing** carries `clip_bytes: 0`, which `gateway_events_apply` refuses as `malformed` (the row leaves the journal, rejected): harmless, said so nobody chases it.
7. The signing keys' ten minutes after a rotation are the cloud's (`previous_key_grace_seconds: 600` in GW1's vectors): the gateway accepts exactly the latest sync's `signing_keys`, so both keys must be in the answer during those ten minutes, as GW1 builds it.
8. The fingerprint: `root_fingerprint` is the SHA-256 of the root's DER, 64 lower-case hex characters; people see it as upper-case pairs with colons, as `openssl x509 -fingerprint -sha256` prints it. Compare after removing everything but hex (GW1 does).
9. The ticket vectors: the gateway's own (`gateway/test/vectors.json`) and GW1's (`gateway/test/gw1-vectors.json`, GW1's blob unchanged) both pass the verifier and both doors (`gw1Vectors.test.mjs`); nothing in the ticket itself differs.

## For GW4 (the release and the install stories)

- **The release keys:** `RELEASE_KEYS_WIRE` in `gateway/src/update/manifest.mjs`, two slots, EMPTY on purpose (with no key every manifest is refused and the health line says updates are off). Fill them with `{ kid, public_key }` (standard base64 of the raw 32 bytes); the private halves live in the release workflow's secret; `stable.json.sig` is standard base64 of the 64-byte Ed25519 signature over the exact bytes of `stable.json`. The compromise procedure is the design's (§10 row 14): sign with the second slot, set `hard_minimum_version`.
- **The channel:** `CHANNEL_URL` in the same file (`https://releases.petalstudios.com/wilson-gateway/stable.json`, D14's host is hers). The manifest's shape is §8's; `published_at` must grow, `version` must be newer, `artefacts.windows-x64.url` must be https.
- **The Windows artefact:** a gzipped POSIX ustar archive (`tar --format=ustar -czf`), regular files and directories only, laid out as `current\` is: `node.exe` and `app\` (`package.json`, `src\`, `updater\`). The updater (`gateway/updater/updater.mjs`) copies it into Program Files, verifies the signature and the hash again on that copy, extracts from memory, swaps (`gateway/src/update/swap.mjs`), waits 90 s for `ProgramData\WILSON Gateway\healthy` naming the new version, else reverts and writes `update-failed.json`.
- **The installed layout:** `Program Files\WILSON Gateway\` = `host\WilsonGatewayHost.exe` (ours, C# 5, built by csc.exe), `current\` (node.exe + app), `updater\` (its own node.exe + app; only the MSI replaces it), `wilson-gateway.cmd` (on PATH), and the updater's `previous\`, `staged\`, `failed\`, `staged.archive`, `swap.json`, `last-manifest.json`. State: `ProgramData\WILSON Gateway\` (config, credential, certs, journal, logs, pipe.key, shares.bin, updates\, healthy, status.json, update-failed.json).
- **The install's order** (the MSI's InstallExecuteSequence, read back by CI): install the services; check the state folder (`CheckState`: a real folder owned by SYSTEM, Administrators, TrustedInstaller or the gateway's service, its own ACL set, then nothing inside a link or another account's; a failure fails the install and the MSI log names the item, so the install story must say where the log is and to remove what it names); give the state folder and everything in it to Administrators (`SetStateOwner`, `icacls /setowner`); set its ACL to SYSTEM, Administrators and `NT SERVICE\WilsonGateway` (`SetStateAcl`); write a fresh `pipe.key` as SYSTEM (`FreshPipeKey`; a failure fails the install); write the enrolment file (`WriteEnrolFile`, hidden from the log); start the services; write the summary. A self-update keeps `pipe.key`; every MSI install or repair replaces it while the services are stopped.
- **A domain install:** the gateway contacts a share's server only after `share-login` for it, or when `config.json` lists it in `connect_without_login` (at most 16 server names, the `nas` of `\\nas\footage`). A domain whose computer account reads the share can use the second; the install story should say which.
- **ACME's hook points:** the outside door's certificate comes from `#outsideTls()` in `gateway/src/runtime.mjs` (the company's own PEM, else the gateway's leaf); TLS-ALPN-01 needs an `ALPNProtocols`/`SNICallback` on the outside door's server (`createDoorServer` in `gateway/src/doors/server.mjs`) and the challenge answered on it, which exists only while the switch is on (F15).
- **A local proxy in front of the outside door** (`outside.behind_local_proxy`): the gateway binds 127.0.0.1 and ::1, and a local non-administrator who takes that port first, or binds 127.0.0.1 beside a wildcard socket, receives the proxy's connections (review round 1, finding 4). The proxy must verify the gateway's certificate (pin its root), and the install story should say so. The outside door's per-peer caps then see the proxy as one peer (60 new connections a minute): the proxy must keep its connections alive.
- **Signing (D14):** the MSI, the host exe and the update artefact are unsigned; node.exe is the OpenJS Foundation's signed binary, pinned by the zip's SHA-256 (`gateway/windows/node.json`).
- **WiX:** pinned to 5.0.2 (MS-RL, before the Open Source Maintenance Fee). WiX 6 introduced the OSMF and WiX 7 enforces it (every command blocked until its EULA is accepted; organisations earning over US$10,000 a year sponsor the project): moving past 5 is a licence decision of Audrey's, not a version bump.
- **A self-updated install and the MSI:** after a self-update, `current\` holds files the MSI did not install; a later MSI (major upgrade) replaces them, and uninstall removes `previous\`, `staged\`, `failed\` and `rollback-tmp\` (RemoveFolderEx).
- **The container:** the base is `gcr.io/distroless/nodejs24-debian12:nonroot` by tag; pin it by digest in the release, and publish the image's digest in the manifest (`artefacts.container.digest`).

## 5. Traps hit

1. **The Bash tool halves doubled backslashes, even inside a quoted heredoc** (`'\\nas'` arrives as `'\nas'`). Every file holding a UNC path or a JS string with an escaped quote goes through the Write or Edit tools. It bit five times: a Python edit whose assertion stopped it before writing, a test title whose `\'` became a bare quote (the suite then failed to load and a narrow `grep` hid it: always look for "Test Files"), a `node -e` script, a hand-off draft, and a design line where Python read the halved `\n` as a newline.
2. **`npx vitest run` from `WILSON/gateway/` finds no files**: the root config's `include` is relative to `WILSON/`. And review round 1's reviewer ran its commands in the main checkout (`…/wilson/WILSON`), which has no gateway, and read "no test files" as a broken config: give a reviewer the worktree's path in so many words.
3. **CI: `npm ci` fails on Node 24** (npm 11 against a lockfile kept with npm 10) and a job's log needs admin rights to read, so failures are echoed as `::error::` annotations, which the public API serves: install with Node 22, test with Node 24. A failed tests job skips the jobs that need it (the MSI, the container): one flaky test hides two jobs' results.
4. **WiX on this PC**: no nuget.org feed configured (`gateway/nuget.config` adds it); `dotnet wix build -d` is swallowed by dotnet (use `-define`); Windows Installer's COM object refuses the wrapped string `Join-Path` returns (`DISP_E_TYPEMISMATCH`: cast with `[string]`); a `SetProperty` makes a custom action named `Set<Id>`.
5. **`netstat -ano` overflows Node's default buffer** (ENOBUFS: give it 64 MB), and lists unrelated connections whose LOCAL port happens to equal the one probed (an outbound 192.168.1.173:50290): filter for LISTENING.
6. **A 1 MB response fits in the socket buffers**: a test of the in-flight cut needs a large file (48 MB) to see the cut.
7. **Tests that depend on luck**: an Ed25519 signature's last byte is below 0x10, so setting its last two base64url characters to "AA" left a "forged" ticket unchanged one time in sixteen (CI's Ubuntu run caught it; flip a bit of the decoded signature); one random key in four has no `+` or `/` in its base64; one random credential in 64 starts with `x` (CI's Windows run caught "does not contain wgc_x").
8. **A body over the cap**: answer 413 only after draining up to 64 KB of it, or the client sees ECONNRESET instead of the status.
9. **The command's one-shot enrolment started a whole gateway** and bound this PC's LAN address for a moment during `config.test.mjs`, unannounced (`53eebf6d`: `enrolOnly` binds nothing, with a test that uses an address this computer does not have).
10. **Tests that pass for the wrong reason**: two TLS tests of the IP name constraint connected to 127.0.0.1 with leaves for other addresses, so they failed on the name check whatever the constraint said; a leaf must name the address connected to, beside a passing control.
11. **OpenSSL checks a dotted common name as a DNS name** when a leaf has no DNS entry (`cn2dnsid`): an IP-only leaf named "192.168.1.10" failed its own root's DNS constraint.
12. **Every sync answer starts a reach check**, which races a test that sets a location's state: the runtime keeps its checks in flight (`reachRuns`) for a test to wait on.
13. **Node runs the handler of every pipelined request at once** and queues only their answers, so a cap that closes a connection after N failures does not stop the requests already written behind it: refuse pipelining (no browser does it).
14. **Floors under limits broke the tests that exercise a limit in three requests**: floors belong to `config.json`'s validation (`resolveLimits(…, { floors: true })`), not to the limiter.
15. **GW1's enrol and sync answers carry no `workspace_id`**: "For GW3", item 1.
16. **`String.prototype.replace` with a string reads `$` patterns in it**: assembling this hand-off, `` IPC$` `` in the inserted text (`` $` `` is "the text before the match") printed §1 to §3 twice. Insert text with a function, `replace(x, () => text)`.
17. **A reviewer's experiments are this session's binds**: round 1's listened on 0.0.0.0 twice before being told; round 2's brief said loopback only, in so many words, and it bound nothing. A report sent back as a message can arrive cut: ask for it as a file written with the Write tool (and do not leave an empty file at that path, which the Write tool will refuse to overwrite unread).
