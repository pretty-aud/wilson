## 5. Traps hit

- ✅ **The dev Electron instance CAN be pointed at a scratch data folder.**
  `electron/main.cjs:31` honours `WILSON_USER_DATA` for unpackaged builds
  (added by the local-storage session on 2026-09-10). Launch:
  `$env:WILSON_USER_DATA = 'C:\Users\Audrey\AppData\Local\Temp\wilson-bins-ud'; $env:ELECTRON_OVERRIDE_DIST_PATH = 'C:\Users\Audrey\Documents\My_Work\Dev_Work\wilson\WILSON\node_modules\electron\dist'; Start-Process <that dist>\electron.exe -ArgumentList '"<worktree>\WILSON"'`
  after `npx vite build --mode development`. Audrey's real
  `%APPDATA%\WILSON\rabbit-data` was never touched (its newest file stayed
  dated 2026-09-07). Sessions 1 and 2's "writes to her real app data" trap is
  obsolete; the seeding script pattern (`scratchpad/seed.mjs`: POST projects,
  scenes, shots, bins, prepare, add — all with `sec-fetch-site: same-origin`)
  makes a test project in a minute.
- 🚨 **Keep the scratch data folder's path SHORT.** The first attempt used the
  session scratchpad (~220 characters); the poster cache path came to 268 and
  libvips's `toFile` failed with "unable to open for write" while Node's fs
  wrote the same path. `C:\Users\Audrey\AppData\Local\Temp\wilson-bins-ud`
  works. (The route now writes through Node, but ffmpeg's own writer has the
  same limit.)
- 🚨 **The dev Electron window pops up on Audrey's desktop and she tried to
  sign in to it** (it has no saved session and no remembered company, so the
  sign-in failed and she reported "login did not work"). Minimize it right
  after launch: `ShowWindowAsync(MainWindowHandle, 6)` via `Add-Type` on
  `user32.dll` — the server keeps running; and tell her in the first message
  that the window is yours.
- **The Electron main process does not hot reload** (session 2's trap,
  confirmed again): after a route change, `Stop-Process` the WILSON
  `electron.exe`, relaunch, read the new port
  (`Get-NetTCPConnection -State Listen -OwningProcess <pid>`), and write it
  into `dev-harness/vite.config.mjs` — Vite restarts itself on a config
  change; no `preview_stop` needed.
- **Run the review agents on a frozen tree, or tell them the tree moves.**
  Both reviewers noticed the working tree changing under them (the `d3c418f`
  edits landed mid-review) and re-checked; had they not, their line numbers
  would have been wrong. Commit before launching them next time.
- **The Browser pane's console buffer keeps errors from BEFORE a reload**, so
  a stale "X is not defined" from an intermediate HMR state shows up after
  the page is fine; compare the count of messages, or check
  `read_network_requests` for a current 500 instead.
- **`computer key` and `computer type` send REAL key events** (they reach a
  document-level `keydown` with focus on `<body>`), which is exactly what a
  test of a document-bound key handler needs; `computer left_click` with
  coordinates needs a prior `screenshot` in the same page, and screenshots
  sometimes time out while a `<video>` preview is mounted — `javascript_tool`
  clicks (`el.click()` on the tile's text node bubbles into React) and
  `find` / `get_page_text` are the reliable path, as session 2 said.
- **A synthetic OS drop is possible without the OS**: `new DataTransfer()`,
  `dt.items.add(new File(...))` with `file.__path` set (the harness stub's
  `getPathForFile` reads it), then `dispatchEvent(new DragEvent('drop', {
  dataTransfer: dt, bubbles: true, cancelable: true }))` on any element.
- **The undo toast is App-level** (`UndoToast` in App.jsx), not mounted by the
  harness — "Removed …" never appears there; verify the removal by the footer
  count and the network instead.
- GitHub connectivity: no retry was needed this session; keep the loops.
