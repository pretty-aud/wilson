## 3. Done and verified

1. **The measurement the whole design rests on, and the brief was wrong about
   it.** The brief said to measure the renderer's origin in packaged AND dev
   modes "because they differ". **They do not.** `main.cjs` does
   `mainWindow.loadURL('http://127.0.0.1:' + port)` with no `app.isPackaged`
   branch — it is the only `loadURL`/`loadFile` in `electron/` — and
   `electron:dev` is `vite build --mode development && electron .`, which
   builds to `dist/` and loads the same way. Vite's dev server (:5203) is the
   WEB path and has no Express server at all. So **the renderer is served BY the
   server it calls**, every renderer request is same-origin, and there is
   exactly one allowed origin, computed at listen time. That simplified the
   design rather than complicating it.

2. **Second measurement, taken in Chromium BEFORE writing any code** (a
   throwaway probe server + the browser pane): an httpOnly cookie **is** sent on
   a same-origin `fetch()`, on `fetch(mode:'cors')`, on a plain `<img>`, on
   `<img crossOrigin="anonymous">`, on `<video crossOrigin="anonymous">` and on
   the document. 🚨 And `<img crossOrigin="anonymous">` is the **one** element
   shape that sends an `Origin` header. That detail is load-bearing: the entity
   thumbnails in ScenesView / ProjectAssetsView / LevelsView / ExperiencesView
   are exactly that shape, so a `cors()` allowlist that refused the renderer's
   own origin would have broken them **with every test still green**.

3. **The lock** (`1531210`, `electron/localToken.cjs`): 32 random bytes per
   launch, never written to disk; ONE middleware ahead of every route and
   **before `express.json`** (so an unauthenticated caller cannot make main
   buffer 50 MB before being refused); header **or** httpOnly cookie;
   constant-time compare; **bare 401 with no body** (saying "missing" vs "wrong"
   tells a prober which half it got right). `cors()` narrowed from `*` to the
   renderer's own origin with `credentials: true`.
   **Deliberately unguarded: the static bundle and the SPA fallback.** They
   serve `dist/` — our own built code, byte-identical everywhere and already in
   the installer on disk — and guarding them would turn a failed `cookies.set()`
   into a white window instead of a degraded feature. A local process that
   loads the shell gets a UI whose every call answers 401.

4. **The renderer** (`src/lib/localServerFetch.js`): `localFetch` = fetch + the
   header, attached **only** when the URL is same-origin. 🚨 That condition is
   the load-bearing half — `otterFetch` falls through to raw `fetch` for
   anything it does not recognise and `fetchImpl` is injected from outside in
   two more places, so an unconditional helper would post the launch secret to
   whatever host a widened call site named. Grep-proven list of 22 calls across
   11 files is in `1531210`'s message. Browser-safe: no `electronAPI` on the web
   or under vitest, so `localFetch` is exactly `fetch` there.

5. **Single instance**: `app.requestSingleInstanceLock()` **after** the Squirrel
   guard (an installer run is a legitimate second process); `second-instance`
   restores, shows and focuses the existing window; checked again at
   `whenReady` because `app.quit()` only STARTS the shutdown.
   MEASURED: `setAsDefaultProtocolClient` appears nowhere and neither packager
   registers a scheme, so there is no deep link to forward yet.

6. **Review round R1 (`e1966cc`) — the finding of the session.** Two **complete
   authentication bypasses**, in code I had committed an hour earlier and that
   19 green harness checks had blessed:
   - **`GET /API/RABBIT/PROJECTS`** — Express's router is case-**insensitive**
     by default, so it matched the route and returned the project list while a
     case-sensitive `startsWith('/api/')` said "not an /api path".
   - **`GET http://127.0.0.1:<port>/api/... HTTP/1.1`** — the absolute-form
     request target (RFC 9112 §3.2.2), which Node accepts and puts in `req.url`
     **whole**, so the prefix test missed it and the router did not.

   🚨 **Neither is visible through `fetch()`**, which normalises the request
   target before it leaves the process — which is why every check passed
   against a guard that was wide open. They were found by re-probing over a
   **raw socket**. The fix is the invariant, not the two cases: the guard must
   match what Express *routes*. `isGuardedPath` now lower-cases and collapses
   repeated slashes (safe direction — guarding case-insensitively guards a
   superset, so enabling `caseSensitive` later cannot open a hole), and
   `requestPathCandidates` returns every reading Express might route on, with
   the guard refusing if **any** is an `/api` path. Nine raw-socket probes are
   now permanent harness checks, asserting on the response **body** (did the
   project list come back), not the status.

## 5. Traps hit

1. 🚨 **`fetch()` cannot test a request-target bypass.** It normalises before
   sending, so a harness built on it is blind to case, absolute-form and
   several slash shapes. **Use a raw socket to test anything that guards on a
   path.** This cost two HIGH bugs that 19 green checks had approved.
2. 🚨 **Express's router is case-insensitive by default.** Any prefix guard
   written against it must lower-case, or it guards a different set of URLs
   from the one the router serves.
3. 🚨 **`npm install --ignore-scripts` (which the protocol mandates) skips
   Electron's postinstall, so `node_modules/electron` has NO BINARY** and
   `npx electron .` dies with *"Electron failed to install correctly"*. Do not
   re-run the install: the canonical checkout has the same version (33.4.11),
   and `<canonical>/node_modules/electron/dist/electron.exe <worktree>/WILSON`
   runs the worktree's code with it.
4. 🚨 **Running the app against Audrey's real profile puts her live session on
   screen.** The first launch booted straight into an MFA enrolment screen with
   a **live TOTP secret and QR code**. The screenshot was deleted unsent and
   nothing was clicked. For anything that needs to write, seed a throwaway
   `--user-data-dir` instead — Electron honours it and `app.getPath('userData')`
   follows.
5. **Drive the app with CDP, not screenshots.** `--remote-debugging-port` +
   `/json/list` + a WebSocket gives `Runtime.evaluate` in the real renderer,
   which is how every measurement in §3.7 was taken.
   ⚠️ `Page.captureScreenshot` **hung twice** on the scratch profile (the
   compositor produces no frames when the window is not visible);
   `Runtime.evaluate` reading `document.body.innerText` worked every time.
6. 🚨 **`process.exit()` while Node's global `fetch` still holds keep-alive
   sockets aborts libuv on Windows** — `Assertion failed: !(handle->flags &
   UV_HANDLE_CLOSING)`, exit code **127**. A fully green harness reported
   failure to CI. Use `server.closeAllConnections()` and `process.exitCode`.
7. 🚨 **Piping a build to `tail` hides its exit code.** `npm run build:dev |
   tail` reported exit 0 over an esbuild failure; the broken file was only
   found because `dist/assets` was missing. Redirect to a file and check `$?`.
8. **Do not insert an import after "the last line starting with `import`"** —
   in `Otter.jsx` that line was the FIRST line of a multi-line
   `import { … } from` and the insertion split it. Cheap to fix, easy to miss,
   and it is what caused trap 7's build failure.
9. **A quoted heredoc still ate `\r\n`** when writing JS through Python: the
   escapes arrived as real CRLF and the file would not parse. The protocol
   already says to write files with the Write tool; this is why.
10. **`/tmp` in the Bash tool is not a path Node can `require`.** Use the
    session scratchpad with a Windows-shaped path.
11. **The GitHub API refused connections twice** (`Failed to connect to
    api.github.com port 443`) and worked on retry. Not a permissions problem.
12. **A red CI run is not necessarily yours.** `98a5cda` failed only on pgTAP's
    *Install Supabase CLI* step — `rate limit exceeded` from
    `supabase/setup-cli` — while Vitest, Playwright and the smoke passed in the
    same run. Read the JOB list and the annotations before assuming.
13. **The classifier refused `git push` once** when it was chained after
    `git log` in one command; the bare `git push origin track-b-auth` was
    allowed. Per-command, as the protocol says.
14. 🚨 **A quoted heredoc ate escape sequences THREE times** — `\r\n` writing a
    JS template, `\n` writing a test's URL fixtures, and a whole edit script
    that would not parse. The escapes arrive as real control characters and the
    file is broken in a way that only shows at parse time. The protocol already
    says to write files with the Write tool; this is the proof, three times
    over. Use Write or Edit for anything containing a backslash.
15. **Do not find/replace an identifier across a large file without reading the

16. 🚨 **Both review rounds found real bugs in code that was already green** —
