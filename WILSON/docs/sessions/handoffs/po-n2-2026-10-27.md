## 5. Traps hit

- **A definer that LISTS needs the same workspace predicate as the one that GATES.** The
  first draft put the cross-tenant belt in the consent helper and forgot the index function,
  which would have listed a forged row's live title to another workspace; round 1's HIGH.
  Every SECURITY DEFINER that returns rows now carries `sub.workspace_id = s.workspace_id`.
- **A pgTAP suite is one transaction.** A GUC set with `set_config(…, true)` lasts to the
  end of the file, so a probe that arms a GUC must reset it, and an "unarmed" probe must assert
  the GUC reads empty first. The forged cross-workspace row is made with the guard trigger
  disabled by the runner instead of by arming.
- **`anon` is 42501, never 0 rows.** 0033 revoked every table privilege from `anon`; a probe
  written as a count aborts the file. The matrix's anon column is `throws_ok` and the
  privilege functions.
- **No wire carries a subject's id.** `subject.list` and `subject.get` map slug, title and
  the list columns only; a client that must call a function by subject id has nothing to pass.
  B1 adds `id` to both wires (and the fixtures') before B2 can share anything.
- **A migration string must not hold a dash pair.** The post-condition that strips comments
  before counting a function's arms builds its regex from `chr(45)` and `chr(10)`, so the file
  carries no `--` inside a string literal that a by-hand apply recipe could misread.
- **The Edit tool matches whole strings.** One missing "a" in a 40-line replacement failed
  it silently-looking (the error was clear); re-read the exact lines (`cat -A`) before a
  long Edit.
- **The settled-share leak.** 0065's SELECT policy admits both parties for ever, so an index
  that joins the live subject hands an ex-receiver every later rename. Snapshots at share time
  (0045's precedent) are the fix; anything a settled row shows must come from the row.
- **An editor grant is a read grant.** Round 1 asked for a probe that a granted editor cannot
  share, and the fix gave the suite's third person the grant, which opened the owner's whole
  course to them and made eight "reads 0" cells false. A fixture user who exists for one probe
  gets that probe and nothing else.
- **A component that is never unmounted is a session cache.** The Validator is rendered
  hidden for the whole session and keeps bodies in `subjectCacheRef`; "read it live" cannot be
  promised there. The honest answer was to keep linked subjects out of it in 1.0.
