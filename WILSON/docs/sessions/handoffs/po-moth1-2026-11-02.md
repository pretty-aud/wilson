## 5. Traps hit

- 🚨 **A fresh worktree on her PC is CRLF** (`core.autocrlf` is true; blobs are LF). A patch script's line-ending patterns miss, and a rehearsal built from the working tree carries carriage returns into function bodies. Normalise a file to LF before patching or rehearsing it, or build from the blob (`build_house.py`). Git stores LF either way, so the diff stays clean.
- **Git Bash rewrites `ref:path` into a Windows path.** `export MSYS_NO_PATHCONV=1` before `git show <ref>:<path>` or `git cat-file`.
- **A fresh worktree holds an untracked `.claude/launch.json` from the app**, which stops the checkout. It is an older copy of the tracked one; keep a copy in the scratchpad and remove it.
- **A foreign key answers past RLS**, so any refusal it gives a client can say a hidden row exists. The guard answers first, with one sentence, whatever the row holds (the review round of 0112 and 0113).
- **A row with a retained setting:** `workspace_storage.provider` is remembered after a company goes back to Petal, and only `mode = 'byos'` makes it active. Read both.
- 🚨 **A helper that runs once per row must be plpgsql, and a gate must run after the sort.** On dev a page of 500 files took 3.4 s: an `ORDER BY … LIMIT` over a filter with a function in it ran the function over the whole project before sorting, and SQL-language helpers cost more per call. The fix is a fenced subquery (`ORDER BY … OFFSET 0`) with the gate outside it: 475 ms. Timing changes no answer, so no probe sees it; a post-condition pins the fence.
- 🚨 **A row-image helper must read only its arguments**: an AFTER DELETE trigger can no longer read the row it was given (0111's review, the major finding).
- 🚨 **A guarded DELETE must `RETURN OLD`.** `RETURN NEW` in a BEFORE DELETE trigger returns NULL and silently skips the delete; suite 113 pins "and it is gone". And `pg_trigger_depth() = 1` tells a client's delete from a foreign key's cascade.
- **A composite key can make a suite's fixture impossible**: suite 113 drops 0113's key inside its own transaction for its two foreign-folder rows (suite 110 has the precedent of dropping a trigger).
- **The fixtures may import only what `devFixtures.test.js` allows**, each proven to import nothing; a new module means a new line and a proof.
- **The Bash tool ate backslash sequences three more times** in inline Python: patch scripts go through the Write tool, always.
- **Context:** the read-only start (the design's §0 to §1.16 and the plan) took 20%; building 0111 and 0113 with one review round reached 61%. Read less of the design: §1.4's entry for your migration and the §2 lines it names.
- 🚨 **A Windows path in a doc broke the web build** (Tailwind v4 decodes a backslash and hex digits as a CSS escape). Never write a backslash path into a tracked file.
- 🚨 **A probe that names its row by id is judged by the SELECT policies too**; only a blanket write reaches USING alone.
- 🚨 **BEFORE triggers run before RLS**: a definer guard judges only rows the caller can see.
- 🚨 **A statement-level AFTER DELETE trigger fires BEFORE the cascade's child rows are captured** (0108).
- 🚨 **`created_at` is the transaction's start, not the write's order**: one entity's history is ordered by id.
- 🚨 **Suites 94, 99 and 101 count each quoted table name in `fn_realtime_broadcast` exactly once** (comments stripped): a restatement that names a table twice (a second CASE, a literal `'projects'` in a payload) fails all three. Resolve both sides in one CASE.
