## 5. Traps hit

- 🚨 **A Windows path in a doc broke the web build** (Tailwind v4 decodes a backslash and hex digits as a CSS escape). Never write a backslash path into a tracked file.
- 🚨 **A probe that names its row by id is judged by the SELECT policies too**; only a blanket write reaches USING alone.
- 🚨 **BEFORE triggers run before RLS**: a definer guard judges only rows the caller can see.
- 🚨 **A statement-level AFTER DELETE trigger fires BEFORE the cascade's child rows are captured**: the RI cascade runs with the children's triggers queued behind the parent's (measured: the parent's delete row is written first, the children's after the statement trigger). 0108's purge trigger therefore pairs with a "project no longer exists" check in the capture and the snapshot.
- 🚨 **`created_at` is the transaction's start, not the write's order**: one entity's history is ordered by id.
- **`projects.id` and `files.id` are the client's to send**: anything keyed by a past project or file id must survive the id being created again.
- **The files snapshot trigger re-stamps a crafted INSERT**: to simulate 0088's backfill in a test, write the crafted row, then UPDATE its project (no trigger sees an UPDATE).
- **`supabase db reset` drops pgtap** (`supabase test db` installs it only for its own run): a hand-run suite needs `CREATE EXTENSION IF NOT EXISTS pgtap SCHEMA extensions` first.
- **A cloud worker restart kills the Docker daemon** (and the local stack with it): check `docker ps` before trusting a running workflow that uses the database.
- A later migration that restates a policy breaks every earlier suite that pins its whole text: run the whole set before committing.
- Scripts with backslashes go through the Write tool; the Bash tool ignores `set -e`.
- Cost: review round 1 (12 agents) and round 2 (fewer) ran as workflows; building in the main loop is cheap by comparison.
