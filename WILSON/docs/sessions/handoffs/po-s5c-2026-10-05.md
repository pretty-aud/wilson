## 5. Traps hit

1. **The app's untracked `.claude/launch.json` blocked the checkout again**
   (part 1's trap 1, S5b's trap 1): moved to the scratchpad, not deleted.
2. **The Budget page binds no Ctrl+Z for the provider's history.** Its only
   undo keys are the Expenses tab's, and they are the EXPENSES hook's own
   history; the Timeline (which binds the provider's) is not mounted beside
   it — R.A.B.B.I.T. mounts one view at a time. Every "Undo (Ctrl+Z)" a
   Budget question promised was false. And a Ctrl+Z added to the Summary
   would be a trap: the waterfall's margin / contingency / agency edits go
   through `ctx.updateProject`, which records no undo step, so Ctrl+Z after
   typing a margin would take back the last VERSION step instead. The steps
   raise the undo toast instead (`ctx.runWithUndoToast`), and no sentence
   says "Ctrl+Z" (Audrey's question 4).
3. **A rate hook's "not loading" is not "read".** `useRateCard` is
   `loading: false` on its first render (before any read starts) and again
   for a render between its two reads (cards, then entries);
   `useProjectRateOverrides` holds the list from before an open wrote a
   version's rates until its reload lands. "Unsaved changes" read off those
   rates is false, and a Save then would write empty or stale rates into
   the bid. `settled` and `loadedEpoch` say "read"; `ratesPendingFrom`
   joins them.
4. **The undo toast holds ONE line and cuts the rest** (480px, truncate):
   put what a step did first and the long version name last.
5. **A plant that removes a redundant layer cannot be caught by behaviour**
   (S5b's trap 5, again): VersionFlow's `first` (the unsaved question frozen
   at the asking) — the provider's `bundleRef` trails a render by an effect,
   and a Save's last write lands in one batch with the next question, so no
   render ever shows the question re-read empty. Recorded, not probed.
6. **CI has no `.env.local`.** A test whose module graph reaches
   `supabaseClient.js` passes locally and fails in CI ("supabaseUrl is
   required") unless it stubs the client — run 37337162905. Run new test
   files once with `.env.local` moved aside before pushing.
7. **`getByText` in Playwright also finds the kit Button's live region**:
   the attention state's region says "“X” has unsaved changes", so
   `getByText('Unsaved changes')` matched two elements (a strict-mode
   refusal that reads as "not found"). Target `.rb-bv-open-status`.
8. **The desktop's "signed-out" Local Server is the DEVELOPMENT build in
   tester mode**: a production build always shows the login; `vite build
   --mode development` alone still builds with NODE_ENV=production (so
   `import.meta.env.DEV` is false and tester mode never runs). It took
   `NODE_ENV=development VITE_DEV_FIXTURES= VITE_DEV_AUTOLOGIN=tester npx
   vite build --mode development`, then `electron.exe` (the main checkout's;
   the worktree's install skips the binary) on this worktree's app. Pages
   switch inside the app (a direct `/rabbit` load lands on Home), and a
   Home entry's click is intercepted (the pet's layer): fire the entry's own
   `click()`.
9. **`sed -i` in Git Bash rewrote a CRLF file as LF** (CrewTeamTab,
   TalentTab): harmless — git normalises to LF in the index and the diff
   showed only the real lines — but a plant written for CRLF would then
   miss. Measure line ends with Node, not `grep $'\r'` (which said "LF" for
   a CRLF file here).
10. **A fixture-paced test cannot see a network-paced state**: every await
    in the fixtures resolves before React renders. To see "the question
    stays, busy, while its Save is in flight", the test holds the adapter's
    request on a gate it releases.
11. **React flushes a two-render glitch inside one `act`**: the list choice
    of the previous open version, shown for one render after another
    version opens, cannot be seen by a jsdom test (both renders flush
    together). Fixed by holding the choice per open version (`{ openId,
    value }`) and recorded as checked by trace, not by a test. (Round 2
    then found the choice came back with its version — R2-04 — and the fix
    became a reset during render, which a test does see.)
12. **The fixtures soft-delete; the Local Server does not.** A proof of "a
    step stopped part way" on the fixtures adapter (`restoreTask`: the bulk
    delete is all-or-nothing) cannot see the Local Server's loss (its
    DELETE removes the row, and it has no `restore*`): R1-01's proof passed
    while R2-01 stood. Stage the Local Server's shape (delete the adapter's
    `restoreTask` / `restorePhase`, splice in `deleteTask`) for any step
    that can stop part way.
13. **The undo queue's wait is an escape hatch, not a lock** (R2-03): after
    `HISTORY_STEP_WAIT_MS` the next step runs beside a stalled replay, whose
    `suspended` drops every step that step records. Anything that must not
    interleave with a replay checks `suspended` itself (`refuseWhileReplaying`).
14. **"The top of the stack at the asking" is not "this step's entry"** when
    the step waits in the queue: an undo, a redo or another step may run
    first. Measure from a marker queued just before the step, or count the
    composite's own batch (`landedSince`).
15. **A provider-wide epoch is not per project** (R2-02): hook state read
    "at an epoch" must also be keyed by the project, and reset in the
    render the project changes — the Budget stays mounted across a switch.
