## 4. D1b's dialog case, and why it is closed without `inert`

D1b asked for `inert` on the dialog's siblings **or** a focus trap. F3 landed
the trap for C2's KR-5. F4's job was to find out whether that actually closes
D1b's case, because an R1 fix in this repo has been an inert guard before.

Two independent reproductions, both with controls:

**In jsdom** (`src/ui/dialogTrap.test.jsx`). 🚨 jsdom has no tab navigation:
six `fireEvent.keyDown(el, { key: 'Tab' })` calls followed by "focus is still
inside" **passes with no trap at all**. So the test simulates what a browser
does — dispatch the keydown, and if the handler did not `preventDefault`, move
focus to the previous focusable in document order. Verified by neutralising the
trap's `preventDefault`: focus escapes on the FIRST Shift+Tab.

**In a real browser** (Playwright, both window sizes, Admin Terminal's
`Invite by email` over 26 live controls):

| | Shift+Tab escapes | Tab escapes |
|---|---|---|
| trap suppressed | **8 of 8** | 7 of 8 |
| trap live | **0 of 8** | 0 of 8 |

The suppressed run is not a rebuild: a capture-phase listener on `window` calls
`stopImmediatePropagation` for Tab, which keeps the handler from running
without cancelling the browser's default action. The escape trail is
`Deactivated → Active → All → Search members → Add people → Diagnostics →
Logs → Requests`, all behind the backdrop.

"Unreachable" is three routes and the trap is one. The other two were already
closed and are now asserted rather than assumed: the backdrop is
`position: fixed; inset: 0` with the dialog inside it (pointer), and
`role="dialog" aria-modal="true"` (assistive technology). That is why `inert`
is not needed, and Q17's ruling stands.

⚠️ **The case D1b measured cannot be reproduced on Settings in a browser.** The
storage-backend controls are `disabled` outside the desktop app, so
`focusableWithin` skips them and there is nothing to escape onto. D1b measured
it with a faked `window.electronAPI`. Admin Terminal has the same shape with
live controls, so that is where the browser measurement was taken; the jsdom
test carries D1b's exact geometry, switch included.

## 4b. Why the `xs` IconButton was built and then withdrawn

C3b filed request 3 because a remove control inside a `.ui-badge` grows the
row: the badge is 20px, the smallest icon button 28. F4 added an `xs` at
16px with a 10px glyph — the numbers `.at-dept-remove` already declares —
and review round one took it back out. Three things, in order of weight:

1. 🚨 **The defect is not what C3b thought, and it is still on screen.**
   Measured in the running app, Admin Terminal → Company: the remove button
   is **28x28 with a 14px glyph inside a 20px chip**. `.at-dept-remove` is
   `(0,1,0)` and `.ui-iconbtn[data-size="sm"]` is `(0,2,0)`, both in the
   `components` layer with no `!important` anywhere — so the private box
   C3b wrote, and which its hand-off describes as the page "giving it its
   own box", **never took effect**. The row grows today.
2. 🚨 **Shrinking it is a trade, not a fix.** 28x28 clears the 24px minimum
   target size; 16x16 does not, and a 20px chip leaves no room for the
   spacing exemption. So the choice is 4px of chip height against an
   accessibility floor. That is Audrey's ruling to make, not the kit's.
3. **It had no caller.** `CompanySection.jsx` belongs to the live Admin
   lane, so F4 could not adopt it — and shipping a size nothing uses is the
   rule this project has paid for ten times. It is also the rule F4 applied
   to `OtpInput` and `CellSelect` three rows up its own table.

**What is owed.** A ruling, then a one-session fix. The options, with costs:

| option | chip height | target size | who |
|---|---|---|---|
| leave it | grows 8px | 28, passes | nobody |
| `xs` at 16/10 (F4 built this; it is in `1ea3096`'s parent) | 20, exact | 16, **fails** | kit + Admin lane |
| `Badge` grows to 24 when it hosts a control | 24 | 24, passes | kit, and a §4 contract change |

The third is the only one that costs nothing measurable, and it is the one
that needs a plan edit. `IconButton.jsx` carries this note in its header so

## 5. Traps hit

1. 🚨 **Three launch entries in `Claude_Work/.claude/launch.json` share port
   5203** (`wilson-dev`, `wilson-ui-review`, `wilson-f1`), each pointing at a
   different checkout. C3b's trap 1, still true. F4 added `wilson-f4` on
   **5231** with `--strictPort`. **Confirm by CONTENT, not by path**: fetch
   `/src/index.css` from the server and grep it for a string only your worktree
   has. ⚠️ Vite serves CSS as a JS module in dev, so the selectors come back
   **escaped** — `ui-tr[data-selected=\"true\"]`, not `="true"`. A grep for the
   unescaped form returns 0 and looks like the wrong checkout.
2. ⚠️ **There are TWO page-local `.ui-tabs` nowrap scopes, not three.** The
   brief said three. Measured: `.at-section .ui-toolbar .ui-tabs`
   (`adminTerminal.css:168`) and `.rs-page .ui-toolbar .ui-tabs`
   (`resources.css:123`). C1 and C2 share `resources.css`, so their "two
   copies" are one rule.
3. 🚨 **node's `/tmp` on Windows is `C:\tmp`; Git Bash's is not.** A backup
   written with `fs.writeFileSync('/tmp/x.bak')` and restored with `cp
   /tmp/x.bak` silently fails — the `cp` cannot find the file and the edit
   stays reverted. Use git to restore a control, or relative paths inside node.
   (A bash heredoc to `/tmp` then `node /tmp/x.mjs` DOES work: MSYS converts
   the argument, but not paths inside the script.)
4. 🚨 **C3b's trap 3 again: `git checkout -- <file>` took uncommitted work
   with it.** Reverting a control on `src/index.css` reverted the unrelated,
   uncommitted fix in the same file. Make controls from a committed state, or
   restore by re-running the patch script.
5. 🚨 **The repo has MIXED line endings** (`core.autocrlf=true`, no
   `.gitattributes`). `src/index.css` is LF in the working tree;
   `adminTerminalCss.test.js` is CRLF. A node script anchoring on a multi-line
   string must detect the file's own newline or the anchor silently will not
   match.
6. ⚠️ **A `.ui-*[data-*]` selector inside a regex literal in a test is a
   CHARACTER CLASS.** Two pinned assertions were rewritten by a careless
   `perl -pi` that ate the escaping, turning `\.ui-tr\[data-selected\]` into
   `\.ui-tr[data-selected]` — which matches a single character and passes
   almost anything. Both were caught and re-escaped; a scan for the shape is
   worth running after any bulk edit of test files.
7. ⚠️ **Admin Terminal's seven sections are all mounted**, toggled by
   `display`, deliberately (C3b). A Playwright `.locator('.ui-toolbar')` picks
   a hidden one and times out on screenshot. Use `:visible`.
8. ⚠️ **`Add people` opens a MENU, not a dialog.** A probe that clicks buttons
   and looks for `.ui-dialog` finds nothing on the Users roster; the menu item
   is the thing that opens one.
9. ⚠️ **Node cannot resolve `@playwright/test` from the scratchpad**
   (dev-fixtures trap 8, confirmed). Put the script inside the worktree —
   `WILSON/.claude/` is gitignored and works.
10. ⚠️ **A column width set with `element.style.width` does not stick** on the
    kit `Table`: the widths are percentages the component sets and React puts
    them back. To make a header clip, narrow the SCROLLER
    (`table.parentElement.style.maxWidth`), which is the geometry a narrow
    window gives anyway.
11. 🚨 **`git checkout -- <file>` also flips the file to CRLF** under
    `core.autocrlf=true`. `src/index.css` was LF in the working tree; after
    one control that restored it, it was 2249 CRLF lines. Any later script
    anchoring on a multi-line string must detect the newline from the file
    rather than assume — this bit three separate edits in this session.
12. 🚨 **A bulk re-key that matches `.ui-<class>[data-<attr>]` is blind to
    two shapes**: an attribute that is not first
    (`.ui-tab[data-surface="light"][data-active]`) and one inside `:not()`
    (`.ui-card:not([data-pad])`). Both survived F4's sed AND the guard F4
    wrote to prove the sed was complete. Scan RULE HEADS, not
    class-plus-attribute.
13. ⚠️ **A specificity assertion over two string literals cannot fail.**
    `expect(units('.a .b')).toBeGreaterThan(units('.b'))` is `2 > 1`. Both
    selectors must be read out of the stylesheet — F3 already knew this and
    wrote it in `Toolbar.test.jsx`; F4 wrote three fresh ones that did not,
    in a commit whose message claimed they did.
14. ⚠️ **A page's private override may be losing the cascade.** `.at-dept-
    remove` (0,1,0) has never beaten `.ui-iconbtn[data-size="sm"]` (0,2,0).
    Before treating a page-local box as "the page handles it", measure it.
15. 📌 **An inline box reports `clientWidth === 0`**, so "is this label
    clipped?" cannot even be asked before the fix. That is itself the cleanest
    statement of the `.ui-th-label` defect.
