## 5. Traps hit

- **A data-modifying CTE's SELECT does not see an AFTER trigger's effect in the same statement.** `fn_projects_auto_staff` looked inert (the producer not seated); a separate SELECT after the INSERT showed the seat. Measure a trigger with its own statement.
- **The rate_cards and task_templates policies ask their workspace test before NOT NULL:** a row without `workspace_id` (or with the desktop's seed id) answers **42501**, not the 23502 the brief expected. The fake refuses the same way.
- **`supabase db query --linked --file` prints only the last statement that returns rows, and a failing statement ends the file:** one probe per file, each with its own `BEGIN … ROLLBACK`; another session's CLI login can race it (`28P01 failed SASL auth cli_login_postgres` once — re-run alone).
- **`git archive <sha> WILSON` must run from the repository root** (the worktree root), not from `WILSON/` ("pathspec 'WILSON' did not match").
- **Git Bash's `grep -c $'\r'` prints 0 on a CRLF file;** count carriage returns with `tr -cd '\r' | wc -c`. Every doc and most source files here are CRLF (the runner's CR count equals its line count), so the Edit tool and `sed -i` are unsafe on them all, not only on the docs: every edit went through an anchored, ending-preserving helper (each anchor exactly once).
- **tus-js-client 4.3.1's `fileReader` option replaces the default reader whole:** passing `fileReader: undefined` breaks a plain Blob upload. The key is set only when the body offers `openSource`; a Blob keeps tus's own reader.
- **`node_modules` counts 746 right after `npm install --ignore-scripts` and 748 after a vitest run** (vitest's two cache directories): the brief's 748 is the after-test count.
- **A fake must emulate every trigger the measured table has, or a dry-run/real-run parity test passes for the wrong reason:** the fake had no `fn_projects_auto_staff`, so the roster's `inserted` agreed between dry and real only because neither seated the mover (round 1). It seats the mover and a member producer on the project's insert, and the new producer on UPDATE OF `producer_id` (round 2), as the trigger does.
- **A record that guards against resurrection must be written at the insert, not only by the later repair step:** `people_set` was recorded by `setPeopleOnEarlierRows` alone, so a row that arrived with its person had no key and a teammate's clearing between two runs was overruled (round 1, HIGH). The project's, a task's and a line's people are recorded as they land.
- **`recordedKinds` is the one list the record's "removed" gate reads from:** a kind recorded under a table's name (the managed files under `files`) must be listed under it there too, else its rows read as "there" and a teammate's removal is called skipped (round 1, MEDIUM).
- **A correction that skips a step must keep the step's check:** round 1's `from === to` branch of `moveReceipt` skipped the move and, with it, the existence check, so a row over a gated path with no body anywhere was flagged money (round 2). Count at the write, not at the shaping, too: `ROLES_LEFT` counted at the shaping said "1 seat given as member" on runs that gave none.
- **A control's title must name its round** when the controls are to be run alone (`-t "review round 1"` selects by title); the surer proof is the swap: HEAD's file written over the working copy, the suite run, the copy restored and its hash compared.
- **A review round's agent can touch the working tree:** `git status`, HEAD and `ls -A node_modules | wc -l` were asserted before and after each round (clean, as committed, 748).
