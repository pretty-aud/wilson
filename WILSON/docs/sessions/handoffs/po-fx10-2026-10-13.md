## 5. Traps hit

1. **Her screenshot is Firefox's, not the desktop app's.** Gecko draws a
   date `09 / 26 / 2026` (spaced slashes, about 8px wider than Chromium's
   `09/26/2026`) and ALWAYS draws its calendar button — no
   `::-webkit-calendar-picker-indicator` rule reaches it, so the tables'
   "glyph only on hover" rules never applied there. In the 112px fields it
   cut 9.5px of a set date and 13px of `mm / dd / yyyy`, in every row, at
   rest. Chromium / Electron held a set date (5px from the glyph) and cut
   the empty pattern by 1.3px only while the glyph showed.
2. **The installed Firefox can be driven without a download**, over
   WebDriver BiDi: `firefox.exe -headless -no-remote -profile <tmp>
   --remote-debugging-port N`, then `ws://127.0.0.1:N/session` (Node 24's
   global WebSocket); `browsingContext.getTree`'s first context needs system
   access, so create a tab (`browsingContext.create`); DRAIN its stdout (a
   full pipe blocks Firefox before it listens); set
   `MOZ_CRASHREPORTER_DISABLE=1` (a killed instance otherwise leaves a
   `crashreporter.exe` per run). Page script cannot see Gecko's date parts:
   read its `max-content` (exact, per value) and scan the field's picture.
   Audrey's own Firefox runs on this machine: touch only processes whose
   command line names your throwaway profile.
3. **Chromium's own width for a date field is not the date's.** About 25px
   wider than its 80.9px whatever the value, and it moves with the engine
   and the screen (a 6px borderless field: 133px at 1x and 139 at 2x in
   Chromium 147's emulation, 131 to 133 in Electron 33); no CSS on the
   inner parts changes it, and `flex: none` on `::-webkit-datetime-edit`
   cannot pull the indicator next to the date (its reserved width is
   internal). So `min-width: max-content` is not a floor a fixed column can
   hold; the floor is a token.
4. **Playwright's Chromium is a headless shell** (measured at DPR 2 in the
   script); `channel: 'chromium'` fails to spawn here ("spawn UNKNOWN").
   Electron 33 (Chromium 130) is the desktop engine: `npm install
   --ignore-scripts` skips its download, so the binary is the main
   checkout's (`--electron`); a hidden window paints no frames (every
   screenshot times out) — `webPreferences.offscreen: true` does.
5. **Vite reloads every open page on ANY change under WILSON/** — a test
   file, a script, a doc counted. Two before runs lost their page mid-walk
   ("window.__fx10 is undefined"). Edit nothing under WILSON/ while a
   measurement or a reviewer runs; prepare changes in the scratchpad (this
   session wrote them as apply scripts, dry-run on copies first).
6. **Firefox draws no calendar button on a disabled field** (the Holidays
   field while R.A.B.B.I.T.'s settings are locked, as they open), and the
   pet companion's sprite floats over the
   Bins inspector's Shoot day: both fooled the ink scan (the year's figures
   or the sprite's orange read as the icon). The script hides the sprite,
   honours `disabled`, and takes Firefox's cut from its own width; the
   before runs predate both, so their Firefox gaps for Holidays (1.5) and
   Shoot day (1) are the scan's error, not the field's.
7. **A floor by specificity is not a floor, and a static model of the
   cascade is never whole.** The kit's `.ui-input { min-width: 0 }` and
   three lane rules lose to `input[type="date"]` (0,1,1), but the
   Dashboard's `.dash-note-meta > .ui-input { min-width: 104px }` (0,2,0)
   beat it (R1-06). The first test ranked by specificity alone; this
   session added `!important` and unlayered rules, and round 2 still got
   thirteen mutants through (another layer, a custom property, a
   condition, a pseudo-element, a parent component's class, a judged
   wrapper, `:not()` and `:is()` misread). `dateField.test.js` now reads
   each of those, and says what it cannot see (a style set from
   JavaScript, a selector it does not parse); the proof of the layout is
   the measuring script's, in three engines. A CI job that loads the
   fixtures and asserts Blink hides nothing would close the gap for good
   (not built: it is CI work, outside FX10).
8. **A wider date takes room from its neighbours, and its order matters.**
   The first version gave an item window's new-task form's dates their
   floor three to a row and left Bid days 51px (R1-01); round 1's fix put
   Bid days first and pushed the dates below a 700px window's fold
   (R2-01). The Bins inspector's and the Control panel's dates ran past
   their columns at 1024 (R1-03). The script now measures every control in
   a date's row, form or window; a select whose own words are drawn clear
   (the Shots table's Framing, its code shown over it) is listed, not
   judged.
9. **Never hide a part the keyboard can reach with `display: none`.**
   Chromium's calendar glyph is a Tab stop inside the field; the tables hid
   it with `display: none` unless the row was hovered or the field
   `:focus`ed — but on the glyph the field is only `:focus-within`, so the
   glyph vanished with the focus on it (R2-03, older than FX10). Hide with
   `opacity`, show on `:focus-within`.
10. **Stamp every measurement with the script that made it.** The first
    after-tables mixed two versions of the script (R2-04); each JSON now
    carries the script's hash and the summaries refuse a mix.
11. **The Bash tool halves backslashes** in heredocs and `node -e` (hit

    **Git Bash rewrites a leading-slash argument** (`/rabbit` became
    `C:/Program Files/Git/rabbit`; `MSYS_NO_PATHCONV=1`). Anything with
    escapes goes through Write / Edit.
12. **CI's runner is several times slower than this machine.** Two controls
