## 5. Traps hit

- 🚨 **A history op that names an unregistered mutator fails silently.**
  History entries call `mutationsRef.current.<name>(…)`; the registry near
  the end of RabbitProvider.jsx is a hand-written list; the undo loop
  swallows throws. Ctrl+Z after an assignment did nothing until
  `replaceShotTakes` & co. were added to that list. Pinned by
  `state/mutationsRegistry.test.js` (a source scan, like the bins wiring
  pin). Add every new mutator there.
- **The harness launcher's cwd is the worktree root**, not `WILSON/`, when
  started from `.claude/launch.json` through the Browser pane: the config
  entry that works is `runtimeExecutable: "cmd"`, `runtimeArgs: ["/c", "cd /d
  WILSON && npx vite --config dev-harness/vite.config.mjs"]`, port 5390. The
  proxy target in `dev-harness/vite.config.mjs` is the dev Electron's port
  (find it with `Get-NetTCPConnection -State Listen` against the WILSON
  `electron.exe` PID — the one whose window title is WILSON).
- **A Vite HMR of RabbitProvider.jsx reloads the page** and empties the
  in-memory history; re-do the action before testing undo.
- 🚨 **The dev Electron instance still writes to Audrey's real app data**
  (session 1's trap). This session created "ZZ Takes Test (delete me)", its
  folder `Documents\My_Work\Zz-Takes-Test-Delete-Me` (the app makes it) and
  ten poster cache files, and deleted all three at the end through the app's
  own DELETE route, `Remove-Item` on the (empty-tree) folder and the
  `bin-*.jpg` files newer than the session start. Her four other projects
  were not touched (the harness auto-opened LEGEND ROAD once, read-only).
- `winget`'s `ffmpeg.exe` (`%LOCALAPPDATA%\Microsoft\WinGet\Links\ffmpeg.exe`)
  is on this machine and makes real H.264 MP4s for tests
  (`-f lavfi -i testsrc2=… -pix_fmt yuv420p -c:v libx264`); it is NOT in
  `resources/ffmpeg/`, so the server probe stays `unavailable` — the
  renderer fallback fills MP4 durations and posters once Bins mounts.
- The Browser pane's `find` did not match a button whose visible text is
  uppercased by CSS ("Use take length"); coordinates from the screenshot did.
- 🚨 **The Electron main process does not hot reload.** Vite HMR updates
  the renderer, but `electron/*.cjs` is whatever was loaded at launch: a
  route fix verified green by vitest read WRONG from the running instance
  until it was restarted (`Stop-Process -Id <WILSON electron.exe>` then
  relaunch; the port changes, update `dev-harness/vite.config.mjs`).
- **`taskkill /PID … /T /F` from Git Bash does nothing** — MSYS rewrites the
  `/PID` flags as paths. Use PowerShell `Stop-Process -Id <pid> -Force`.
- **After a full page reload the Browser pane's synthetic clicks stopped
  reaching React** (the click was dispatched at the right element, nothing
  changed) and screenshots timed out; `javascript_tool` clicks and
  `find` / `get_page_text` reads worked and are what verified the seam.
- **A button inside a button**: the inspector's collapsible section header
  was a `<button>` and its right-hand `IconBtn` nested inside it — React
  warns, browsers may split the DOM. The header is now a row of siblings.
- GitHub connectivity: pushes and fetches wrapped in retry loops again; none
  needed a retry this time.
