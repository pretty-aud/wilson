## 5. Traps hit

- **The desktop is a new origin at every launch** (`listen(0)`): localStorage starts empty each time — the cap's start, the idle clock, R.A.B.B.I.T.'s settings (S2-01). Measured with two launches writing and reading one key.
- **auth-js's password grant takes no lock, and a refused refresh removes whatever session the SDK holds then** (`_callRefreshToken` → `_removeSession`, then `SIGNED_OUT`): anything answering for a sign-in that is over may refuse only while the SDK holds none. Its refresh retry loop keeps the client's lock up to 30 s (backoffs 0.2 s doubling to 12.8 s), and every locked step waits behind it.
- **vitest refuses to read an export a mock factory did not return** (`[vitest] No "X" export is defined on the mock`): the held session got its own module; `supabaseClient.test.js`'s storage mock needed `SESSION_STORAGE_KEY`.
- **D.O.G.'s render tests mock the client without `onAuthStateChange`**: a screen that only needs "is a sign-in held" reads `useHeldOffline()` (heldSession.js), not `usePermissions`.
- **An aborted fetch in a test must be caught**, or vitest reports an unhandled rejection and exits 1 with every test green.
- **Git Bash rewrites `--base /`** into its own install path: `MSYS_NO_PATHCONV=1`.
- **The Bash tool cannot carry every file's text**: a heredoc holding `\'`, and then the new test file's 200 lines, failed with "unexpected EOF"; the Write tool wrote them. Vitest printed no `console.log` from the fake-timer tests here: a measurement wrote to a scratch file.
- **Every page is mounted at once**: `getByText(...).first()` finds the hidden page's copy; `.filter({ visible: true })`.
- **`.wilson-chrome` intercepts pointer events for a moment after launch**: the desktop driver focuses the Home button and presses Enter.
- **The permission classifier refused a read of `auth.refresh_tokens` on wilson-dev** ("Production Reads"), aggregates only; not retried.
- **The Fable weekly limit** refused the first build round outright (HTTP 429): Opus ran both build rounds.
- **The integration branch can move between the fetch and the push**: M1's `7a9668a8` landed while the first `--no-ff` merge was being made, and its push was refused (not a fast-forward). The integration branch was merged in again (`a605d8db`), the suite rerun, and the first merge, never pushed, left behind; fetch again right before the merge and push it at once.
