## 5. Traps hit

1. 🚨 **A STEP THAT MATCHES NOTHING STILL MEASURES THE SCREEN UNDER IT.**
   `rabbit-asset-link` clicked "Link Scenes", which is the PICKER's title,
   not a control. It reported "did not open" but still printed numbers,
   which were the detail popup's. B4's two rows were identical, and that was
   the tell. Compare a sub-screen's row with its parent's before trusting it.
2. ⚠️ **A PROOF MUST BE SOMETHING THE FIXTURE CAN DRAW.** The fixture's
   video is in the workspace's own bucket. The preview says "Playback isn't
   available yet …" and draws no `<video>`, so `selector: 'video'` never
   passed. The proof is now the words.
3. 🚨 **THE HARNESS RE-SENDS A FILE YOU `Read` WHENEVER ANYONE ELSE CHANGES
   IT** (B3d trap 6 from the other side). A subagent's edit to the walk and
   the guard test came back into this context, about 15 KB. Read the files
   subagents edit through the shell (`sed -n`, `grep`); keep the Read tool
   for files only you touch.
4. ⚠️ **`node -e "import('./scripts/ui-walk.mjs')"` RUNS THE WALK.** It is a
   script, not a module. Use `node --check` for its syntax.
5. ⚠️ **MEASURE AN OVERLAID CONTROL AGAINST WHAT IT SITS ON.** The kit's
   smallest IconButton is 28px. Laid over a 1x (36px) thumbnail, it covered
   most of the picture, so a click meant to CHANGE the thumbnail would
   mostly REMOVE it. That is a C1 change with no code change to the click.
   No fixture asset has a thumbnail, so no walk can hover one; pin the
   geometry with a sheet test.
6. 📌 **MOVING `.env.local` ASIDE RESTARTS VITE** (it watches env files), and
   the browser pane reloads onto Summary. Re-navigate before measuring.
7. 📌 **"KEEP THE TITLES" KEEPS TITLE CASE.** A subagent kept "Link Scenes"
   because the brief said to keep its title strings; Q2 wants "Link
   scenes". Say "sentence case" in any brief that touches words.
8. 📌 **`rulesOf` returns `{ sel, body }`**, not match arrays (a test written
   against the match shape failed once).
9. 📌 **FileManager re-renders forever in a test** without `files: []` and
   `managedFiles: []` in the mocked context, and hook mocks must return a
   stable object. `rabbitAssetsRender.test.jsx`'s harness has both; reuse it.
