## 3. Done and verified

1. **Migration 0068 `fn_user_pets_reject_stale_write`** — `5add1d4`, header
   corrected in `7322e12` and `b338745`. A BEFORE UPDATE trigger on
   `public.user_pets` raising SQLSTATE **`WP001`** when
   `NEW.last_updated_at < OLD.last_updated_at`. The comparison is the DECAY
   ANCHOR, never `updated_at` — the touch trigger stamps that on every write,
   so a guard on it could never fire. **Equal is allowed and that is
   load-bearing**: every save that does not move hunger or happiness re-sends
   the anchor it holds, and the suite's pre-existing probe 18 (a real feed) is
   the failing control that proves `<=` would break ordinary use.
   Post-condition block proven non-vacuous by **nine mutations** run inside
   `BEGIN … ROLLBACK` against dev: the shipped guard stays quiet, all eight bad
   ones raise.
2. **The client stopped stamping a fresh anchor on every save** — `700588e`.
   This is what makes 0068 able to fire at all; without it the stale window's
   anchor is always the newer one. The anchor now moves when, and only when,
   hunger or happiness move.
3. **The death trio** — `700588e`, corrected in `7322e12`. `applyOfflineDecay`,
   `derivePetState` and the three rate tables MOVED to
   `src/lib/petLifecycle.js` so they could be driven as real functions instead

## 5. Traps hit (the brief did not say these)

- 🚨 **A STALE WORKTREE PUSHED TO THIS BRANCH WHILE I WORKED, AND MY INDEX WAS
  THE ONE THAT WENT STALE.** The A2s2 worktree committed four times onto
  `track-a-product`; because HEAD is the branch ref, my HEAD advanced while my
  worktree's index still held the older blob of the A2s2 hand-off. `git status`
  showed a STAGED change I had not made, and committing would have reverted 70
  lines of that file. `git checkout HEAD -- <file>` fixed it.
  **Read `git status` before every commit on a track branch and look at the
  staged column, not only the unstaged one.** The protocol's new rule
  (`git checkout --detach` as the last command of a hand-off) is the other
  half; this session ends that way.
- 🚨 **THE THEME OF THIS SESSION, AND IT IS THE SAME ONE THE A2 SESSION
  RECORDED: FOUR INSTRUMENTS WERE WRONG, AND ONLY A BREAKER FOUND EACH.**
  - A probe asserted `isStalePetWrite(err)` against a message that CONTAINED
    the message token, so the predicate's message arm answered and the probe
    passed with the SQLSTATE deleted. **Assert the field the mutation removes.**
  - A `toBeCloseTo(…, 5)` on a decay value demanded agreement to 5e-6, which a
    few milliseconds of real elapsed time between building the fixture and
    calling the function exceeds. It went red under an unrelated mutation.
    **A flaky pin is worse than none.**
  - A COUNT pin matched only the colon form `lastUpdatedAt: new Date()`, so the
    one site that is an ASSIGNMENT was invisible — and two of its matches were
    a comment and a fallback arm. Deleting the site it named was green.
    Later, the same pin's floor was four below the actual count, and the stamp
    with no anchored assertion at all turned out to be the load-bearing one.
    **A count pin must be the EXACT count, over comment-stripped source, and
    every load-bearing site needs its own anchored assertion.**
  - A containment pin sliced from the middle of a block, so everything ABOVE
    the slice was invisible; adding the mutation there was green. **Slice the
    whole function, assert the count inside it, then assert position.**
- 🚨 **A "REVIEW THE CORRECTIONS" ROUND IS NOT CEREMONY.** R2 found that R1's
  fix for Pet Mode was a WORSE bug than the one it fixed — it made migration
  0068 inert for the exact control the walkthrough tells Audrey to press. A fix
  that removes a guard in order to fix a symptom is the shape to look for.
- 🚨 **AND THE WALKTHROUGH ITSELF CAN BE WRONG IN A WAY THAT COSTS AUDREY'S
  TIME.** Walkthrough 07's first draft told her to change the Difficulty, which
  does not move the anchor, on a pet that may be a ghost — so the correct
  behaviour (both windows holding the same copy, second write accepted) would
  have been reported as the bug. **Ask of every walkthrough step: does this
  gesture actually reach the code the step is testing?** Her own test-plan note
  ("on B, pet it") had the same defect: `handlePetAction` returns without
  saving for a ghost or a corpse, so petting one writes nothing at all.
- **A raw NUL byte in a source file makes git treat it as BINARY.** A
  `${UID}\0` test value rendered the whole 11 KB test file as
  `Bin 0 -> 11281 bytes` in every diff, invisible to review. Write the byte
  as a unicode escape in the source; it is the same value to the test.
  ⚠️ This hand-off did exactly the same thing while describing it, and
  `grep` answering "Binary file … matches" is how it surfaced. Sweep any
  file you write for `\x00` before committing it.
- **An unasserted `str.replace()` in an edit script is a silent no-op.** One
  edit "renamed" a label that did not match; nothing failed, nothing changed,
  and the mistake surfaced two rounds later. **Assert the occurrence count on
  every replacement.**
- 🚨 **The tool harness collapses backslashes inside a bash heredoc** — the
  third hand-off in a row to say so, and I hit it anyway writing a Python
  script inline. Every regex, every escape: use the Write tool.
- **`supabase db query` can fail to CONNECT and look like a pass.** A breaker
  script read "no exception raised" as "the check did not fire" when the CLI
  had actually hit the SASL race on its rotating temp login role. **A run that
  did not connect is UNMEASURED, not green** — the same rule as pgTAP's QUERY
  FAILED. Detect it and say so.
- **`gh` is not authenticated in a spawned worktree.** `curl` against the
  public REST API works and needs the FULL SHA.
- **`node scripts/tap-all.mjs` prints everything at the end**, so a background
