## 5. Traps hit

**1. 🚨 A CSS cascade layer put Foundation's entire kit behind Tailwind's
preflight, and every test stayed green.** `settings.css` opened
`@layer components`. A layer's position in the cascade is fixed where it is
**first named**, not where its rules are written — and because this stylesheet
is imported from a component, the bundler emitted it *before* `src/index.css`,
so `components` was created ahead of `base`. Every rule in that layer, mine and
all of `src/ui/`, lost to preflight. The symptom was specific and easy to
misread: `height` survived (preflight does not set it) while `padding`,
`font-size`, `color` and `background-color` were silently reset. Buttons had no
fill, tabs had no padding, the page looked half-built. **2136 tests passed
throughout**, because no test in this repo mounts React. The fix is one line at
the top of the file naming the four layers in order; it is a no-op when
`index.css` gets there first. **Any session adding a component-level stylesheet
must do the same.**

**2. A comment that quotes a pinned literal inflates the count.**
`workspaceRootWiring.test.js` counts gated-action tags by source text. My first
draft of an explanatory comment spelled the tag out, and the count went 3 → 4 —
so the assertion would have passed with a real gate deleted. A source-text test
cannot tell code from prose. The comment now describes the tag without
spelling it. `userStateWiring.test.js` records the same trap twice from the
other direction, where a negative assertion matched its own documentation.

**3. Two pinned strings straddle a line break.** `localMediaWiring:124-125`
asserts `Local Server is` and `for demos only: its projects stay on this
computer and cannot be shared.` The first ends a source line and the second
*is* the next line. Re-wrapping that paragraph fails the test with copy that
never changed and a message that says nothing about design. Change the class,
never the wrapping. The same holds for the hint at `:126`, asserted **with its
surrounding single quotes**, so it must stay a one-line quoted literal.

**4. The kit's `Input`/`TextArea` Escape contract will eat your handler.** They
handle Escape themselves and `return` **before** calling the caller's
`onKeyDown`, and their cancel path calls `blur()` — which fires `onBlur`
**unconditionally**, because only `onCommit` is gated on "the edit was not
cancelled". So `onBlur={commit}` makes Escape *persist* the edit it is
cancelling, and Enter (which also blurs first) commits twice. Use `onCommit`.
On an autosaving field, wire a local draft or Escape will write its revert to
disk.

**5. `Button` has no `Icon` prop.** `Badge`, `Banner`, `EmptyState`,
`IconButton` and `Menu` all take one; `Button` does not — it spreads unknown
props onto the DOM, so `Icon={X}` renders nothing and hands React a
function-valued attribute. The kit sizes an icon **child** through
`.ui-btn > svg`. Thirteen icons were silently missing.

**6. A JSX comment placed directly inside a `&&` expression is a parse error,**
not a comment. `{cond && ( {/* … */} <div/> )}` fails the build. It cost two
builds; put the comment above the guard.

**7. On one ink, a coloured edge is not a carrier.** My first pass gave error
and warning feedback a `#ea580c` left edge. Measured against the well behind
it that is **1.40:1** — so the two states you must notice were the two
invisible ones while success (ink, 6.90:1) was the only one that read. Same
mistake on the selected storage-backend dot: filling it with signal put it at
1.40:1, making a *selected* dot harder to see than an unselected one. On this
ground the carrier has to be form — edge width, weight, fill vs ring.

**8. `min-height` includes padding under border-box.** `min-height: 36px` with
`padding: 8px 0` is a 52px row the moment it holds a 36px control. Four row
heights shipped while the contract claimed one.

**9. The preview harness runs the dev server from the MAIN checkout, not from
this worktree.** `preview_start` with a launch.json name served the canonical
`WILSON/` — the pre-change `SettingsPage.jsx` and a `.env.local` without the
tester flag — so the first screenshots would have been of the old page. Verify
by fetching a file that only exists on your branch before trusting anything you
see. The workaround: run `npx vite --port <free>` from the worktree yourself
and open it with `preview_start { url }`.

**10. Element and viewport screenshots both stop at the fold,** because the
page scrolls inside its own container rather than the document. To capture a
whole tab: walk up from `.s-page` setting `height: auto; max-height: none;
overflow: visible` on every ancestor, take `page.screenshot({ fullPage: true })`,
then restore. `@playwright/test` is already a dev dependency.

**11. `GatedAction` changes a row's flex-child count.** When a control is
denied it injects a wrapping `<span>`, so an admin and a member get different
DOM. No row rule may use `> *`, `:first-child`-as-layout or gap arithmetic.

4. **Light-surface holes measured in F1's kit:**
   - `Chip` and `Loading` accept `surface="light"` but no CSS resolves it, so

   - `Spinner` and `Kbd` have no `surface` prop at all.
   - `Switch`'s light variant covers **only its label**. Its track is `ink-3`
     grey when off and `signal` on `ground-light` (~1.06:1) when on, so the
     state is unreadable. **This is why the six toggles on this surface are
     still two-state buttons and not `Switch`.**
   - `IconButton:disabled` on light resolves to `ink-3` grey, because
     `:disabled` is declared after the light rule at equal specificity.
   - **A disabled light `Button` is visually identical to an enabled
     secondary** — same ink, same hairline, no fill on either. A disabled
     control needs a form change on this ground, not an ink change.
5. **`GatedAction` dims denied controls with `opacity: 0.4`** — the spelling
   plan §3.1 bans — putting a denied label at 2.20:1 next to kit buttons that
   use the token. `src/permissions/GatedAction.jsx` is not this session's file.
6. **`ProfileSection` needs a `surface` prop** before lane C2 moves the
   Dashboard onto `paper`: the same component is mounted by both
   `SettingsPage` and `DashboardPage`.
7. **`pageBars.js`**: S23's 120/80 for Settings, when Wave 3 does the class.

## 8. Deferred structural work

**`SettingsPage.jsx` is not split into seven tab files.** The review's S37
prescribes it and the critic seconds it. I did not do it, and the reason is
mechanical rather than aesthetic: plan §6.6 records that Tracks A and C both
carry unmerged changes to this file, and its rule for such files is *"append,
swap classes, never reformat or restructure"* so a later merge conflicts on
lines rather than on structure. A seven-way file split is the most
merge-hostile change available on it, and it would additionally repoint all
four wiring tests' read targets. **It should happen in the session after the
tracks merge**, as its own commit with zero styling in it.

`src/cloud/auth/WorkspaceSwitcher.jsx` (first thing on the General tab) and
`src/cloud/auth/MfaSection.jsx` (between Profile and Session on the Profile

the old `h2 text-sm font-bold uppercase tracking-widest` heading, raw
`text-[11px]`/`text-xs`, mono on labels, `rounded-sm`, two 2px borders, a
seventh brown alpha and eight raw hexes, including `#15803d` at 2.43:1 and
`#fff7ed` on `#ea580c` at 3.35:1. **The Profile tab is the one place the page
visibly does not read as one system**, and D2 closes it. Until then, the
