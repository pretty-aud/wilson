## 6. The caret re-measurement

`AuthPasswordInput` draws asterisks over a real `type="password"` input. The
alignment invariant has two halves, and the file's header records that the
current drift is **0.00px**:

1. **Width parity** — the password field's rendered width must equal a plain
   text field's. This was the `ch` bug: `22ch` of monospace measured 205.6px
   against the sans fields' 201.6px, so the wrapper was given the sans family
   *and* the sans size to make `22ch` mean one thing. `ch` depends on family
   **and** size, and this session changes both.
2. **Caret parity** — the caret sits after the Nth bullet; the overlay draws N
   asterisks. Both layers spread one `metrics` object, so this holds by
   construction as long as the object stays shared.

**What changes, and why the risk is retired rather than re-taken.** AUTH-22
prescribes one field measure *"in px on the 4px scale rather than in ch (ch
drifts with the face and the size)"*. Adopting `AUTH_FIELD_WIDTH = '240px'`
removes half 1 from the font entirely: both the plain input and the password
wrapper take the same px width, so no font metric can separate them. The mono
stack inside `metrics` is pinned to `var(--font-mono)` (Geist Mono) in the same
edit that deletes `AUTH_TEXT_STYLE.fontFamily`, per AUTH-02. `metrics.fontSize`
moves 17px → 14px with the input. `metrics.fontWeight` 700 → 600: the variable
face is declared `400 600`, so 700 already clamps to 600 and the source stops
claiming a weight that does not exist. `lineHeight: '1.2'` and
`padding: '4px 0 6px'` are **unchanged on both layers** — they are the
row-height parity the file already documents, and the review is explicit that
only the size step may move.

**How it is re-proved**, in the running app at 1440x900 and again at 1280x700,
on the sign-in screen with `VITE_DEV_AUTOLOGIN` unset:

```js
const user = document.querySelector('input[aria-label="Username"]')
const pass = document.querySelector('input[aria-label="Password"]')
const mask = pass.parentElement.querySelector('span[aria-hidden="true"]')
// (1) width parity — the number the header records
user.getBoundingClientRect().width - pass.getBoundingClientRect().width   // must be 0.00
// (2) the two layers resolve one font
getComputedStyle(pass).fontFamily === getComputedStyle(mask).fontFamily
getComputedStyle(pass).fontSize   === getComputedStyle(mask).fontSize
// (3) the mask's painted run ends where the input's own text run ends
pass.getBoundingClientRect().left - mask.getBoundingClientRect().left     // must be 0.00
```

Typed into the field first, so `value.length` is non-zero and the mask actually
has glyphs. The measured numbers go into the header comment the way the current
ones are, and into the hand-off. **Failure mode if this is wrong: a locked-out
admin, not a cosmetic regression.**

`SPLIT_BAR_HEIGHT` (`'24vh'`) is re-derived the same way — from a fresh
measurement of the retyped `NewUserWelcome` in the running app at a 700px
window, not from arithmetic. If it still overflows, the lever is the gap scale
and a two-column row for pronouns and title, **never a second set of bars**.

## 9. The Playwright selectors

Thirty selectors across three files resolve into these surfaces. Twenty-eight
are unaffected: `getByLabel` reads `aria-label`, which is already sentence case
and deliberately differs from the visible uppercase `AuthField` label — both
stay. `getByRole('button', …)` reads button text, which is already sentence
case (`Continue`, `Sign in`, `Send reset link`, `Set password`, `Send invite`,
`Set up later`). The Home tiles keep their `<button>` + `role="img"` shape, so
the `.filter({ has: getByRole('img') })` disambiguation still works.

Two are case-sensitive and would break when `LOGIN` becomes `Login`:

| File | Line | Now | Becomes |
|---|---|---|---|
| `tests/e2e/authFlow.ts` | 58 | `page.getByText(/^LOGIN$/)` | `page.getByText(/^login$/i)` |
| `tests/e2e/web-path.spec.ts` | 56 | `page.getByText(/^LOGIN$/)` | `page.getByText(/^login$/i)` |

This is a **loosening**: the new regex matches the old text and the new one, so
it cannot regress, and it is the mechanism the plan names — *"Source-text tests
are updated in the same commit as the source they pin."* `/^RESET PASSWORD$/i`
and `/^NEW PASSWORD$/i` are already case-insensitive and need no change.
