## 5. Traps hit

1. **🚨 THE DEV SERVER SERVED THE WRONG CHECKOUT, AND LOOKED FINE.**
   `preview_start` with the worktree's `wilson-dev` entry resolved its cwd to
   the **main checkout**, which is on a pre-overhaul branch with no `src/ui/`
   at all. The app booted, the page rendered, and every screenshot would have
   been of the wrong code. It was caught by probing for a file only this
   worktree has: `curl /src/ui/Table.jsx` returned `index.html` (Vite's SPA
   fallback) instead of a module. **Probe for a worktree-unique file before
   trusting anything you see.** The fix is a launch entry that passes the
   root: `npx vite <abs path> --port 5221 --strictPort`. Vite takes the root
   **positionally** — `--root` is an unknown option and exits 1.

2. **🚨 A STATE TEST THAT CHECKS A VALUE THE STYLESHEET DOES NOT READ PROVES
   NOTHING.** The kit's `Row` writes `data-selected={selected || undefined}`
   and `index.css` keys on the attribute's **presence**
   (`.ui-tr[data-selected]`). C3's extraction spells state
   `data-x={String(<expr>)}`, which renders `data-selected="false"` — present,
   so it paints. Passed straight to `<Row>`, **every roster row rendered as
   selected and deactivated at once**, and:
   - the source-scan guard passed (the spelling was right),
   - the seven render tests passed (they asserted the string `"false"`),
   - the full suite passed, the build passed,
   - and the page was visibly wrong in the first screenshot.

   Both spellings are correct for their own side; the defect is the two
   meeting. **Before passing a `data-*` to a kit component, grep `index.css`
   for whether that selector reads the value or the presence.**
   `adminTerminalCss.test.js` now fails the build on the combination, and the
   render tests assert absence rather than `"false"`.

3. **`git checkout -- <file>` reverts your uncommitted work along with the
   mutant.** Reverting a deliberate break in a file that also held an
   uncommitted fix silently undid the fix; the next run showed *four* failures
   where the mutant had caused three, which is the only reason it was noticed.
   C3 recorded the untracked-file half of this trap; this is the tracked half.
   **Commit before mutating, or re-apply after reverting and re-read.**

4. **Git Bash rewrites a leading-slash argument into an MSYS path.**
   `--pages /admin-terminal` became `c:/Program Files/Git/admin-terminal`.
   `scripts/screenshot.mjs` documents the `root` alias for a bare `/` and the
   same trap reaches every path argument. Prefix the command with
   `MSYS_NO_PATHCONV=1`.

5. **A quoted bash heredoc still mangles a Python script containing regex
   escapes**, in a new way from C3's: `\s` and `\{` inside a heredoc emit
   `SyntaxWarning` and the substitution silently fails to match, so the edit
   "succeeds" and changes nothing. C3's advice stands and is stronger than it
   looked: **write the script with the Write tool and run it by path.** Every
   edit in this session that used a heredoc had to be redone.

6. **A single grep lies, again, in a new shape.** `grep -c "<h1"` reported 1
   after the `<h1>` was deleted — the hit was the word `<h1>` inside the
   comment explaining the deletion. C3 recorded stale grep output; this is
   grep matching prose. **Read the matching line, not the count.**

7. **`grep -c $'\r'` under Git Bash reports 0 on a CRLF file.** The shell
   strips the CR from the quoted argument, so a line-ending check written that
   way says "all LF" about a file that is entirely CRLF. Use `od -c`.

8. **A guard derived from two sources can pass while checking nothing, and
   did, twice in ten minutes.** The presence-attribute guard's component list
   came from a regex that only matched `import X, { Y } from`, so it found
   neither `Button` (a plain default import) nor `Table`, and scanned an empty
   set. Both derivations now have an explicit "the scan is not empty" test
   beside them. **Every derived list needs a companion assertion that it is
   populated.**

9. **🚨 A SCRIPTED TOKEN SWEEP COLLAPSES DISTINCTIONS IT CANNOT SEE.** Two
   files took a find-and-replace map from light-ground literals to dark
   tokens, which is the right treatment for files another track owns — and it
   silently destroyed two deliberate one-step contrasts. `rgba(120,70,30,0.08)`
   on a row and `rgba(120,70,30,0.12)` on the panel inside it both became
   `paper-raised`: **1.00:1, no boundary at all**, on the panel that says what
   approving a change request will do. A dark brown ink and a pale orange fill
   both became the signal, which is 3.75:1 against itself. **After any sweep,
   list the source values that mapped to the same destination and look at each
   pair.** Neither defect is visible in a diff — both lines are correct on
   their own.

10. **A `:disabled` rule on a control does not reach children that set their
    own colour.** The Storage pickers' disabled state was written, tested for
    in the sheet, described in a comment — and reached nothing, because every
    string inside the button carried an inline `color`. The guard that catches
    inline-beats-class only looked at the `.at-*` element itself, not at its
    descendants. **A state on a container has to name the descendants it
    colours, or it is a declaration rather than a state.**

11. **A media query on the VIEWPORT, inside a container the viewport stopped
    driving.** The page is capped at the data measure, so the section pane
    saturates at about 1016px — while a `max-width: 1320px` rule kept widening
    the detail panel past that point. The result was that a window 1px wider
    than 1320 permanently cost the table 60px, and the roster was at its
    NARROWEST at the plan's own 1440x900 reference size. **Inside a capped
    container, measure the container, not the window.**

12. **GitHub was unreachable intermittently, again** — one push failed with
   `Failed to connect to github.com port 443 after ~21s` and succeeded on
   retry seconds later. Third session running. Plan §6.3's "retry on
   rejection" covers it.
