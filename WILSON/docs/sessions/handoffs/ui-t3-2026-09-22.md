## 5. Traps hit

1. 🚨 **THE BRIEF'S OWN BASELINE WAS WRONG, AND THE REASON IS A SILENT
   FAILURE THAT HAS BEEN LIVE SINCE T0.** `npx vitest run` at `e1b5c31` is
   **139 files / 2823 tests** on Windows, not 140 / 2858.
   `src/ui/typeScale.test.js` cannot COLLECT, and vitest reports that as a
   failed SUITE with ZERO failed tests — the summary line stays calm while
   T0's entire 35-case type guard silently does not execute.

   The mechanism: Git for Windows ships `core.autocrlf=true` in its SYSTEM
   config, so every checkout here gets CRLF although every blob is LF. Vite's
   SSR transform hoists a module's imports to the top of the rewritten body
   and strips a `#!/usr/bin/env node` hashbang on the way past — but the strip
   only matches an LF-terminated one. With CRLF the hashbang SURVIVES, lands
   mid-body, and `new AsyncFunction(...)` throws `SyntaxError: Invalid or
   unexpected token`. `typeScale.test.js` imports six hashbanged scripts, so
   any one of them takes the suite down.

   Proved with a two-file probe, one LF and one CRLF, otherwise identical:
   LF loads and the hashbang is stripped; CRLF throws with the hashbang left
   at index 223. Fixed with `*.mjs text eol=lf` at the repo root, which
   changes no content (`git add --renormalize '*.mjs'` stages nothing).

   **CI never saw it: CI is Linux, where the checkout is LF either way.** That
   is also why `3f785d6` is genuinely green on GitHub while the same commit
   could not load its own guard here.

   🚨 **All three Wave 1 sessions hit this within minutes of each other.** T1
   diagnosed the symptom and worked around it by externalising
   `scripts/*.mjs` from Vite, then reverted in favour of this; T2 wrote a
   second `.gitattributes` under `WILSON/`, which the merges resolved away.
   One root `.gitattributes` survives. **If you are reading this in a worktree
   cut before `b4eac8f`, `.gitattributes` does not convert files that are
   already checked out** — merge, then convert them in place or delete and
   re-checkout, or you will chase the same ghost a fourth time.

2. 🚨 **A MUTATION THAT SILENTLY FAILS TO APPLY IS INDISTINGUISHABLE FROM AN
   ASSERTION THAT CANNOT FAIL**, and it happened twice in this bundle. A perl
   substitution that did not match, and a Python one whose search string was
   LF against a CRLF file, both produced a green suite that read exactly like
   "the control is inert". The fix is one line: **assert the mutation landed
   before running the suite.** Every mutant here does. T0's §5 trap 13 is the
   same lesson from the other end — there the control was inert; here the
   control was fine and the experiment was broken.

3. ⚠️ **A COMMENT QUOTING A CLASS NAME ADDS AN AUDIT HIT.** Writing
   ``tracking-[0.4em]`` in a prose comment took the arbitrary-tracking row
   from 3 to 4, so a comment looked like a fourth live site. T0's remainder
   notes already carry two hits that are only comments. Describe the class,
   do not spell it.

4. ⚠️ **`\bem\b` MATCHES NOTHING AGAINST `0.9em`** — `9` and `e` are both word
   characters. That is T0's §5 trap 2 for the fourth time in this bundle, and
   it failed in the direction that looks fine: an `accept()` clause silently
   swallowed seven real hits while its comment claimed to exclude them.

5. ⚠️ **AN EXEMPTION WINDOW IS A THRESHOLD, SO MEASURE IT.** `sweep`'s ±140
   window is too narrow for the frozen transition title: the nearest string
   that identifies the element ends ~155 characters from its `fontSize`, so at
   ±140 two of its five declarations matched their own exception and two did
   not — which would have read as a real defect inside a block C2 forbids
   touching. ±400, measured. (T0 §5 trap 18, on another surface.)

6. ⚠️ **`git checkout <sha> -- src/` IS BLOCKED BY THE DESKTOP APP'S
   CLASSIFIER** as irreversible local destruction, which is the right call —
   it is also T0's traps 8 and 10. The way to get a "before" screenshot of a
   surface is a plain file copy: back the file up with `cp`, edit it with a
   script that ASSERTS its substitutions applied, shoot, restore with `cp`,
   and confirm `git diff --stat` is empty.

7. 📌 **DEVICE PIXEL RATIO CHANGES THE CARET'S ROW HEIGHT AND NOTHING ELSE
   THAT MATTERS.** Measured in the Browser pane at DPR 1.5 the rows are
   27.46px, not D2's 27.80 — because a 1px border snaps to one DEVICE pixel,
   0.667 CSS px (16.792 + 4 + 6 + 0.667). Every other axis still reads 0.00
   there, and a 240px field still measures exactly 240.000px, which is how the
   page is known not to be scaled. Playwright defaults to `deviceScaleFactor:
   1`, which is D2's condition and reproduces 27.80 exactly. **A session that
   compares 27.46 against AuthShell's comment and concludes the row moved will
   be chasing a rasterisation difference.** The script prints the DPR and the
   border width so that comparison cannot be made blind.

8. 📌 **F1'S HAND-OFF §8 IS STALE AND THE NEXT SESSION WILL GO LOOKING.** It
   records that `AuthShell.jsx` still carries a private mono stack
   (`ui-monospace, SFMono-Regular, …` at weight 700) that should point at
   `var(--font-mono)`. It does not, and has not since D2: the family is
   `FONT_MONO` and the weight is 600, with the reason written beside it.

9. 📌 **THE AUTH SIGN-IN SCREEN TAKES ~9 SECONDS TO APPEAR** (1200ms logo in,
   up to 3800ms hold, 500ms out, 1000ms idle, then the step), and it only
   exists with `VITE_DEV_AUTOLOGIN` commented OUT of `.env.local` **and the
   dev server restarted** so Vite re-reads it. Step 1's company check degrades
   to the derived slug when `resolve-login` is not deployed, so any plausible
   name reaches step 2 without a real account. `ui-caret-check.mjs` exits 2
