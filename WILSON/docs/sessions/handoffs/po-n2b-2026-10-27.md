## 5. Traps hit

- **An editor grant is a read grant, again.** The brief's chain ended at `user_g`, who holds an editor grant on C1 and reads S1 whatever the chain does; "g reads S1: 0 after the cascade" could never be true (round 2 of N2 hit the same). The chain ends at a new plain fixture, `user_h`. A fixture user who exists for one probe gets that probe and nothing else.
- **There is no `subject.create`.** A subject's first save is `subject.save` (`POST /api/software/:slug/subjects`), in six places in `Otter.jsx`; a run holds slugs, not ids (`subject.save`'s response carries none); `subject.save` updates a slug it finds, so "saved" is not "new"; and the six paths end six different ways, so a hook that waits on `loadSoftwareList()` waits on nothing in four of them. Hang the hook on the run's last save, decide "new" against the course's slugs before the run, and read `subject.list` for ids after.
- **Locking the parent row is not locking the chain.** A revoke two links up takes its lock and opens its cascade cursor before a concurrent pass-on commits, and a plpgsql FOR-IN-query cursor keeps its snapshot, so the new row is never reached. Lock every link above the new row `FOR SHARE`, root first (the cascade's own order, so no deadlock), and assert the lock in a post-condition, because a pgTAP suite is one transaction and cannot probe a race.
- **A `NOT NULL` column with no default has to be named in every forged-row fixture.** SH5 lacked `subject_owner_id`; the insert would have raised 23502 outside any `throws_ok` and aborted the file.
- **A whole-row SELECT grant is a whole-row disclosure.** The policy's owner arm hands the owner every column of every row of their subject, the middle person's note among them; the index's nulls are what the client shows, not a boundary. Say it.
- **A definer that LISTS must test a link as the one that GATES does** (N2's trap, one level up): the index checked the parent's status where the helper checks subject, sharer and depth too, and a depth-forged row was listed as accepted.
- **One number in two places drifts.** `chain_depth` on the row, pinned and `CHECK BETWEEN 1 AND 8`, makes both walks step by one and end by construction; a counter in the helper would have needed a twin in the row-maker.
- **Standing before identity.** A function that says *that is their own subject* before it has checked who is asking tells anyone with a subject id who owns it.
- **A batch row in the owner's trash refuses every accept.** An Accept-all loop that stopped there would hold the other six hostage; skip `gone` rows, let Decline all take them, give them Dismiss.
- **Editing a 3,000-line CRLF design.** The Edit tool and `sed -i` are not safe here; a CRLF-preserving Python helper with every anchor asserted to occur exactly once was. Every failed anchor ended mid-line where the file's line ran on: anchor on whole lines as `cat -A` shows them (MSYS `sed` strips the `\r` on output). Count the HTML comment openers before and after (this file is a markdown file too: none in it). The Bash tool halves `\\` in a heredoc, so write scripts with the Write tool and run them.
