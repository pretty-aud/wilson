## 5. Traps hit

- **Bash heredocs halve `\\`**, again: an edit script's `\r\n` anchors became real line breaks in
  the script itself. Scripts with backslashes went through the Write tool.
- **The Write tool can turn an escaped surrogate pair** (`\ud83d\ude00`) **into the character
  itself**: it did twice in this session, inside quoted strings, and not in prose; a lone `\udc00`
  and `\u0000` stayed escaped. The string is the same at run time, but a test or probe that means
  the escape must be checked byte by byte after writing.
- **Line endings differ file by file:** the files this session wrote whole are LF in the working
  tree (the model, the twin, the provider's state, their tests, 0098), the rest CRLF. Every edit
  script anchored on the file's own ending and stopped when an anchor was found other than once.
- **The coverage guard wants a suite named exactly after each table in `RLS_TABLES`**; one suite
  cannot be named for two tables, so `item_groupings` is in `COVERED_BY` (93_bins' shape).
- **`supabase db query` prints no NOTICE:** a probe that catches errors reports through rows, or
  through one raised exception that carries the whole report.
- **jsonb's text is not `JSON.stringify`'s:** `": "` and `", "`, keys by length then bytes,
  numbers in full without an exponent (R1-5, R2-4); and Postgres refuses NUL (22P05) and half a
  surrogate pair (22P02) in jsonb and in text alike.
- **Which of two groupings survives a shrink onto one set depends on the order the items go**
  (R1-2, R2-1): one request per asset on the desktop's bulk delete, heap order in the cloud's
  scene cascade. The screen's mirror can be wrong; an undo must go by the backend's answers.
- **A redo replays the mutator with the history suspended**, so the entry keeps the closures of
  its first capture (R2-2): whatever an undo learns, such as a new id, goes back into that capture.
- **RLS drops a DELETE without a word:** a delete that removed nothing needs a read to tell
  `deleted` from `filtered` (R1-3).
- **The history runner swallows an op's throw:** an undo op that can partly fail reports its own
  failure (the notice, R1-1).
- **The signed-out desktop's boot keeps the provider's default mode** (S-1): an effect keyed on
  the mode alone never ran again once the adapter arrived.
- **A save that finished after a project switch still raised its undo toast** (found by this
  session's own test): every toast checks the project visit it began on.
- **Two tests flake at vitest's default worker count** (`taskItemDrops.test.jsx`, a 5 s timeout;
  `gateway/test/certs.test.mjs`, `ETIMEDOUT`); both pass alone, and the four-worker run is clean.
- **Python's stdout on this machine is cp1252:** the mutation runner refused a test name's emoji
  until it reconfigured stdout to UTF-8.

## The API for VW1d (what the screens build on)

Everything is on the provider's context (`state/tableViewsState.js`, called
once by `RabbitProvider.jsx`); the rules are `state/tableViewsModel.js`; the
backends' contract is `adapters/index.js` (the block starting
`tableViewsAvailable`, and `TableViewWrite`).

| On the context | What it is |
|---|---|
| `tableViews`, `itemGroupings` | the open project's rows (every adapter's load; the live merge keeps them current on the cloud) |
| `tableViewsAvailable` | false on a cloud without 0098 and on Google Drive ("Saved views are not on this server yet.") |
| `tableViewsError` | a load's read error in words (the dropdown's error state); null after a clean load |
| `viewsOf(tableKey)` | a table's views in the dropdown's order (position, created_at, id) |
| `allViewOf(tableKey)` | the built-in *All*: `{ id: 'all', name: 'All', builtIn: true, revision: 0, config }`, never stored |
| `groupingsOf(tableKey, kind)` | the saved groupings of a table and kind |
| `addTableView({ tableKey, name, config? }, { words? })` | a new view, saved for everyone at once (Q-G1), after the table's last; `config` omitted = *All* |
| `updateTableView(id, config, { expectRevision?, words? })` | the bar's *Save*: written only while the view still has `expectRevision` (the view's own when omitted); answers a TableViewWrite |
| `renameTableView(id, name, { words? })` | never a new revision |
| `deleteTableView(id, { words? })` | its undo makes the view again with its id |
| `reorderTableViews(tableKey, ids, { words? })` | the named first, the rest after |
| `addItemGrouping({ tableKey, kind, entityIds }, { words? })` | a set already stored answers the stored grouping (nothing written) |
| `removeItemGrouping(id, { words? })` | rows keep their items; answers `{ removed: true }`, or `{ removed: false, status }`: `deleted` (gone already, off the screen) or `filtered` (the cloud's policies dropped it: it stays, and the screen says `GROUPINGS_GATE_WORDS`, "You can no longer change groupings on this project.") |
| `tableViewLast` | `{ status: 'loading' \| 'ready' \| 'unavailable' \| 'failed', map }` |
| `lastViewOf(tableKey)` | the person's last view of the table: an id, `'all'`, or null |
| `setTableViewLast(tableKey, viewId)` | written only while `ready`, in order |
| `viewDraftOf(tableKey)`, `setViewDraft(tableKey, { viewId, baseRevision, config })`, `clearViewDraft(tableKey)` | the changes for now (dropped on a project switch) |

A TableViewWrite: `{ status: 'saved', row }` · `{ status: 'removed' }` ·
`{ status: 'deleted' }` (gone) · `{ status: 'changed', row }` (a teammate's
save; `row` is theirs, already on the context) · `{ status: 'filtered', row }`
(the cloud only: the person may no longer change views on this project).
Every mutator offers its undo in the shell's toast and is never a
keyboard-history step; pass `{ words }` for the screen's own sentence. A name
or settings the rules refuse never reach a request: the mutator throws with
`code: 'table_view_invalid'` (or `item_grouping_invalid`) and words for the
card (`viewNameProblem`, `viewConfigProblem`). A refused undo is the
provider's to say (its notice), and one that met a passing fault keeps its
toast. A delete for good of a scene, shot, level or experience (or an asset
on the desktop) takes the item out of the groupings that name it, and its
Ctrl+Z puts them back: nothing for the screens to do.
