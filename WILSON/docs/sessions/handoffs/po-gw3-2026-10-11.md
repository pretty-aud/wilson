## For GW4 (the release and the install stories, what a browser's user must be told)

1. **The root to trust.** On the office network the browser reaches the gateway's own address over TLS with the company's root (the one Settings, Storage offers after the fingerprint is confirmed; a second one when a new root is ready). An office computer without it sees *WILSON can see the gateway … but this browser cannot reach it at <address>. On the office network, the gateway's certificate must be installed on this computer (Settings, Storage)…* — the install story must say where the certificate goes on Windows and macOS, and that a new root (a year before the old one's end, or when an inside address moves) is offered beside the old one and installed the same way.
2. **Chrome's local-network prompt.** The first time the web app reaches a private address Chrome asks whether WILSON may reach devices on the network; the tab says *Chrome will ask whether WILSON may reach devices on your network; allow it once.* Allowed once it is remembered for the site; blocked, every clip reads as unreachable until the site's permission is reset. The story must show the prompt.
3. **The gateway's own computer.** The office door does not answer its own host (§4): a browser on the gateway's computer plays nothing through it, and the tab says *On the gateway's own computer the office door does not answer its own host: use another computer on the office network, or the outside door while the switch is on.* The Windows story (walkthrough 61) should say it beside *doctor*.
4. **What plays.** MP4/M4V, WebM, a .mov the browser's decoder takes (H.264; not ProRes or DNx), the audio formats, the stills; a sequence as its middle frame. The story should set the expectation: proxies play in the browser, masters in the desktop app.

## For GW5 (what to attack in the player)

1. **A leaked URL.** The clip URL carries a two-minute ticket for one clip, one person, one gateway (`rv` for the outside door): copied out of the page it plays for at most two minutes (plus 30 s of skew) anywhere the door is reachable, and a renewal needs the first ticket's `jti` AND a fresh ticket the cloud mints only for the signed-in person. Attack: the Range requests a copied URL can make inside those two minutes; the audit's attribution of them (the `jti` is the viewer's).
2. **The overlay's removal.** The mark is a `<span>` over the element: the browser's tools remove it, and a recording of the screen keeps it only where it was drawn. The design (D9, G8) calls it a deterrent and the audit row the record. Attack: whether anything in the page lets the mark be turned off without the browser's tools (there must be nothing), and whether fullscreen (through the container) ever shows the bare element.
3. **The renew path.** `POST /v1/clips/<id>/renew` with `{ jti, t }`: GW2 binds the fresh ticket to the stream's clip, viewer, gateway and workspace. Attack from the page's side: a renewal posted with another clip's fresh ticket, another viewer's, a guessed `jti`; the page's own behaviour when a renewal is refused (it stops the src at the held ticket's margin and says the refusal).
4. **A hostile page holding the local-network permission.** Chrome's permission is per site: a page on `wilson.petalstudios.com` that an attacker controls (XSS) could probe the office door's address. The probe reads only `{ gateway_id, path, version }` and the clip route needs a ticket; attack the information the probe leaks (the gateway's presence and version) and whether a ticket could be obtained without the cloud.
5. **The diagnosis HEAD.** A failing element triggers one HEAD with its OWN ticket (review round 1, finding 6), and only without a ticket of its own a HEAD on a fresh one; a ticket that aged earns one fresh src per clip until a src loads; a YOUNG ticket the door refuses backs the clip off a minute with no fresh src (round 2, finding 1). Attack the rate (ten failed tickets close a connection, GW2) with a page that fails on purpose, a cloud that answers young tickets the door refuses, and a decode error that is not `MEDIA_ERR_DECODE` made to look like one.

## 5. Traps hit

- **A timer keyed on a parent's callback never fires when the parent re-renders often.** The player's renewal was a `setInterval` in an effect whose dependencies held `onRenew`; BinsView hands a new function on every provider update, and the tab's own 60-second gateway re-read is one, so with the design's 75 s the renewal never ran (the shortened 20 s runs passed; the first 80-second run against GW2's gateway posted no renewal at all). The callback is read through a ref now, and a test re-renders the player with a new callback every 30 s. Any timer in the Bins tab keyed on a context callback has the same trap.
- **Vite's dev server reloads every open page when any file under its root changes, documents included** (`page reload docs/OUTSTANDING.md` in its log): a Playwright run against port 5289 lost its page to Summary mid-step twice because the session edited the hand-off and OUTSTANDING meanwhile. Touch nothing in the worktree while a run against its dev server is going (the planted-fault runner included).
- **The first discovery with no gateway left the tab "probing" for good:** `listBins` raises the probing flag for the first discovery and `probeAll` returned early with nothing to probe, never ending it, so a company with no gateway read Chrome's sentence forever and an admin never saw the admin's line. Found by the provider test, fixed (`probeAll` ends the probe when nothing is to probe), pinned.
- **Playwright's strict mode and the hover scrub:** a tile hovered after a click keeps its scrub `<video>` (and, outside, its mark), so a page-wide mark locator matched two elements and `waitFor` threw a strict-mode error that read as "not found". The scripts move the mouse off the grid after each click and scope the mark to the inspector.
- **Chrome keeps the whole clip once read** (60 MB in seconds on loopback), so a seek alone asks the gateway for nothing: a proof that the old URL is served after a renewal, or refused after a cut, must make the element load its URL again (`v.load()`), which is what the e2e script does.
- **A page's tickets minted too far in the past never play:** the composite reuses a ticket only while more than 30 s remain, so a clock-faked ticket must keep at least that margin at the first request (the script backdates by 60 s, not 90).
- **A `data-surface="dark"` on a Bins file trips `binsCss.test.js`** (every `data-` state in `views/bins/*.jsx` must be a boolean `'true' | undefined` with a rule in bins.css): the stamp went on the table component itself (`RemoteViewingsTable`'s `surface` prop), where the Settings sheet's rules read it.
- **The Bash tool's heredoc halves `\\`** and a Python edit through it silently misses a string with backslashes; the Edit tool was used for those.
- **The fixtures' rows carry no `.wav` row**: the audio rows are `.bwf` (the stub plays the bundled WAV for them); a test that looks for `.wav` finds nothing.
- **A mutation tool's restore can fail on Windows** (`OSError: [Errno 22]` writing a file another process held for a moment, likely the dev server's watcher): the planted-fault runner crashed once and left one fault in `gatewayBins.js` until it was restored by hand and checked by its tests; the runner now retries both writes. After any crash of a tool that edits files, read `git diff` before anything else.
- **Testing Library's `act` holds a parent's render until its scope ends**, so a test of "the parent re-renders before the child's async continuation" passes vacuously unless an `act` ends between the two (a gate the test opens, and an assertion that the order really happened). Round 2's survivor R2-18 was exactly that.
- **A comparison with NULL in PL/pgSQL is NULL, not false**: `v_cand_fp = v_root_fp` with no root in the report leaked NULL into `kept_confirmed` and `in_use`; write `x IS NOT NULL AND x = y`. Found by the rehearsal, not by reading.
- **Bash heredocs bit twice more** (a test title's `\'` lost its backslash, so a search missed; an unquoted heredoc ran the backticks in a sentence as commands, harmlessly). Script files written with the Write tool, as the brief says.
