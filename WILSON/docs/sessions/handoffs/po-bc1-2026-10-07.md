## The API for BC2 and BC3

**The three sentences the next two bundles must open with:**

1. The footage never moves. A cloud clip is a footage LOCATION (the company's share, saved once by its network address, `\\server\footage`, and named) plus a path inside it; WILSON records where the file is and reads it from there on a computer that can reach it. Nothing uploads, nothing costs footage storage (B1, B2).
2. A clip's small picture goes to the cloud only while the company's admin has turned "Allow files to be viewed from outside the office network" on (B4, B5a). The database refuses the upload while it is off; the client asks the switch first so a person reads a sentence, not a storage error. A teammate on the office network makes their own picture from the file.
3. Reviewers may do everything members may in bins (B6): the gate for all four tables is `can_edit_shot_lists()`, and `project.bins.write` in the client matrix mirrors it. Removing a clip or a bin removes rows, never a byte on the server (B10), and the undo puts the rows and their takes back.

### The location model

- `bin_locations` — per WORKSPACE: `{ id, workspace_id, name, unc_path, added_by, created_at, updated_at }`. `unc_path` must be a network address: two leading backslashes, a server and at least a share, segments free of `\ / : * ? " < > |`, no `.` or `..` segment, no trailing backslash, at most 1024 characters; never THIS computer (`localhost`, `127.x.x.x`, `0.0.0.0`) and never an administrative share (`C$`, `ADMIN$`, `IPC$` — `\\localhost\C$\Users` is `C:\Users` in disguise; a hidden share like `footage$` is ordinary) (the CHECK `bin_locations_unc_path_shape_chk`; the desktop's and the fixtures' `isUncPath` refuse the same list); unique per workspace compared lower-cased (`bin_locations_workspace_unc_key`); name and address stored trimmed. Every active member of the workspace reads them; anyone past `can_edit_shot_lists()` on a project of the workspace they can see writes them. A location that still has clips cannot be removed (`bin_files_location_fk` is ON DELETE RESTRICT; the sentence is "This location still has clips in it — move or remove them before taking it away.").
- `bin_files.location_id` + `relative_path` — the path inside the location, forward slashes, no leading or trailing slash, no empty segment, no `.` or `..`, no backslash, no colon (the CHECK `bin_files_relative_path_shape_chk`); a frame sequence names its FOLDER. The composite FK `(location_id, workspace_id)` keeps a clip on a location of its own company.
- Resolving on a computer: `unc_path + '\' + relative_path with '\'` — the same string on every computer on the network. The per-computer fallback (B2: the share seen as `Z:\`) is a LOCAL path registered with the Local Server for this computer only (below); it lives nowhere in the cloud.
- `online` is never stored. A backend that cannot say what this computer can reach (the cloud, in a browser: `capabilities.resolveFiles === false`) has its rows marked `online: false` by the provider — "not on this computer" (B3): the clip shows with its details, can be logged, flagged and assigned, and cannot be played. BC2 fills `online` from the Local Server's `resolve` route and should expose `resolveFiles: true` in its composite capability object.
- `poster_path` — the picture's key in `rabbit-thumbnails`: `projects/{project_id}/bin_files/{bin_file_id}/{ts}-{name}` (the CHECK `bin_files_poster_path_shape_chk` keeps it under the row's own project's `bin_files` prefix). ## 5. Traps hit

1. **`tap-hosted.py` runs only the suites you name.** An older suite that pins a SET — 72's "exactly the twelve project-scoped tables" — fails only in CI. Before restating `fn_realtime_broadcast` (or any function an older suite names), run `grep -rln "<function>" supabase/tests/rls/` and rehearse every hit with the new migration prepended. The same goes for policy COUNTS on `storage.objects` (`rabbit_thumbnails%`, `rabbit_files%`, `petal_%`): 0091 added four and pins the new numbers itself.
2. **CI runs the Electron route tests on Linux.** `process.platform`, `path.sep`, `path.resolve` and a Windows-only `path.win32.join` give different answers there; `resolveCloudFilePath` now decides by the ROOT's shape. When a route test only passes on Windows, the annotations endpoint says so before a log can: `GET /repos/pretty-aud/wilson/check-runs/<id>/annotations` is public (the job LOG endpoint needs admin rights; `gh` is not signed in here). The pgTAP annotate step greps `could not` and so flags two passing probes of 57 and 80 as failures on every red run — read the `# Failed test` line, not those.
3. **The plants runner under cp1252.** Python's stdout on this machine is cp1252; a verdict line carrying `⎯` or `…` raises `UnicodeEncodeError` and the runner dies after its `finally` restored the file — the tree is clean and the log is empty. Run every scratch script with `python -X utf8`.
4. **A no-op plant survives and means nothing.** P4 removed `?? null` from a value the destructuring default already made null. Before calling a plant a hole, ask whether the code still behaves the same; the stronger plant (default gone too) was caught by the existing probe.
5. **The reviewer's model is the brief's rule, not the session's.** The brief demanded Opus 5.5 for the session and `model: "opus"` for both reviewers; the session ran on Fable 5.1 at Audrey's word and the reviewers on Opus as written.
6. **Private-project probes refuse for the wrong reason.** An INSERT without `workspace_id` lets `fn_populate_workspace_from_project` fail first (or succeed through it), and a stripped suite cannot tell a missing hop from a missing column. Set `workspace_id` explicitly in the probe and the only thing left to refuse is the hop (B9, B13).
7. **A data-changing function inside a probe's query sees that query's snapshot.** The take RPCs' invariant (one primary per shot) looked broken when asserted in the same `SELECT` that called the RPC; it holds when the call and the read are separate statements. pgTAP's `lives_ok` then `is`, never `is((SELECT rpc()) ...)`.
8. **`IS DISTINCT FROM ANY (ARRAY[...])` is not SQL.** `COALESCE(x, '') NOT IN (...)` is. And a `FOUND` after an `UPDATE ... WHERE` that matched nothing (a sole take has no sibling) reads false for an innocent reason — probe the write up front (`UPDATE ... SET updated_at = now() WHERE id = p_id; IF NOT FOUND → 42501`), then do the work.
9. **A data-modifying CTE cannot feed `INTO`.** `remove_shot_takes` reads the rows under the caller's filter first, then deletes; a caller who sees none gets P0002, one who sees them but cannot delete gets 42501.
10. **`new URL('./x', import.meta.url)` under jsdom** throws "The URL must be of scheme file"; pin a source file with `path.resolve(process.cwd(), ...)` instead.
11. **A python heredoc eats `\'`.** The matrix test's reason sentence lost its escape and the file failed to parse; the brief's rule stands — any text with a backslash or an apostrophe goes through Write/Edit.
12. **The desktop app and `supabase db query --file` under `supabase/migrations/`** (S3a trap 8): the apply was allowed this time — `supabase db query --linked --file supabase/migrations/0091_bins_on_the_cloud.sql` ran from the worktree's `WILSON/` folder without a prompt. The kit path stays the fallback.
13. **The browser pane.** Clicks need a `read_page` first ("ref map not initialized"); `get_page_text` reads the D.O.G. `<main>` before the tab; screenshots time out while the pane is hidden — `find` proves what is on the page.
14. **`storage.protect_delete()` on hosted Supabase refuses a direct DELETE on `storage.objects`** (42501, "Use the Storage API instead"); the older suites therefore pin their delete policies by catalogue shape only. The trigger honours its own override — `SELECT set_config('storage.allow_delete_query', 'true', true);` for the transaction — and a suite that sets it runs the REAL policy (94's probes 51/52). CI's local stack starts without storage-api and has no such trigger; the setting is harmless there.
15. **A breaker that removes a CREATE POLICY but leaves its COMMENT ON POLICY aborts on 42704** ("policy does not exist") — the wrong reason, which reads like a catch. Plant the DROP, the CREATE and the COMMENT together (B18's second run).
16. **`typeScale.test.js`'s CONTROL times out under load** (6.2 s against a 5 s limit when another vitest or the reviewer runs beside it); alone it passes in under a second. Not a failure of the bundle; run the file alone before believing it.
