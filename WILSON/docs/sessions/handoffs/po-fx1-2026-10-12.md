## 5. Traps hit

- **The brief's review file is the wrong part.** It names `docs/design/review/r-a-b-b-i-t-part-2.md` for "the overhaul's rules for the shots table"; part 2 is the Timeline. The shots table and the popups are **part 3** (R3-26 the inline controls' rest state, R3-36 the popup groups, the Hick's Law hotspots).
- **`src/ui/kit.css` does not exist.** The kit's rules are in `src/index.css` (`.ui-input`, `.ui-input[data-size="sm"]`, the hover and disabled rules); there is no kit number-input rule.
- **"takes" is not a number field.** The brief lists it; the shot rows' takes are chips (`ShotTakeChips`) and the shot popup's takes panel has no number field. The Bins inspector's Take number is the Bins tab's, outside this brief.
- **The spinner never overlapped the digits.** Read through the DevTools protocol (`DOM.getDocument` with `pierce: true` exposes the user-agent shadow root), the input's editing area ends exactly where Chromium's spinner starts. The defect was the room left: four figures flush against it, longer ones clipped from the end ("12345" and "123456" both read "1234").
- **No `.env.local` means no Supabase client.** `createClient('')` throws "supabaseUrl is required" and the page stays blank. The launch entry sets `VITE_SUPABASE_URL=http://127.0.0.1:9` (a port Chromium refuses: `ERR_UNSAFE_PORT` in the console is that) and `VITE_SUPABASE_ANON_KEY=fixtures-only`; the fixtures answer everything in memory.
- **The app stops the preview server when a turn ends** ("was stopped by the app"). Start it again with `preview_start` before any script; a script against a stopped server fails with `ERR_CONNECTION_REFUSED`.
- **"Scenes" is two tabs.** The page's own strip and the toolbar's Content tabs both have one; a script needs `getByRole('tablist', { name: 'Content' })`.
- **React puts a refused controlled value back only once the event it was offered in has finished.** A step dispatched inside a `pointerdown` handler is nested in that event's batch, so right after `dispatchEvent` the field still shows the refused figure; the hold reads whether a step stood at the next beat, never inside the step.
- **Home's document keys (P1-03)** took ArrowUp / ArrowDown on every page until FX3's `35265888`; measured on FX1's branch before the merge (the arrow keys did nothing; ArrowUp then Enter opened `/settings`). After the merge they step these fields natively. A script or walkthrough written on a branch without FX3 will say otherwise.
- **The Bash tool halves backslashes** in heredocs and `node -e` strings (the brief's trap, hit twice: a broken JS string and a failed replacement). Files with escapes go through Write / Edit.
- **A planted-fault run rewrites source files while it runs.** It restores each byte for byte, so an edit made to a mutated file during the run is lost; edit only docs while one runs. Its final `git diff --stat` comparison also reports any docs edited meanwhile.
- **The machine is loaded by other sessions.** A plain `npx vitest run` timed out 6 to 41 tests in files outside FX1; `--maxWorkers=4` gave a clean run. Re-run failures alone before believing them.
- **A reviewer can leave a browser running.** Round 1's tried the installed Firefox on a profile in the scratchpad and left two processes holding it; the scratchpad would not empty until they were stopped. Brief a reviewer to close what it starts, and check for its processes before cleaning up.
- **Line endings.** The checkout is CRLF (`core.autocrlf=true`), the Write tool writes LF, blobs are LF either way; `.mjs` is pinned LF by `.gitattributes` (a CRLF hashbang breaks Vite's transform).

## Known limits (named, not broken)

- **Seven figures or more scroll in the tables' field** while focused (six fit whole); the title always has the whole number. A million frames is 11.6 hours at 24 fps.
- **The chevrons are 14x12 CSS px**, under WCAG 2.5.8's 24px; typing is the equivalent control (the exception), as it was for the browser's spinner, whose parts were about the same size (15px wide).
- **The title is also the field's accessible description**, so a screen reader can read a capped number twice (the value, then the title). The brief asks for the title.
- **Under forced colours (Windows High Contrast)** there is no cap: six figures show whole, seven or more end in the field's own ellipsis; with the pointer on a chevron the field's Highlight hover edge falls back to the plain edge, and a hovered chevron's fill does not show (a system colour in the lane sheet is what its §6 guard forbids).
- **Firefox and Safari were not measured** (Playwright here has Chromium only). By the engines' documented behaviour, `appearance: textfield` hides Gecko's spin box and the `-webkit-*-spin-button` rules hide WebKit's.
- **A held chevron writes one undo entry per step** and the history keeps ten, so holding for 0.7 s leaves nothing earlier to undo (OUTSTANDING, `RabbitProvider`'s; the browser's spinner did the same).
- **The wheel steps a focused, pointed-at field** (+1 a notch), as the browser always has on number fields.
- **At 1280x700 a scene's shots run past the window's right edge**, as before FX1 (the nest is laid out to fit 1440); the Frames field is reached by scrolling the table sideways.
