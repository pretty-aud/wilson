## 3. Done and verified

1. **The mechanism, measured.** `serveClip` (`gateway/src/doors/clips.mjs`) counted a response into its viewing in `done()`, which runs on the pipeline's end: the response's `finish`, after the socket's write callbacks. The harness's `request()` resolves on the client's `end`, which needs only the bytes. Nothing orders the two, so the test's `W.clock.t += 60_000; tick()` could run between them and close the row (`lastAt` still the second request's, exactly 60 s before) with the second range missing. The test already consumed the whole body before the tick; the brief's first branch (await the body, then tick) was already true, so the race is the door's: it could close a row before a response it had fully answered was counted. Not Linux's alone: rarer on this machine, which fits its never having shown in a Windows suite run.
2. **The fix (`3a3ecd88`).** The counter transform calls `viewings.served()` for each chunk before passing it on, where `sent` and the outside bytes budget count it, so the client cannot hold a byte the row lacks. `served()` no longer moves `lastAt`; the new `settled()`, from `done()`, does, as `served()` did there before (a response's end is activity, when it served bytes). Totals, offsets, coverage, the 60 s and five-minute rules and the `clip_served` log line were unchanged by it (the five-minute rule went later, item 6); an over-budget chunk is counted as before.
3. **The control.** *"the row holds every byte the client has, even when the response's own end lands after the idle check (the control)"*: `makeWorld`'s new `onRequest(req, res)` hook lets it hold the second response's `finish` and `close`, so the door's `done()` cannot run before the tick. Red on `a351adc8`'s gateway with the CI figures (10 of 10, and once more with the final file), green after. Its waits allow 10 s and the test 30 s, so a slow runner is no failure. Item 8 reshaped it for D7's new rule, under the same name.
4. **The flaky test** now also asserts both ranges arrived whole (206, 524,288 and 524,305 bytes), so a cut response can never pass for this race again.
5. **The first record (`5128e020`).** OUTSTANDING: the dated line closing the CI-flake thread under the gateway's tests entry (the entry stays for the Windows time-outs and the journal's EPERM); a new entry, *A response open longer than the idle minute is counted only up to its viewing's close* (removed again by item 9); the session log's row.
6. **Audrey's answer, built (`b8b4ccd7`).** `viewings.mjs`: a viewing counts the responses it is serving (`begin` adds one, `settled` takes one off). A row is over only when none is being served and a minute has passed since its last request or response; the five-minute row is gone. The door bounds a response, the row does not: a connection that moves no bytes for a minute is closed and a stream lives four hours at most, so a pause longer than about two minutes ends the row. A row ended while a response is still being served (the door closing, the gateway stopping) ends at that moment. What follows from the rule, written in the design's GWF entry: a long play reaches the admin's table once it ends, not every five minutes while it runs, and a gateway that crashes mid-play loses that play's counts (its row is flushed as *incomplete*), not just the last five minutes'.
7. **Every response settles once.** `clips.mjs`: the normal end, an empty clip and a throw before the pipeline each settle the viewing, once-guarded like the slot releases; without that a row would never end. A test of all three (and a client's cut) is red with either new settle removed.
8. **The tests that move the clock wait for the door's own end.** A response the door has not finished now holds its row open, so the flaky test, the control and `runtime.test.mjs`'s posted viewing wait for the `clip_served` line before the idle minute. The control now shows the idle check closing nothing while the second response's end is held, the row counted whole while open, and the row ending a minute after that end.
9. **The record.** The design's §6 D7 changed in place, its decision list's D7 annotated, and a GWF entry in the review history; OUTSTANDING's entry removed as fixed, the dated line's last sentence and the session log's row updated, and a dated line on the afternoon's time-outs outside the gateway (§5); markers 4 → 4; `gateway/test/gw4Docs.test.mjs` and `docs.test.mjs` green.
