### 🚨 A real Playwright hazard, found during that merge and not this session's to fix

`getByLabel('Email')` and `getByLabel('Username')` are **no longer unique
anywhere in the signed-in app.** `App.jsx` mounts every page and hides the
inactive ones with `display: none`; `DashboardPage` keeps all three tabs
mounted deliberately (the notes editor must not lose its Y.Doc); so D1's
`ProfileSection` and its two inputs are live in the DOM from the moment a
member row loads. Playwright strict mode counts MATCHED nodes, not visible
ones, so `.fill()` resolves to two elements and throws.

It is masked today: the only `getByLabel` calls that run after a completed
sign-in are `auth.spec.ts`'s invite scenario, behind
`test.skip(SKIP_EMAIL, …)` with `PLAYWRIGHT_SKIP_EMAIL: '1'` set in
`.github/workflows/rls.yml`. Every other one is pre-auth. **It bites the first
local mailpit run.** `{ exact: true }` does not help — both labels are already
exact; it needs a scoped locator (`page.getByRole('dialog').getByLabel(…)`),
which is a spec edit and `tests/e2e/auth.spec.ts` is not this session's file.
`authSelectors.test.js` now asserts the mount chain and fails with
"hazard (d) is now LIVE in CI" if a lane moves a `getByLabel` into the ungated
scenario.

## 5. Traps hit

1. 🚨 **`preview_start` runs in the canonical checkout, not in this worktree.**
   It launched `npm run dev` from `C:\…\wilson\WILSON`, so the Browser pane was
   showing **Audrey's `feat/demo-2026-09-11` working tree** — pre-F1 code, with
   Tailwind's default `--font-sans`. Ten minutes went into "why is the restyle
   not applying". The tell is one line: `getComputedStyle(document
   .documentElement).getPropertyValue('--font-sans')`; if it is not the Geist
   stack you are not looking at your own branch. Adding a config to the
   worktree's own `.claude/launch.json` did not help — it still ran in the
   canonical checkout. The fix is to start Vite from the worktree with Bash on
   its own port and point the pane at it with `navigate`.
2. 🚨 **A comment can break a source-text test.** Three times. `devAutoLogin
   .test.js` asserts the string `VITE_DEV_AUTOLOGIN` appears in exactly two
   files, so writing it in a comment in `AuthShell.jsx` failed the suite; the
   new "no hand-written mono stack" assertion failed on a comment that *named*
   the stack it had removed. Both are the tests working correctly. Describe a
   deleted string; do not reproduce it.
3. **The kit's light hover drops the ink.** `.ui-btn[data-variant="ghost"]
   :hover` sets `color: var(--color-ink)` at (0,4,0); the `[data-surface=
   "light"]` block that would take it back is (0,3,0) and its hover rule sets
   only a background. So a hovered **ghost on a light surface** paints
   `#f5f0ec` on orange at **2.10:1**. `.ui-iconbtn`'s light hover rule has the
   `color` half; `.ui-btn`'s does not. Round 1 walked straight into it while
   fixing something else. **K8.**
4. **On a light surface the kit gives `danger` and `secondary` identical
   declarations**, so a destructive confirm pair was two identical buttons.
   There is no light-surface destructive treatment in the token set at all —
   `--color-danger` is a dark token and the plan draws no status colour on
   `#f4a261`. Separate by **fill**, which no cascade can undo. **K7.**
5. **An inline style beats the global `:disabled` cursor.** Restoring a lost
   `cursor: pointer` as an inline style made a disabled control show a pointer.
   Cursors belong in classes (`cursor-pointer disabled:cursor-not-allowed`).
6. **`.ui-dialog-error > span` truncates.** `white-space: nowrap` plus an
   ellipsis, with the full text only in a `title` a keyboard user cannot reach.
   At `width="form"` about 43 characters survive. **K5b.**
7. **The `AuthShell` consumer list was wrong and the geometry depended on it.**
   `MfaEnrollGate` mounts the shell from `MfaSection.jsx` and was not listed,
   so the first derivation fitted the well to the second-tallest screen. If you
   add a consumer, re-measure.
8. **The content slot outranks the bars** (`zIndex: 53` against `52`), so
   content taller than the well spills *over* them and keeps rendering in an
   ink that also works on the bar orange. An overflow here is a composition
   problem, not a clip. Worth knowing before treating one as an emergency.
9. **Playwright's `getByLabel` matches substrings.** `getByLabel('New
   password')` also matches `aria-label="Confirm new password"`. Pre-existing,
   recorded in `authSelectors.test.js` as a known collision so a *new* one
   fails.
10. **A hand-rolled comment stripper is not worth writing.** Round 1's broke on
    an apostrophe in JSX text (`We'll email a reset link.`), leaving 33 comment
    lines in the corpus it existed to clean. `esbuild` does not strip comments
    without also destroying character offsets; `@babel/parser` plus blanking
    the reported comment ranges does both.
11. ⚠️ **`authSelectors.test.js` imports `@babel/parser`, which is
    transitive** — `@vitejs/plugin-react` → `@babel/core` → `@babel/parser`,
    one entry in the lockfile, no version conflict, resolves today. It was left
    transitive rather than churning the lockfile in a UI session. If a future
    install hoists it differently the test fails loudly and naming it a direct
    devDependency is the one-line fix.
12. **A reviewer that is told to attack will over-reach.** Several round 2
    findings were wrong and were argued down rather than applied; one agent
    correctly refused an instruction of mine (that `esbuild`'s `jsx: 'preserve'`
    strips comments — it does not) and proved it with a table. Read the
    disagreements, they are where the value is.
