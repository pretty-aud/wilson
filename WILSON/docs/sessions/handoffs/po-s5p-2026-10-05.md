## 5. Traps hit

1. **The app's worktree had an untracked `.claude/launch.json`** at its
   root; the integration branch tracks that path, so the checkout refused.
   Moved to the scratchpad (not deleted), then the branch checked out.
2. 🚨 **A plain function captured by a memoized callback keeps its render's
   values.** `scrollDetailToDay` was a function declaration;
   `scrollDetailToDate = useCallback(…, [overviewSpan.start])` captured it
   afresh only on a schedule rebuild, so the minimap's click used Week's
   22px a day at every zoom from the Timeline's opening (at Day zoom 207
   days early with weekends SHOWN — nobody had measured the end date at
   another zoom). Any function a `useCallback` calls must itself be a
   callback on what it reads.
3. 🚨 **A jsdom harness hides that bug unless the context's arrays are
   stable.** `ctx?.assets || []` makes a new array each render when the mock
   leaves `assets` out; `buildSchedule` then recomputes, `overviewSpan.start`
   changes identity every render and the stale callback is re-created — the
   test passes on broken code. `timelineWeekends.test.jsx` gives every array.
4. **TimelineView reads `TODAY` once, at import.** A test that fixes the
   clock must do it before the dynamic import (`vi.useFakeTimers({ toFake:
   ['Date'] })`, then `vi.setSystemTime`), and fake only Date so React's
   scheduler keeps its timers.
5. **Chromium rounds `scrollLeft` to a whole pixel at 1x** (the app read
   back 12483 for 12482.9) and clamps it when the chart narrows; a scroll
   event follows a tick later. The jsdom stub does all three, or a test
   passes on a scroll the browser would never hold — and a test's own
   rounding of a window edge must avoid an exact half (the click test parks
   the gantt at today + 0.3 of a column for that).
6. **The state shots' dependency arrow is not deterministic before the
   first re-render.** In the shots taken before the first zoom click (01–08
   but 04, whose hover re-renders the gantt), one dependency arrow's box
   differs by 40–60px between two runs of the SAME code. Compare two runs of
   the new code before blaming a change.
7. 🚨 **A stale weekend mask hides from the left date.** A mask built from
   the old span start is stale only when the span keeps its length (the
   whole phase moved), and the left date shows it only where the weekday
   counts at the chart's two ends differ (−3, −2, +4, +5 here, not +1 or
   +3). Read the header the pane draws, not just the date at the edge.
8. 🚨 **An instrument that only watches motion passes a jump** (S1's trap 2,
   again, in this session's own slide script): "some frame had
   `data-animate`" and "every frame between the ends" both hold for an
   outline that never moves. Judge the committed box, the element's
   identity, all edges, and require a frame strictly between.
9. **A probe that clicks the minimap must find EMPTY minimap**: after a jump
   that works, the window covers the date it was sent to, and a second
   click there lands on the window. The probe parks the window at Today
   first.
10. **Plants that never touch the worktree.** Rendered tests: a scratch
    Vite config whose `load` hook serves a planted copy of a module
    (`SWAP_FILE` / `SWAP_MAP`); the app in the browser: Playwright
    `page.route` on the module's URL, rewriting the transformed JS. Both
    used by the reviewers and by S5p; nothing in the tree changes.
11. 🚨 **Edit nothing in the worktree while a probe runs.** The dev server
    reloaded the page under the final run when S5p wrote the docs beside it
    (the weekends probe died on "Execution context was destroyed … a
    navigation" at 1440 and timed out at 1280; the 1280 state shots lost the
    settings drawer from shot 27 on). Re-run undisturbed, everything passed.
    Write the docs before or after the probes, never during.
12. **Copy comment text exactly when editing, and write backslashes with

## For the Timeline's version-control session (S5d)

What S5p leaves in `TimelineView.jsx` that a version picker on the Timeline
must respect:

- **The anchor.** Where the gantt is, is a DAY: `anchorDayRef` (a day
  position from `overviewSpan.start`, fractional) and the state
  `detailStartDay`. Every write of the gantt's `scrollLeft` is followed by
  `anchorDayRef.current = dayAtX(el.scrollLeft, DAY_PX, maskDays)`; the pin
  in `rabbitTimelineCss.test.js` (`scriptedScrolls`) counts four writes,
  each recorded — a fifth (say, "open this version at its start") must
  record too, and the pin's count changes with it. To move the gantt to a
  date, call `scrollDetailToDate(date)`; never compute px from days by hand.
- **No arithmetic on the scale.** The only `* DAY_PX` / `/ DAY_PX` left is
  the unmasked chart width (`chartW = totalDays * DAY_PX`); `pinConversions`
  fails on any other. Conversions go through `timelineMinimap.js`'s pair
  (`dayAtX`, `xAtDay`, `visibleDayRange`) with `maskDays`.
- **The mask.** `dayMask` is built in `TimelineView` from `hideWeekends`
  (`weekendMask(overviewSpan.start, overviewSpan.days, DAY_PX)`) and handed
  to `DetailPane`, which builds none. A version that changes the schedule
  changes `overviewSpan`; the re-anchoring layout effect keeps the date
  through a span move, a zoom and the weekends switch (its deps:
  `overviewSpan.start, DAY_PX, hideWeekends, maskDays`). Opening a version
  whose rows are set aside (S5b's `set_aside_at`) moves the span the same
  way; nothing more is needed for the gantt to keep its place — and the
  span-move tests in `timelineWeekends.test.jsx` are the guard.
- **The geometry the scroll listener reads** (`geometryRef`) is written in
  a layout effect, at commit. If the picker introduces a transition,
  Suspense or `<Activity>` around the Timeline, that is what keeps the
  listener in step; leave it there.
- **The toolbar.** The "Shot list:" label's cap is the room the toolbar
  leaves: `max(96px, 100vw − 1100px − (tabs − 4) × 38px)` (S3c, measured);
  a version dropdown comes out of the 1100, and `timelineShotLists.test.jsx`
  holds that number. S5p added nothing to the toolbar.
- **The undo keys.** A popup the picker opens is one of the page's own
  dialogs only while it renders: count it in `ownDialogsRef` then (S3c's
  "For S5"), or Ctrl+Z stands down under it.
- **Measure it.** Before and after, at 1440x900 and 1280x700:
  `node scripts/timeline-weekends-probe.mjs <port>` (exits 1 on any moved
  date; the gantt's dates read off its header, the window's off the
  minimap's own lines) and `node scripts/timeline-window-slide.mjs <port>`
  (exits 1 on a wrong box, a jump or a re-created outline).
