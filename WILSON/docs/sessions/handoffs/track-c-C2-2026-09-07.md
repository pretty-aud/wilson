## 5. Traps hit

- 🚨 **A certificate code can already be taken by another track, in the file
  you are editing.** `WIL-7009` was free in the handbook's Appendix B and in
  `git log` on this branch, but Track A's merged A1 uses it for the setup-link
  certificate inside `operator-workspaces` itself — the same file this bundle
  edits. Grep the FUNCTION and every track's docs, not just the handbook,
  before minting a code. (R1 found it; nothing else would have.)
  ⚠️ **For the controller / Track A:** Appendix B still has **no row for
  `WIL-7009`**. Track C did not add one — it is Track A's code and their edit
  to make — but a reader chasing 7009 from the operator's Audit view finds
  nothing. The `WIL-7012` row says so explicitly in the meantime.
- **A certificate written after the state it certifies can be orphaned by a
  crash.** `sweep_open_uploads` COMMITS its rows; anything that certifies them
  later can die in between, and the retry sees nothing left to certify. The
  durable shape is to read the record back from where it lives
  (`file_events`) rather than to trust what the closing call returned — which
  also makes the certificate mean "everything this tenant had", the stronger
  claim. R2 found the first version of this; R1 had only narrowed the window.
- **A certificate must be written where a crash cannot orphan it.** The
  reservation sweep COMMITS its rows before the Edge Function's blob work; a
  certificate written after that work would, on a retried teardown, find
  nothing open and let the CASCADE take the first run's records. Write it
  immediately after the state change it certifies.
- **`echo "$LIST" | grep -q "$t"` under `set -o pipefail` can turn a MATCH
  into a step failure**: `grep -q` exits on the first match, `echo` gets
  SIGPIPE, and the pipeline's status is failure. Write the list to a file and
  grep the file.
- **The desktop app's Bash tool only parses `EOF`-delimited heredocs** (C1's
  lesson, hit again): `<<'PY'` dies with "unexpected EOF". Write scripts with
  the Write tool. A `python - "$ARG" <<'EOF' … EOF` block DOES work.
- **`supabase db query` one at a time PER PROJECT**; dev and staging in
  parallel are fine. `tap-all` on staging: copy `scripts/` and
  `supabase/tests/` into the staging workdir and run it from there.
- **`tap-all.mjs` buffers everything when piped** — no output at all until it
  finishes, so a "hung" sweep is usually just running.
- **Re-applying an amended migration leaves the history row stale.** The
  recorded `statements[1]` is whatever was recorded first; re-running the DDL
  does not update it. Record it with an UPDATE (same dollar-quoted script) and
  re-verify `md5(statements[1])` against the file.
- **`npx esbuild --bundle --platform=neutral` with `--external:https://*`
  type-checks nothing but does parse the Edge Function** — the only syntax
  check available on this machine (no Deno). Use it after editing
  `supabase/functions/**`.
- **Suite 67 still cannot run through the hosted shim** (`col_type_is`
  unimplemented) — Track A's `ce0d73e` teaches the shim those helpers and is
  not on this branch. Expect it as the one QUERY FAILED in every hosted sweep
  until A1 merges; CI's real pgTAP runs it.
- A vitest **source pin that reads a file** must normalise CRLF: the working
  tree is CRLF under `core.autocrlf` and CI's is LF, so a multi-line regex pin
  passes locally and fails in CI (or the reverse). `readFileSync(...).replace(
  /\r\n/g, '\n')`.
