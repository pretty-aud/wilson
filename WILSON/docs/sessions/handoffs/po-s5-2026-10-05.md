## 5. Traps hit

1. **The app wrote an untracked `.claude/launch.json` into the worktree
   root**, which blocked `git checkout -b … origin/feat/…` (the branch
   tracks that file). Its three entries were already in the branch's copy;
   it was moved to the scratchpad, not deleted.
2. **A volatile function's write is not reliably seen by a subquery of the
   statement that called it** (pgTAP): `SELECT f() IS NULL AND NOT EXISTS
   (…)` can read the table from before `f` ran. Call, then check, in two
   statements (suite 91's probes 16–17).
3. **On the cloud a TRASHED row hides behind its SELECT policy, and an
   upsert by its id is refused** (ON CONFLICT DO UPDATE must see the row).
   The Local Server hard-deletes and the fixtures merge into the trashed
   row (which keeps its `deleted_at` unless the write clears it). Anything
   that "re-creates with the saved id" must clear the stamp AND have a
   new-id fallback with every reference remapped (S5-03).
4. **`vi.mock` of `dev/devFixtures` must spread the original** when the
   test also imports `dev/fixtures/install` (`installDevFixtures` lives
   there): `vi.mock(path, async (orig) => ({ ...(await orig()), devFixtures: () => null }))`.
5. **The plant runner must match line endings**: a multi-line plant written
   with `\n` silently fails to apply to a CRLF source (it reported "not
   unique (0)" for four plants until it learned to convert). The runner is
   `scratchpad/plant.mjs` (this session's), restoring every file byte for
   byte.
6. **`src/dev` may import only proven-pure app modules**
   (`devFixtures.test.js`): the fixtures now build their bids with
   `budgetVersionModel` and `budgetMath`, admitted with a proof that each
   imports nothing but `dates.js` (which imports nothing) — a planted client

7. **The budget page's old write path reloads the project after every
   version write** (`ctx.setActiveProject`), which clears the provider's
   history — the root of F12.4. Any new caller must use the mutators.
8. **A test that reads the bundle while a composite waits sees the
   composite's own optimistic writes** (`updateTask` paints the new value
   before its request answers): "nothing changed" is not witnessed by a
   field there. Witness the undo stack instead (`ctx.canRedo`), and check
   the step BEFORE the composite with a second undo — the first version of

- **The provider API** (`useRabbit()`), every call async, each ONE undo step
  and never a reload:
  - `createBudgetVersion({ name, summary, basedOnListId, roleRates })` —
    Save as new version: written from the live rows, then OPEN, and
    SELECTED unless a budget is active. Refuses an empty name.
  - `saveBudgetVersion(id, { roleRates, basedOnListId })` — Save into the
    open version (`basedOnListId` undefined keeps its list). Refuses the
    locked version.
  - `openBudgetVersion(id, { roleRates })` — Edit this version. Refuses
    the locked one and an old one (no timeline). A refusal part way keeps
    one undo step for what landed and says so.
  - `selectBudgetVersion(id | null)` — refused for another version while a
    budget is active. `renameBudgetVersion(id, name)`,
    `updateBudgetVersionSummary(id, summary)`, `deleteBudgetVersion(id)`
    (refuses the locked one; deleting the open one closes it).
  - `activateBudget(id)` / `resetToBidding()`.
  - `ctx.project.open_budget_version_id` is the open version;
    `selectedVersionOf(ctx.budgetVersions)` the selected; the lock is
    `project.budget_active && project.budget_active_version_id`.
  - `roleRates` = the Budget's live map: `buildRoleRates(rateCard.entries,
    rateOverrides.overrides)` (BudgetView already computes it). The
    Timeline does not load rates today: its version control needs them for
    "unsaved changes" and Save — mount a small component that calls
    `useRateCard()` / `useProjectRateOverrides()` only for people past the
    money gate (F10).
- **"Unsaved changes"** = `versionDiff(openVersion.snapshot,
  snapshotFromLive({ tasks, phases, milestones, project, roleRates }),
  { shotListId: openVersion.shot_list_id, liveShotListId: <the Select's value> }).isDirty`.
  Right after opening a version, tasks ADDED since it was saved make it
