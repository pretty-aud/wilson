### Rules for running tracks in tandem

1. **One worktree and one branch per track**, cut from `feat/multi-user-v1`.
   Each bundle merges into the branch when it passes review and her
   walkthrough (merge commits); each track merges the branch back in before
   starting its next bundle.
2. **Migration and suite numbers are pre-assigned per track** so parallel
   work cannot collide (the trap that has bitten twice): A takes 0067–0069
   and suites 71–73; B takes 0070–0072 and 74–76; C takes 0073–0075 and
   77–79; D takes 0076 onward and 80 onward. Gaps are fine; collisions are
   not. Bundles keep their migrations independent of each other.
3. **Shared files have one owner per bundle:** `App.jsx`'s session layer and
   `electron/main.cjs`'s server belong to Track B; `RabbitProvider` and the
   adapters to Track A; the storage functions to Track C. `rls.yml`'s
   `RLS_TABLES`: each track adds its own table names in the same commit as
   the suite (the guard needs both on one branch); Track C resolves the
   conflicts in that list when branches meet. Anyone else needing a change
   in an owned file asks the owner.
4. **Nobody runs `supabase db push` blindly.** 0065 is unapplied and must
   stay so; apply by hand with the throwaway-workdir recipe.
5. **Three real Claude Code sessions, not one session fanning out
   subagents.** Each bundle needs a human in the loop between build, review
   and walkthrough, and subagent fan-outs have overwritten a working tree
   before.
