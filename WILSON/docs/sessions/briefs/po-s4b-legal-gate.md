## What Audrey ruled

## The facts this design stands on (verified on the tip; re-verify as you read)

- **One definition of a locked folder.** `public.rabbit_money_segment(seg)` (0042) is `coalesce(upper(seg) IN ('INVOICES','FINANCE'), false)`: "the SINGLE source of truth for the reserved-segment list". It is read by: the eight `rabbit-files` storage policies (three base policies negate it, the money policies assert it with `can_access_project_money`), the eight `rabbit-thumbnails` policies (0053), `files_money_provider_chk` (0050: a money row — `is_financial` OR a money third segment — must have `storage_provider = 'supabase'`), `file_event_is_financial()` (0074: events for a money key are hidden from non-managers), `rabbit_quota_exempt_path` (0055, bounded by size in 0078), and 0076. A file's object key is `projects/{projectId}/{INVOICES|containerSeg}/{entityId}/{ts}-{safeName}`; the THIRD segment is the gate.
- **The row gate is narrower than the blob gate today.** `files_select` and `files_delete` are still 0038's; `files_insert` and `files_update` are 0083's; all four carry `(NOT is_financial OR public.can_access_project_money(project_id))` — the FLAG only, not the path. 0050's CHECK reads both axes "because either alone is a way in".
- **The client.** `supabaseAdapter.uploadFile` chooses the segment with `scope.financial ? 'INVOICES' : container.seg`, pins money to the Supabase provider in its private-project and network-workspace branches (`!scope.financial` tests), and writes `is_financial: !!scope.financial`; a guard refuses a custom segment that collides with INVOICES or FINANCE. `src/tools/rabbit_v0.1.0/fileTags.js` (S4a): `GATED_TAG = 'legal'`, `LEGAL_HINT = 'Not restricted yet: …'`, `DERIVED_TAG = 'finance'`, `tagSettable(id, { canWrite, canSeeMoney })`. The Files tab's toolbar has Add files (`{ type: 'project' }`). `FILE_COLUMNS` holds `tags`. The Local Server's folder categories and `resolveFileBaseDir` send `is_financial` files to an `INVOICES` directory; `projectFileStream.cjs` is the streamed upload; its PATCH merges any key.

## The invariants (the design may vary; these may not)

- **I1 — bytes.** A Legal file's object, and its thumbnail, are readable and writable only by callers who pass `can_access_project_money` for its project. Mechanism: `LEGAL` joins `rabbit_money_segment`'s list (one function body; the sixteen storage policies and their post-condition counts are not restated). Prove no object or `files` row with a third segment `LEGAL` (any case) exists on dev before the change, and make the migration's post-condition refuse to run if one does.
- **I2 — the row.** A Legal file's ROW (name, notes, tags, size, dates) is selectable, insertable, updatable and deletable only by the same people: all four `files_*` policies, USING and WITH CHECK both, DROP + CREATE (never add-beside: permissive policies OR together), each restated from its LATEST body (0038's select/delete, 0083's insert/update) plus exactly the new arm, with post-conditions that pin the four names and the whole predicates (S4a's trap 16: compare the definition as Postgres prints it, never `LIKE`). Recommended shape: read money-ness on BOTH axes in the row policies, as 0050 already does — `NOT (is_financial OR public.rabbit_money_segment(split_part(storage_path, '/', 3)))` — so the folder is the truth for rows too and a money-path row with a false flag stops being a way in. If you choose another shape (e.g. the tag in the predicate), justify it in the header.
- **I3 — Legal is set at upload and never after.** The `legal` tag and the `LEGAL` segment are created together and can never disagree: a table CHECK ties `'legal' = ANY(tags)` to the third segment being `LEGAL`, so tagging an existing file Legal fails, un-tagging a Legal file fails, and editing `storage_path` across the boundary fails or lands the row under the gate. The migration first strips a stray `legal` tag from any row whose path is not under `LEGAL` (S4a's label-only period; expect zero rows) and says how many it stripped.
- **I4 — Legal bytes never leave Supabase.** `files_money_provider_chk` covers the new segment by construction; `uploadFile` must choose the Supabase provider for a Legal upload on private projects (0072) and on network / s3 workspaces exactly as it does for `scope.financial`, and refuse with a plain sentence where it cannot.
- **I5 — nothing else names a Legal file to the wrong person.** Enumerate every path a `files` row or its name can travel and test each with a reviewer-role and a member-role probe: `file_events` (should follow the segment through `file_event_is_financial`; prove it), the realtime broadcast of `files` (0016 / 0061 / 0077 — if it sends row payloads to every project member, invoices already leak there: fix it for both or record it as a HIGH pre-existing finding with the measurement), `edit_history` (who may read a files row's history), the intake pipeline and the "core" flag (a Legal file must not be markable Core: its text would be extracted into project context everyone reads — refuse in the UI and with a CHECK), D.O.G.'s project attachments (`deckAttachments.js` excludes money; it must exclude Legal), the pet's knowledge index, search, exports, the `log_file_downloaded` RPC and `reserve_upload_bytes` (0083), signed URLs (`fileUrl` / `downloadUrl` / `thumbnailUrls`).
- **I6 — the quota.** `rabbit_quota_exempt_path` keys on the money segment, so `LEGAL` inherits the bounded exemption 0078 defines. Decide deliberately and write the decision in the header: Legal bodies MUST live in Supabase even on a workspace that pays for no Petal storage (I4), which is the same reason invoices are exempt; confirm 0078's size bound covers it, or state why a different rule is needed.
- **I7 — who may add one.** Only people who pass the money gate can add a Legal file (WITH CHECK on the row, the money INSERT policy on the object). Everyone else is never offered the option.
- **I8 — both backends, one behaviour.** The Local Server: a `LEGAL` folder category beside `INVOICES`, `resolveFileBaseDir` and `projectFileStream.cjs` honour `scope.legal`, the PATCH route refuses adding or removing `legal` in `tags`, the fixtures adapter matches; one sentence in the UI and the walkthrough says the Local Server cannot enforce it (no roles) and that the folder can be locked on the NAS.
