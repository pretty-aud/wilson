## Facts that will bite

- Move the untracked `.claude/launch.json` at the worktree root to your scratchpad before the checkout; never delete it. `node_modules` is absent in a fresh worktree.
- **The desktop's routes store whatever the renderer sends** (`rabbitSubentityRoutes`): the fixtures are in the cloud's shape and still break three of its CHECKs; the desktop's real rows are what you carry. Measure the writer, then the cloud.
- **An unknown key refuses the whole row** (PGRST204), and a refused parent skips its children; numbers past NUMERIC(14,2), (10,2) or (7,3) give 22003, extra decimals round silently, an empty string gives 22P02 in a number and 22007 in a DATE.
- **`workspace_id` is filled by trigger only when it is null** (0004): never send a desktop workspace id.
- **The money gate is RLS**: a migrator without it is refused row by row; that refusal is a count and a sentence, never a failed project. Money-gated files never leave Supabase (0050 refuses the row).
- **`verified` reads by `project_id` and by `id`**: `task_links` has no `project_id`, `project_members` no `id`; do not reuse it blindly.
- **`withoutSetAside` assumes bid versions are never copied**: with versions carried, an open version sits beside rows that arrived live; measure what the cloud shows.
- **`ALTER TYPE … ADD VALUE`**: the new value cannot be used in the same transaction; the suite runs after the migration commits. **The two-directional guard** in `rls.yml` and `rlsSuiteLists.test.js` pin the suite names: a new suite is a change to both.
- **No session holds a password for any account on wilson-dev**: her desktop run is the real one; yours is the round trip on the fixtures plus rolled-back rehearsals on wilson-dev (one statement per call, `BEGIN … ROLLBACK` inside the file, the refusal's text quoted). Never `supabase db push`; the only committed writes are 0103's statements and its history row.
- `supabase db query --linked -f` prints only the last statement's rows, and a failing statement ends the file. The integration branch's ref moves under your worktree while others push (one `.git`): read it again right before the merge-in.
- The docs are CRLF: the Edit tool and `sed -i` are unsafe on the long ones; a CRLF-preserving helper with every anchor asserted once; count the HTML comment openers before and after in any long markdown file you touch. The Bash tool halves a doubled backslash in a heredoc: scripts go through the Write tool.

- A subagent can overwrite your working tree: assert the executable form with failing controls after each round; `git status` clean, HEAD unchanged, `node_modules` 748 after each.
