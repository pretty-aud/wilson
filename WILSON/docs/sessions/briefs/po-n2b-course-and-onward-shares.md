## Facts that will bite

- A SELECT policy that reads its own table recurses at run time; `subject_owner_id` on the row exists so the policy never joins. A recursive CTE inside a STABLE SECURITY DEFINER plpgsql helper is fine; bound its depth and stop at the first ancestor that is not `accepted`.
- The guard trigger checks the update arm against `OLD.id` one row at a time: a cascade arms, updates and resets per descendant row. `set_config(…, true)` is transaction-local, which is what a function wants and a pgTAP file must undo by hand (N2's trap).
- An HTML comment opener in a long markdown file silently hides everything to the next closer: count the markers in the design before and after (none today), and in OUTSTANDING if you touch it (four).
- The design docs are CRLF; Git Bash's `sed -i` turns a file LF; the Bash tool halves `\\` anywhere in a command; the Edit tool matches whole strings (re-read the exact lines before a long Edit, N2's trap).
- A migration string must not hold a dash pair: the post-condition's comment stripper is built from `chr()`; keep it that way in anything you add.
- `otter_subject_share_live_uidx` is partial on `(subject_id, shared_with)` for live rows: it is what stops a chain circling back, and it is why a batch skips rather than raises.
- Never `supabase db push`, never `supabase config push`; this session runs no query at all. A subagent can overwrite your working tree: `git status` after each round.
