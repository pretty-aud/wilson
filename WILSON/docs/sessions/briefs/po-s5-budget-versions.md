## The model, in one paragraph (make it legible on both pages)

A bid version is a **living document**, not a photo. One version per project may be **open**: the live Timeline and Budget hold its data, and every change made there is a change to it until **Save** writes it back into that version. **Save as new version…** is the only way a new version appears, and it asks for a name. A version can be **viewed** without opening it (read-only). One version per project may be **selected** (the one the variance measures against — today's `budget_versions.is_active`, a misnamed column: call it the selected bid everywhere in words and comments, never rename the column). One version may be **locked** as the active budget (`projects.budget_active_version_id`, `locked_at`, `locked_by` — "Budget active — in production"): it cannot be opened for editing, the Timeline dropdown is disabled with the reason, the live Timeline stays editable, Save as new version still works and the new versions stay unlocked, and the variance keeps measuring against the locked one. Three states, three words — open, selected, locked — and the design must never let a person wonder which of the three a control is about.

### 4. Open, edit, Save, Save as new (F2)

- **Open for editing** (from the Summary's details and from the Timeline's banner): ONE kit Dialog at the confirm width naming what it does ("Open Mid ROM · v2 for editing? Its phases, dates, days, roles and rates replace what the Timeline and Budget show now. Tasks added since it was saved stay."). If the open version has unsaved changes (step 5's diff is non-empty), the question is the three-answer one first — **Save to Mid ROM · v2** / **Discard changes** / **Cancel** (Cancel first and focused; Escape = cancel) — and only then the open question; if NO version is open and the live schedule differs from every version (a project that never saved one), offer **Save as new version…** / **Discard** / **Cancel** the same way, so nothing is lost unsaid.
- **Opening** writes the snapshot into the live rows as ONE undo step: phases (sub-phases included), each task's dates, bid days, role, position, status and links; the milestones (key dates); role rates, margin, contingency, agency; `projects.open_budget_version_id`. Tasks added after the version was saved stay as they are (her F2). A task the version holds that no longer exists is recreated from the snapshot (with its saved id where the backend accepts it, else a new id written back to the snapshot on the next Save); `logged_days` is never written. Read S3b's trap 12 and S3b's `deleteAsOneStep` before leaning on the provider's batch slot for this many writes. Opening also SELECTS the version (one fewer state to explain), unless a budget is active (then the selected bid stays the locked one, F9).
- **Save** writes the live rows into the OPEN version's snapshot (the new shape, totals, span, `delta`), `updated_at`; the version keeps its name and note. **Save as new version…** asks for name + note (the kit Dialog, Cancel focused), writes a new version from the live rows, opens and selects it (F2, F9). On a locked budget: the locked version cannot be opened ("Open for editing" greyed with the reason); Save as new version works and the new version is unlocked (F9).
- **The leave guard is NOT needed here** (nothing is lost on leaving: the live rows persist and the open version simply stays unsaved); say so in the help page so nobody adds one.
