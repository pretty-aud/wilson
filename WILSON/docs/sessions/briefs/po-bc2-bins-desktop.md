## The work, in order

1. **The desktop signed in knows what it can reach.** When WILSON runs inside the desktop app and the backend is Supabase, the provider's capability object becomes the composite — data from the cloud, files through the local process: `pickFiles`, `probe`, `stream`, `resolveFiles`, `openInOs` true, `relink` by locations, `posters` `'cloud'`. The predicate is "the desktop's file process is reachable" (`window.electronAPI?.rabbit` AND the Local Server answering), never the storage mode — say in the hand-off why this is not the `supportsManagedFiles` mistake (it picks no store). On sign-in and on every change of `ctx.binLocations`, the renderer registers the company's locations with the local process (`POST /api/rabbit/cloud-bins/locations`), with this computer's `local_path` where one is saved (B2's fallback, kept in the desktop's local settings, never in the cloud).
2. **Locations.** A settings surface (where the storage settings live) listing the company's footage locations — name, network address, who added it — with Add (name + `\\server\share`, validated as the database validates it, the refusal's sentence shown), Rename / Re-address, Remove (refused with its sentence while clips use it), and, per computer, "Where is this location on this computer?" for the drive-letter fallback. The first Add can also happen from the add-clips flow when a picked file lies in no known location ("Which location is this? Name it.").
3. **Adding clips from a location.** The OS picker and the folder walk (`prepareBinFiles`) now resolve each picked path to `{ location_id, relative_path }` — a path outside every location is refused with the sentence, never silently added; the adding computer fills the technical columns (`prepare` then `probe`: size, mtime, media type, sequence detection, duration, dimensions, fps, codec, timecode) and `addBinFiles` sends them; duplicates (B8) through `findDuplicateBinFiles` with Skip / Add anyway per file; the name parser's suggestions as today.
4. **Pictures.** A poster is made locally for every clip this computer can reach (ffmpeg or the renderer's decode, as today) and shown from the local cache; it is UPLOADED through `postBinFileThumbnail` only when `binsInfo.remoteViewing` is true — the client checks first, and a refusal (`remote_viewing_off`) is shown once, not per clip. When the switch turns on later, an "Upload pictures for clips without one" action offers the catch-up (count named); when it turns off, nothing is deleted (the plan: already-uploaded posters stay — say so).
5. **Play and scrub in place.** The preview panel and hover-scrub for cloud rows stream through the local process (`binFileStreamUrl` resolving `unc_path + relative_path`), with the same Range support, the same codec notice, "Open in default app"; a row this computer cannot reach is "not on this computer" (B3) with everything but playback.
6. **Offline and relink against locations.** `resolveFiles` marks each cloud row `online` by whether this computer can reach it; when a whole location is unreachable, one notice names it ("Footage NAS is not reachable from this computer") with "Where is it on this computer?"; relink by re-pointing the location (per computer), never by rewriting `relative_path` for everyone.
7. **The admin's switch (B5a).** In the company's settings, admins only: "Allow files to be viewed from outside the office network", off by default, with the storage design §4b sentence beside it (what turning it on means for a studio that needs TPN certification); everyone else sees its state and the sentence "Only a workspace admin can change…". Flipping it is `setRemoteViewingEnabled` (undoable).
8. **The Scenes tab's takes on the cloud.** `supportsBins` is now true on the cloud, so the shot popup's Takes and "Show in Bins" run there; check them, and `deleteShot`'s undo (BC1's Deferred: it does not put the shot's takes back on the cloud) — fix it in the provider as `removeBinFiles` does, with a test on all three backends.
9. **Help, docs, walkthrough 57** (adding from a location on the desktop signed in; a second computer seeing the same clips; a clip not reachable here; the switch off → no upload, on → the catch-up; play and scrub a clip on a network path; relink a location), screenshots at 1440x900 and 1280x700 into `docs/sessions/handoffs/img/po-bc2-*`. **Test on a real network path**: a share on Audrey's network if one is reachable, else a share stood up for the test (a UNC path, not a drive letter) — the measurements in the hand-off; if neither is possible, say so plainly rather than passing with a local folder.
