## The wire, fixed (the controller's, so GW1 and GW2 agree without talking; identical text in GW2's brief)

- **Enrolment token:** `wgt_` + 32 characters of base32 (RFC 4648 alphabet, upper case, 160 random bits). The cloud stores SHA-256 (hex) of the WHOLE string's UTF-8 bytes. 24 h, single use, spent by one `UPDATE … RETURNING`.
- **Gateway credential:** `wgc_` + base64url (no padding) of 32 random bytes; stored as SHA-256 (hex) of the whole string; carried as `Authorization: Bearer <credential>` on every gateway call.
- **Signing keys:** Ed25519 per workspace; `kid` is 1–16 characters of `[a-z0-9]`; the public half travels at sync as standard base64 of the raw 32 bytes: `signing_keys: [{ kid, public_key }]`; the previous key is accepted for ten minutes after a rotation.
- **The ticket:** claims object with keys in exactly this order and nothing else: `v` (the number 1), `kid`, `gw`, `ws`, `sub`, `clip`, `loc` (all ids lower-case UUID strings), `path` (the cloud's `relative_path`, forward slashes), `seq` (boolean), `mt` (the media type string the row holds; advisory), `rv` (boolean), `iat`, `exp` (integer Unix seconds; `exp = iat + 120`), `jti` (32 lower-case hex characters, 128 random bits). `payload` = base64url without padding of the UTF-8 bytes of `JSON.stringify(claims)` with no whitespace. `sig` = base64url without padding of the Ed25519 signature over the ASCII bytes of the string `v1.<payload>`. The ticket = `v1.<payload>.<sig>`. The gateway refuses a ticket string longer than 4096 characters before parsing; `iat` is the not-before; clock skew allowed: 30 s each way.
- **Renewal body:** `POST /v1/clips/<bin_file_id>/renew`, `Content-Type: application/json`, `{ "jti": "<the stream's first jti>", "t": "<the fresh ticket>" }` → 204 or 401.
- **The cloud's address:** the enrolment token carries no URL. Your Settings card shows, beside the token, the cloud's functions base (`<SUPABASE_URL>/functions/v1`) as `WILSON_CLOUD_URL` for the container story and as the installer's second field for the Windows story; the gateway's compiled-in default is prod's.
- **Test vectors:** in your FIRST commit, `docs/design/gateway-ticket-vectors.json`: a throwaway Ed25519 key pair (both halves; a fixture, never a real key), its `kid`, and five tickets with their expected verdicts: valid with `rv: false`, valid with `rv: true`, expired, for another `gw`, and one with a flipped signature byte. GW2 reads this file from your branch before its review round 2 and runs its verifier against it; GW3 reconciles whatever still differs.
