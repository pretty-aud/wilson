## Her rulings (2026-10-09) that the design must honour

G1 either host; G2 the gateway registers itself with the cloud and the web app learns its address, with a certificate the admin installs once per computer; G3 the company exposes it themselves (a port, a tunnel, or the NAS vendor's relay) — WILSON tells them what to open and checks reach, Petal never relays; G4+G5 served only to project people past the Bins gate (reviewers included), only bin clips of that project by the cloud's location + path, never a path the browser sends; **G6 only reads from OUTSIDE the network are logged** (who, which clip, when, how much; visible to workspace admins with the file activity; office reads are not logged); G7 browser-playable formats only, no transcoding; G8 the viewer's name drawn by the player over REMOTE playback; G9 self-updating with the version shown (updating by hand possible); G10 design first. And the standing ones: B4 (pictures leave the server only with the switch on), B5a (the switch, admins only, off by default, the TPN sentence at the control), B6, the four TS-2 conditions of §4b, A9.

## What the design must contain (one section each, in this order)

1. **The thing, in one page**: what it is, where it runs (G1's two shapes, one program), what it talks to (the cloud's database and auth; the company's share; browsers), what it never does (relay through Petal; read outside bin clips; copy, convert or cache footage; serve anything with the switch off from outside).
2. **Registration and discovery (G2)**: how the gateway proves to the cloud it belongs to THIS workspace (an enrolment token the admin generates once in WILSON's settings; what the gateway stores; how a stolen token is revoked), what it registers (its inside address, its outside address when the switch is on, its version, its reach per location), how the web app learns the address, and what the browser sees when the gateway is not running.
3. **The certificate story (G2)**: a self-made certificate on first run and the one-time trust step per computer, written for the admin in plain words; a company's own certificate when they have one; what happens on the day it expires.
4. **Reach from outside (G3)**: exactly what the company must open (one port, HTTPS only), the tunnel and NAS-relay variants, the reachability check WILSON runs and the words it shows; what the gateway refuses from outside while the switch is off (everything, provably — the §4b condition).
5. **Every read's checks (G4, G5)**: the sign-in token verified against the cloud's keys on every request; the project membership and the Bins gate checked against the cloud (how often it may be cached, and the longest a revoked person can still play); the clip resolved from the cloud's `bin_locations` + `relative_path`, never from the request; the location's share mounted read-only by the gateway's own account; allow-listed media types; Range reads only; rate limits; the `online` and reach-per-location answers BC3 needs.
6. **The audit (G6)**: a file event per remote read (who, clip, when, how much), written to the cloud as the other file events are, visible to admins; office reads not logged — and what "inside the network" means precisely (the request's source as the gateway sees it, the admin's declared office ranges, or both).
7. **Playback (G7, G8)**: what plays, what shows the picture instead, the player's name overlay for remote reads (drawn by the browser, the gateway tells it when a read is remote), the poster → stream hand-over BC3 left a seam for.
8. **Updates and health (G9)**: self-update from Petal with the version shown in the company's settings, a signed release, what happens to a half-updated gateway, and the health line the admin sees.
9. **The switch's enforcement, end to end**: the database's `remote_viewing_enabled`, the gateway reading it, the poster policies, and the proof that switch-off is identical to no gateway from outside.
10. **The threat model**: a stolen token, a stolen certificate, a malicious browser on the LAN, a renderer that lies about its location, a share path with traversal, a huge file, a flood, a revoked member mid-stream, a NAS relay that terminates TLS — each with the control that answers it, and which TPN control (v5.3) it maps to; what the design cannot promise and must say to a customer.
11. **The install story**, written twice: for a NAS (package/container) and for a Windows PC (a service), each as the admin will read it.
12. **The build plan**: the sessions (three to five), their order, their files, their numbers, what each proves before the next starts; the first session's brief in draft.
