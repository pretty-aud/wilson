## The one distinction the design must make legible

S3b gave a shot LIST its own order ("List order", Move up / Move down, live-saved like every other list change). An EDIT is a cut order saved as a version, held as a draft until Save edit. So: while a LIST is on screen, Move up / Move down still reorder the list, and a DRAG asks "Make a new edit from this list?" (her flow) and, on Yes, switches the tab to a draft edit; while an EDIT or a draft is on screen, drag AND Move up / Move down change the draft. Whatever you design, a person must never be unsure which of the two they are changing: the bar says what is on screen (S3b left room: "Shoot · v2 — edit: Director's cut · v3"), and the question's sentence says what Yes will do.

## Facts that will bite

- The schema exists: `edits` (items JSONB, one chain per list), `budget_versions.shot_list_id`, `tasks.scene_id/shot_id`, `assets.scene_ids/shot_ids`. No migration is expected; if one becomes unavoidable the next free numbers are **0089 / suite 91** (0087 and suite 89 were held and never used; leave them), proven with the hosted shim in a rolled-back run and handed to Audrey — the app's classifier refuses DDL writes from a session.
- `createEditFrom` refuses a second root or a branch ("this shot list's edits form one chain — a new edit continues from the latest one"): a draft started from an OLDER edit still saves as the chain's next edit, with the older edit's items.
- `saveEdit(editId, items, summary?)` writes the whole item array and a snapshot of the referenced shots' and scenes' names and numbers (`snapshot.shots[shotId].name`), so D17's "Missing shot: name" has a name to show; `updateEdit` changes an edit's title, version or summary. Neither delete sweep touches an edit's items (by design: `desktopDeleteSweep.test.js`).
- Every page stays mounted; a document or window key listener needs a page gate and an overlay check, and a bare Shift tap is the pet's. Enter presses the focused control app-wide since S2a.
- The kit Drawer is not on the overlay stack (S4a trap 10); the ⋯ menu must be S3b's `MenuButton`.
