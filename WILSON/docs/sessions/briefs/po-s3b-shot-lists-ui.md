## What this bundle is, and is not

It is the SHOT-LIST half of Audrey's Session 3 in the Scenes tab: seeing which list you are viewing, making a new list, picking one from a table, saving a version point, saving as a new version, making a list active, setting one aside and bringing it back, adding shots from another list, removing them from this one. The schema, the provider and all three adapters already exist (S3a); **you write views**.

It is NOT edits, drag-and-drop, the first-drop confirm, the pulsing Save edit button or the leave guard (all S3c), and NOT the Timeline, the Budget, the task popup, the asset relations or Bins (S3c owns `TimelineView.jsx`'s scene rows, `BudgetView.jsx`, `TaskDetailPopup.jsx`, `RelationsPanel.jsx`, `bins/shotTakeSelectors.js`). Nobody else is running: you have the tree to yourself.

## The work, in order

### 1. Make the tab safe for more than one list (before any new control)

S3a's "Deferred" list, the ScenesView part: project-wide facts must read `ctx.allScenes` / `ctx.allShots` — the next scene/shot number minting, "this scene's shots" in the single delete and the bulk delete (a shot held only by another list must not be cascaded away without its own undo), the scene and shot popups (`SceneDetailPopup`, `ShotDetailPopup` resolve their row through `ctx.sceneById` / `ctx.shotById`, so clicking a row of a non-active list opens it), and the task pickers inside those popups. Tests with a second list in the mocked ctx prove each (plant the old read and the test must fail).

### 2. The viewed list

A `viewedListId` per person and project (localStorage, the `rabbit_scene_saved_views` idiom; default and fallback = the active list; an archived or missing id falls back). Every table, gallery, group, tile and count in the tab reads `ctx.scenesOf(viewedListId)` / `ctx.shotsOf(viewedListId)`; "New scene" / "New shot" pass `{ listId: viewedListId }`. A new sort option "List order" (the list's own positions) becomes the default sort; with it selected, each scene and shot row gets Move up / Move down actions (`reorderShotListItems`; the takes panel's pattern — drag handles arrive in S3c). The existing number / name / status sorts stay.

### 3. The list bar (D7)

One row between the tiles and the toolbar, on the kit (`Toolbar` or the tab strip's geometry — choose with the design skills and say why; no new chrome invented). Left: what you are viewing — `Title · v3`, its summary on hover, an "Active" badge, or "Active: Other title · v2" beside it when they differ, "Archived" when you opened one from the archive, and "Not saved since changes" when the list changed after its last version point (or was never saved). Right, in this order: **New shot list**, **Shot lists…** (the two buttons she asked for), then **Save**, **Save as…**, **Set active** (hidden when it is already active; gated by `project.shotlist.activate` with the reason shown the GatedAction way). Hick's law: nothing else on the bar; Archive, Withdraw, Restore, Clear and "Add from another list…" live in the picker and in a small overflow menu on the bar.

### 4. "Shot lists…" — the picker (a kit Dialog at the `reading` width with a kit Table)

Columns: Active (mark) · Title · Version · Created (through `dates.js`'s `showDate`) · Summary · actions. Sorted newest first. A row click selects; double-click or the footer's **Open** loads it as the viewed list. Footer: **New shot list…** on the left (the create button she asked for inside the table view), Cancel, Open. Per-row actions by seat: Set active, Archive (managers/admins), Withdraw (the maker of an untouched list), Edit details (title, summary). Below the lists, a divider, then **"Not in any list (N)"** (only when `ctx.unlistedScenes` / `unlistedShots` are not empty: picking it shows those rows like a list, each with "Add to list…"), then **"Archived…"** (a second view of the same table: archived and withdrawn lists, with Restore for whoever may: a manager/admin, or the maker of a row `isWithdrawn`). While `ctx.recentlyWithdrawn` is set, show "Recently removed: Title · vN" with **Open** and **Restore** (`restoreWithdrawn()`) at the top of the picker AND as a quiet line on the bar; call `clearRecentlyWithdrawn()` when the tab mounts and when the person leaves it (unmount, or R.A.B.B.I.T. no longer the page shown — `Rabbit.jsx` already has `pageActive`). The backend's refusal sentences are shown verbatim in the Dialog's `error` slot.

### 5. "New shot list" and "Save as…" (one kit Dialog, `form` width)

Fields: Title (prefilled with the viewed list's), the toggle "Same title, next version" (shows the version it will take from `nextShotListVersion`; off = a new title starting at v1), Summary (TextArea: "what this shot list is"), and **Start from**: "The list on screen" (`from: viewedListId` — the same scenes and shots, linked, not copied) or "Empty". New shot list defaults to "The list on screen" when a list is open and to "Every scene and shot in this project" (`fromAll: true`) when the project has no list yet; Save as… is the same dialog fixed to "The list on screen" with the toggle on. On success the new list becomes the VIEWED list; it becomes ACTIVE only if the project had no active list and the person may activate, otherwise the bar says who can make it active. Validation and uniqueness through `validateVersionedTitle` / the provider's refusals, shown inline. Do NOT pass `undoable: false` (the undo of a creation is a withdraw).

### 6. Membership verbs in the tables

Row actions on a scene or shot of the viewed list: **Remove from this list** (`removeFromShotList`; the row stays in the project and in its other lists — the confirm says so and names them) beside the existing **Delete** (which deletes the scene or shot from the project and every list — its confirm now says that, with the list count). **Add from another list…** (overflow menu and the picker's unlisted view): a kit Dialog on `AssignToShotDialog`'s scene → shot groups with search, source = a list she picks (or "every scene and shot"), rows already in the viewed list disabled; adds through `addToShotList`. **Clear this list** (overflow; only on a list never Saved; a `confirm`-width Dialog naming the count; removes every membership row, deletes nothing). ## Things S3a measured that will bite

- `ctx.scenes` / `ctx.shots` are the ACTIVE list's rows; `scenesOf(listId)` is LIST order; a scene with no item of its own whose shot is in the list is "implied".
- Membership writes are server-first deltas; a refused write sets `ctx.error` and re-reads — surface `ctx.error` near the bar (kit Banner), never swallow it.
- Title, version and summary are last-write-wins: before you add "Edit details", send only the changed columns (S3a's "Known limits" describes the patch path; the adapters are yours to extend for that, with tests on all three backends).
- `listsContaining` includes archived and withdrawn lists.
- The undo of a Save re-reads first and may refuse; show the sentence.
- A project with no list at all: every row is "unlisted" and `scenes` is every row — the tab must still read as today, with the bar saying "No shot list yet" and New shot list offering "Every scene and shot in this project".
