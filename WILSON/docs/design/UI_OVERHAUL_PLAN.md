## 1. Diagnosis (why it reads as dated, and why "files" is the loudest)

WILSON has no type system and no component layer, and the two compound. No typeface is loaded, so everything renders in the OS fallback, and `font-mono` on 1,918 elements (plus the inline `fontFamily: 'monospace'` spelling) makes the browser's fallback monospace the de-facto UI face. Twenty-six type sizes are in use (seven of them half-pixel, about 300 below 10px); the de-facto body is 12px where Notion runs 14 to 16 and Apple's desktop floor is 13. 1,167 elements are uppercase and 1,029 are letter-spaced, so a section heading, a nav item, a button, a table header, a chip and a status pill are the same typographic object: 10 to 12px bold uppercase tracked. When everything is emphasised, nothing is.

The second cause is written into the design doc as a virtue: "local tokens, not global" (`visual-language.md`, composition rule 3). Every page defines its own token object, so the app carries 121 distinct hex values, 19 to 22 hand-built tables (five byte-identical header copies that have already forked), 64 hand-rolled modal overlays across 36 files with 22 backdrop values, four toast systems in four screen positions (five with the agent panel's), four tab bars with three active treatments, two scrollbar systems fighting on specificity (one injected globally from inside D.O.G., and four O.T.T.E.R. surfaces depend on it), and two shadow languages in an app whose spec says it has none. The one shared token module, `lightSurface.js`, is imported by 30 files and fixed grey-on-orange app-wide; its own header calls itself "a deliberate exception". The rule is the defect and the exception is the cure.

The third cause is structural: `#f4a261` is a saturated mid-tone, so the whole stone ramp fails on it and the white-or-black rule is the correct forced response. One ink means hierarchy can only come from size and weight, and the type system that would deliver that does not exist, so every light page invented a workaround (a brown well, a cream header, a dark input on an orange field). The Files page is where all three causes land at once, plus a one-line bug: `'project-files'` was never added to `PAGE_BARS`, so the densest table in the app renders inside Home's 268/268 chrome and loses about 400px of vertical field.

A fourth cause the critic surfaced: **state lives in inline `style` objects and className template literals** (ScenesView mutates `e.target.style.borderColor` in 32 places; every Bins button has a dead hover because an inline `backgroundColor` beats its `hover:` class; seven R.A.B.B.I.T. components drive hover from `useState`). A class-based restyle written next to a surviving inline style silently drops states. Every session extracts state to data attributes and CSS as its first commit on a file, before any visual work.

What already works and becomes the template: `binUi.jsx` (one token object and thirteen real components, with a Modal that handles stacking, Escape, busy-lock and errors), `lightSurface.js` (a token module that measures its own contrast), the bins shortcut bar (persistent, non-modal, teaches by presence; its 34px height and 30px left padding are Audrey's, 2026-09-10, so the adapter dot reads as part of the bar), `pageBars.js` (geometry with a rationale and a test), the single `TRANSITION` constant, and the UndoToast.

## 3. The design system

Inks: 3 (paper, ink, signal). Families: 2 (sans, mono). Weights: 2 (400, 600). Radii: 2 (4, 8). Border: 1 (1px hairline). Shadow: 1 (floating surfaces only). Type steps: 8. Spacing steps: 7. Every value below lives in `@theme` in `src/index.css` and is re-exported by `src/ui/tokens.js`; a session that writes a hex anywhere else has failed C8.

### 3.1 Type

Anchor **14px body**, ratio **1.125** (major second; dense UI with many near-peer levels), display step hand-set, every step a whole pixel, every step with a job. 14 rather than the 15 to 16 UI band is a decision: a frameless desktop tool at 100% zoom with seven-column tables; Apple's desktop floor is 13; the current de-facto body is 12, so 14 is a 17 percent legibility gain without losing a column.

| Role | px | Leading | Tracking | Weight | Case | Used for |
|---|---|---|---|---|---|---|
| Display | 34 | 1.0 | +0.12em | 600 | UPPER | the page-transition title only |
| H1 / page title | 20 | 1.2 | +0.01em | 600 | Sentence | PageHeader title in the orange bar |
| H2 / section | 16 | 1.3 | 0 | 600 | Sentence | SectionTitle, Dialog title, EmptyState title |
| H3 / subsection | 14 | 1.4 | 0 | 600 | Sentence | card titles, group headings, the active tab |
| Body | 14 | 1.5 | 0 | 400 | Sentence | paragraphs, descriptions, list items, inputs |
| Dense | 13 | 1.45 | 0 | 400 | Sentence | table cells, dense lists, tree rows, sidebars, the tool subtitle |
| Caption | 12 | 1.4 | 0 | 400 | Sentence | metadata, hints, counts, timestamps |
| Label | 11 | 1.3 | +0.06em | 600 | UPPER | table headers, field labels, eyebrows, Kbd, status badges. **The floor.** |

Measure 60 to 66ch, set in `ch`, capped at 72ch for Help and Settings prose. Numerics in tables use `font-variant-numeric: tabular-nums`, right alignment, and the mono at `--mono-size-adjust`. Uppercase appears only in Display and Label, both tracked; everything else is sentence case with zero tracking. Disabled is one token: ink at 52 percent plus `cursor: not-allowed`, never `opacity-30/40/50`. Placeholder is ink at 52 percent; caret and `::selection` are the signal on dark and `#1c1917` on light.

Tailwind names (from `@theme`): `text-display`, `text-h1`, `text-h2`, `text-h3`, `text-body`, `text-dense`, `text-caption`, `text-label`; `font-sans`, `font-mono`.

### 3.3 Spacing, radius, border, elevation, density

- **Base 4px.** Scale 4, 8, 12, 16, 24, 32, 48. Nothing in `vh` (`App.jsx`'s `3vh 0` content padding becomes 24px).
- **One page gutter: 24px**, shared by the top bar, the nav strip's right edge and every page's content, which is what makes the strip align with the hamburger that opens it. Two measures: 720px for reading and form pages; full width capped at 1240px for data pages. Pages stop setting their own padding. The Electron `TitleBar` is 32px and every drawer, panel and overlay offsets from it through one token instead of hand-compensating (three surfaces do today; one slides under it).
- **Radius** 4px controls / 8px floating / full for dots and the Switch (Q5). 2, 3, 5, 6, 10px are deleted.
- **Border** 1px hairline from the `rule` token, everywhere except inside LayoutVisualizer.
- **Elevation** one shadow for floating surfaces only: `0 8px 24px rgba(0,0,0,0.35)` dark, `0 8px 24px rgba(60,30,10,0.25)` light. Docked surfaces get a hairline and nothing else. All 41 hard-offset and 43 soft-blur shadows and the status-dot glow are deleted.
- **Density tokens.** Control heights 28 (sm: toolbars, dense rows) and 36 (md: primary actions, form fields). Table row 36 (dense 32), header 32, cell padding 8px 12px, toolbar 44, page header 56, panel header 32, shortcut bar 34 (Q10). Icons 14 inside dense controls, 16 in rows and buttons, 24 in empty states. Three icon sizes, not eleven. Icons stay lucide-react; no emoji. Icon-only buttons carry both `aria-label` and `title` (the `title` is the tooltip; no tooltip component is added).
- **Minimum window 700px** (Electron's floor): every session checks its surface at 1280x700 as well as 1440x900, because every size and density increase above makes tall content taller (Settings tabs, TaskDetailPopup, TaskEditor and the S3 bucket card already overflow there).

### 3.4 Motion

- **The page transition stays exactly as it is** (C2). One change inside it: the title rises from 16.8px at 0.3em to the 34px Display step at +0.12em, weight 600, still `#1c1917` on `#f4a261`. Reduced motion on the transition is Q18; if yes: skip compress and expand, hold the title 400ms over a still frame, cross-fade the page in 120ms, reading the preference at call time inside `navigateTo` and `playWelcome` the way `AuthShell` already does.
- **Three durations for everything else.** State change (hover, focus, toggle, selection) 120ms ease-out. Interactive response (menu, dropdown, tab, chip) 200ms `cubic-bezier(0.2,0,0,1)`. Panel and column (nav strip, resources column, settings slide-out, drawers) 240ms, same curve. Decorative reveals stay above 400ms. `transition-all` is retired for named properties. Every one of these honours `prefers-reduced-motion` with an instant end state, scoped by class, never by a blanket rule in `index.css` (C5).
- Nav hover moves from an opacity value to a named hover ink, so the colour rule stops needing an exception.
- Pet animations are untouched (C5).
